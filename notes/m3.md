GC2 paranoia fixpoint oracle:

- Added `LJ_GC2_PARANOIA` as an explicit debug build flag in `lj_gc2.h`.
- Added `lj_gc2_ismarkedmem(g, p)` so paranoia checks can validate raw
  arena allocations that legacy traversal explicitly marked, while preserving
  `lj_gc2_ismarked(g, o)` as the GC object wrapper.
- Added a real fixpoint false-negative oracle in `lj_gc.c`, called from
  `atomic()` after legacy marking and finalizable resurrection have fully
  propagated, and before weak clearing/sweep begin.
- The oracle checks:
  - live objects still linked through `g->gc.root`;
  - objects in the `mmudata` finalizer ring after resurrection;
  - live interned strings in `g->str.tab`;
  - open upvalues reachable from live threads;
  - table array/hash storage;
  - thread stacks;
  - raw roots explicitly mirrored by `gc_mark_gcroot`: string table,
    lightuserdata segments, global/TG tmpbufs, FFI ctype/callback storage,
    and JIT trace/IR/snapshot buffers.
- Kept extra-mark detection nonfatal for now via
  `lj_gc2_paranoia_legacy_diff(g)`. This counts marked traversable arena
  blocks that do not correspond to a legacy-live object base. The check is
  useful for unit coverage, but it is not a runtime abort yet because black
  allocation can intentionally retain born-during-cycle garbage until a later
  cycle.
- The first paranoia run caught a real fixed-string hole: fixed/reserved
  strings are legacy-live even if normal marking leaves their color alone.
  `gc_mark_gcroot` now mirrors fixed strings into GC2 arena marks with
  `gc_mark_fixedstr(g)`.
- Added `lj_gc2_legacy_preserve_abort(g)` and call it from the
  `lj_gc_fullgc()` partial-cycle fast-forward path. A preserving legacy sweep
  after an interrupted mark must not leave GC2 in `MARK`, and must not enter
  `SWEEP` because the mark bitmap is partial.
- Made `lj_gc2_markobj(g, NULL)` return 0. This keeps upcoming barrier and
  handshake call sites from inheriting a null-crash footgun.

Multi-state public C API safepoint fix:

- A public C API pattern inherited from base LuaJIT can create two independent
  states on one OS thread, then call into `L2` while TLS still names `L1`'s
  `TGState`. GC2 handshake self-ack used raw TLS, so a full collection on `L2`
  could signal `L2`'s main TG and then wait forever because the leader saw
  `L1` as self.
- `safepoint_ack_native(g)` now resolves self with `lj_thr_get_tg_fallback(g)`.
  This scopes the self-ack to the handshake's `global_State` without globally
  switching TLS on every public API entry.
- GC2 finalizer ownership got the same stale-TLS handling, but only when TLS is
  non-null. Missing TLS may be an unattached helper thread, and must keep the
  external-owner sentinel so concurrent finalizer consumers are not treated as
  recursive entries.
- Added a behavior regression to `t-safepoint-handshake`: create `L1` and `L2`,
  assert TLS remains on `L1`, run a direct handshake and public
  `collectgarbage` on `L2`, and assert finalizer owner selection uses `L2`'s TG.

SSB `HS_FLUSH_SSB` scaffold:

- Added fixed per-TG SSB storage:
  - two local 1 KB `GCRef` buffer nodes;
  - active/free node tracking;
  - the existing `ssb_base`, `ssb_next`, and `ssb_end` pointer triple now
    points into the active node.
- Added a GC2 published-buffer stack and counters:
  - `gc2.ssb_head`
  - `gc2.ssb_published`
  - `gc2.ssb_drained`
  - `gc2.ssb_items_published`
  - `gc2.ssb_items_drained`
- Added `lj_gc2_ssb_push`, `lj_gc2_flush_ssb`, and `lj_gc2_drain_ssb`.
  Mutator-side push stores a `GCRef` and bumps the active pointer; overflow
  or `HS_FLUSH_SSB` publishes the filled/partial node to the global MPSC
  stack and switches to a free local node.
- The temporary drain path now moves published SSB entries into a GC2-owned
  single-worker grey stack, recycles the SSB node back to its owner, and drains
  the grey stack with GC2-only traversal. It does not yet perform Chase-Lev
  worker deque scheduling or parallel stealing.
- Wired `safepoint_apply_actions` so `LJ_GC2_HS_FLUSH_SSB` is now a real
  safepoint action.
- Added `lj_gc2_ssb_empty(g)`, the SSB/grey side of the future fixpoint
  predicate. It checks that the published stack, GC2 grey stack, and every live
  TG's active SSB buffer are empty.
- `lj_gc2_markobj` now queues newly-marked traversable GC objects into the
  SSB during MARK/WEAK phases. Raw `lj_gc2_markmem` remains bitmap-only, so
  plain/raw roots such as table arrays, hash nodes, stacks, and buffers do not
  enter object grey work.
- Plain userdata is the current non-traversable exception: it can hold
  metatable/env/buffer references, so first marking a userdata object traverses
  those references immediately instead of dropping them behind the arena-kind
  gate.
- Assert builds now fail if a newly-marked traversable object cannot be pushed
  into the SSB. While worker recycling is still scaffolded, SSB overflow first
  drains/recycles published nodes before reporting failure.
- Worker-side traversal marks children with a private helper that schedules
  grey work directly on the GC2 stack. It deliberately avoids the public
  `lj_gc2_markobj` SSB path, so drain does not recursively enqueue through the
  mutator buffer. Until worker deques exist, legacy sweep entry, preserve
  abort, and cycle end flush/drain SSB work as a worker-consume stand-in.
