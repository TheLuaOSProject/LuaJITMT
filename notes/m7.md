- Original plan state: `plan/11_ffi_concurrency.md` calls for lock-free

  - public string-based abstract type parsing through `ffi_checkctype()`

FFI cdata finalizer registry bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for a concurrent
  FINREG registry keyed by cdata, with `ffi.gc(cd, nil)` and the collector
  resolving races by atomically claiming/deleting registry entries.
- Earlier bridge state added a small always-on `CTState.fin_token` around the
  hidden `GCROOT_FFI_FIN` table. That serialized legacy GCtab mutation while
  the full lock-free FINREG protocol was still unavailable.
- Current slice adds the planned FINREG value-slot claim for entries that
  already exist. `lj_cdata_setfin()` claims an existing finalizer table slot by
  CASing its `TValue` to an internal lightuserdata sentinel, then publishes
  either the new finalizer or nil and updates `LJ_GC_CDATA_FIN` with atomic
  marked-byte helpers. Cdata finalization claims an existing non-nil slot with
  the same sentinel, stores nil, clears the FIN flag atomically, and only then
  calls user finalizer code.
- Enabled missing-key registration now tries lock-free insertion in the
  current hidden-table hash generation before FINREG grow.
  `lj_tab_try_newkey_anchor()` CASes an empty anchor's value from nil to the
  FINREG claim sentinel, release-stores `LJ_TKEYLOCK` into the key slot,
  publishes the cdata key, then lets `lj_cdata_setfin()` publish the finalizer
  value. Collision insertion claims an existing free node with the same value
  claim, marks the key slot with `LJ_TKEYLOCK`, CAS-prepends it into the anchor
  chain, then publishes the cdata key and finalizer value. Other FINREG
  inserters that encounter either a linked key lock or the older nil-key value
  claim before key publication pause and retry, avoiding duplicate first
  registrations for the same cdata. Legacy GC traversal of FINREG generations
  in both legacy GC and GC2 waits out both the value claim sentinel and
  `LJ_TKEYLOCK` before marking the strong finalizer value, so it does not
  observe a half-published table slot.
- The enabled missing-key full-generation path no longer calls the legacy
  `lj_tab_set()`/rehash path and no longer uses a FINREG grow token or active
  claim counter. `CTState.fin_head` is a CAS-published list of weak-key FINREG
  generations. When the current generation has no free node,
  `lj_ctype_fin_newgen()` waits out visible FINREG claim sentinels across all
  generations, rechecks for an existing cdata key, creates a private weak-key
  generation with the new key already claimed, and CAS-publishes it as the
  newest head. Existing generations are retained for lookup and close-time
  drain instead of being copied/resized.
- Legacy GC and GC2 now root every FINREG generation through GC2 FINREG root
  helper boundaries, identify every generation table through
  `lj_ctype_fin_istab()`, and wait out the claim sentinel before marking
  finalizer values. `lua_close()` keeps FINREG enabled until close-time
  cdata/userdata finalization reaches a fixed point, uses the generation list
  to detect pending cdata finalizers, and then disables every generation
  before state teardown. The initial FINREG generation is now created during
  `lj_ctype_init()` and release-published through `fin_gen_head_rel()`; the
  legacy `GCROOT_FFI_FIN` bootstrap root has been removed. `ffi.new()` ctype
  `__gc` registration still routes through `lj_cdata_setfin()` instead of
  duplicating table writes.
- The recorded `crec_finalizer()` path now emits `IRCALL_lj_cdata_setfin` for
  direct `ffi.gc(cd, fn)`, `ffi.gc(cd, nil)`, and ctype `__gc` registration.
  `lj_cdata_setfin()` temporarily anchors the cdata key and non-nil finalizer
  around FINREG lookup/insertion so traced calls have the same GC visibility as
  the interpreted `ffi.gc()` call frame. The guard runs `tests/t-ffi-gc-trace.lua`
  and checks the IR dump for `lj_cdata_setfin`.
- M8 replaced the shared `vmthread(g)` user-finalizer callback stack with the
  collector caller's `lua_State`, claimed through the existing `thr_owner`
  discipline for the callback window. The old reentrant
  `global_State.finalizer_token` bridge was removed after M8 added a GC2
  finalizer dispatch owner claim around `mmudata` draining; finalizer frame
  setup is now serialized by that owner claim. Normal and close-time
  `mmudata` cdata finalization rechecks the FINREG generation list and claims
  the finalizer slot before clearing/calling it.
  This still leaves legacy `mmudata` membership and ordering as bridges, not
  the final lock-free FINREG/finqueue design.
- FINREG claim/keylock observers now yield in bounded native sleep slices
  instead of spinning on `la_cpu_pause()`. This covers legacy GC FINREG table
  traversal, GC2 FINREG table traversal, ordered P_WEAK/close-time/pending
  scans, and `lj_ctype_fin_newgen()` waiting for visible generation claims.
  Wait sites use the current `lua_State` where one is available, and fall back
  to the no-L form only where the caller has no Lua state. The active M7 FINREG
  behavior case covers these claim/keylock waits so a preempted publisher cannot
  turn finalizer registry discovery into an unbounded busy wait.
- FINREG generation-head CAS losers in `lj_ctype_fin_newgen()` now reuse the
  same bounded wait helper before retrying. This keeps concurrent generation
  publication contention from falling back to a raw CPU spin while preserving
  the existing CAS linearization.
- Follow-up generation wait cleanup threads the current `lua_State` through
  those `lj_ctype_fin_newgen()` waits. Generation-claim observers and
  generation-head CAS losers now sleep through `lj_thr_sleep_ns(L, ...)` when a
  Lua state is available, so the owning TG is native and safepoint-visible
  during FINREG generation publication contention.
- FINREG value-slot claimers now use the same current-state native sleep wait
  when they observe another owner already holding the slot claim sentinel. The
  CAS loop still owns publication, but waiting for the current publisher no
  longer burns CPU if that publisher is descheduled in the claim window.
- Added `tests/t-ffi-gc-finreg.lua` under `tools/ci/lua_test.sh m7_ffi_finreg`
  to stress concurrent `ffi.gc()` registration, explicit clear, and finalizer
  execution across spawned Lua threads, including a finalizer that performs
  nested GC.
  The test now also races several workers over the same already-registered
  cdata finalizer slot, then installs a known finalizer and verifies exactly
  one closeout after collection. The suite case runs the script with both
  `-joff` and the default JIT state; the latter now executes traced `ffi.gc()`
  loops and therefore also depends on the current M6 execute-stable mcode
  bridge.
  The runtime gate serializes each worker's fixed-size ctype setup, pre-grows
  worker stacks, avoids per-worker keep-table growth, and stops GC during the
  synchronized `ffi.gc()` window so it remains focused on finalizer registry
  mutation instead of the still-open CTState parser/hash, VLA arena, and worker
  stack-growth/collection work.
- Follow-up FFI entry validation cleanup routes `ffi.gc()` finalizer-eligible
  ctype validation through `ctype_info_acq()`. Keep the acquire-load reason
  documented near the helper; do not encode the helper spelling as a test.
- Follow-up stable-input cleanup routes `ffi.gc()` finalizer eligibility through
  `lj_ctype_info_snapshot()` / `lj_ctype_info_wait()`, so cdata type validation
  waits out parser rollback instead of directly dereferencing the current ctype
  record.
- Remaining finalizer work from the original report: move legacy `mmudata`
  execution toward the planned scalable dispatch/finqueue path and close the
  remaining generation-publish edge cases as part of that design. Performance
  tuning remains deferred to M9.

FFI pin userdata root:

- Original plan state: `plan/11_ffi_concurrency.md` calls for
  `ffi.pin(obj) -> pin` / `pin:release()` as a convenience root implemented as
  a registry-table insert/remove once the normal concurrent registry table is
  available.
- Current slice implements the same API contract without mutating the shared
  registry table. `ffi.pin()` returns a dedicated `UDTYPE_FFI_PIN` userdata
  whose hidden payload is one `TValue`; `CTState.pinmt` roots the handle
  metatable, and both legacy GC and GC2 traverse the hidden payload while the
  pin userdata is reachable.
- `pin:release()` release-stores nil into the hidden payload and is
  idempotent. The pin `__gc` path performs the same release so dropping the
  handle eventually drops the root even if user code forgets to call release.
- GC2 allocation-black construction now uses the same release-store discipline:
  `ffi.pin()` copies the payload with `copyTVrel()` and barriers the pin-to-value
  edge before release-publishing `UDTYPE_FFI_PIN`.
- Follow-up helper slice routes the `CTState.pinmt` root through
  `ctype_pinmt_*()` in pin construction, module initialization, legacy GC/GC2
  root scans, and GC2 paranoia checks. The `m7_ffi_pin` guard rejects raw
  implementation-side `cts->pinmt` access.
- Added `tests/t-ffi-pin.lua` and `tools/ci/m7_ffi_pin.sh` to cover Lua-object
  weak retention, cdata finalizer retention/release, idempotent release,
  handle `__gc` release, and a small normal-build threaded construction/release
  smoke. Threaded exact collection timing is deliberately not asserted because
  worker stack lifetime and scheduling can retain temporaries past an
  individual collection boundary.
- This is a correctness-oriented M7 representation. The original
  concurrent-registry representation can still replace it later if that becomes
  cleaner, and performance cleanup remains deferred to M9.

FFI duplicate cdef worker stack-growth fix:

- Original M7 stress target included same-name `ffi.cdef()` races where both
  threads get identical ctype semantics. The focused repro also called
  string-based `ffi.sizeof()`/`ffi.typeof()` from spawned workers, which forced
  both worker Lua stacks to grow while racing duplicate parser work.

  path. The two spawned `lua_State` stacks were created by the main thread

  still single-threaded.
