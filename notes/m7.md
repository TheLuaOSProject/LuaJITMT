  allocation and post-thread ctype lookup walks. Those exposed the still-open

FFI cdata finalizer registry bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for a concurrent
  FINREG registry keyed by cdata, with `ffi.gc(cd, nil)` and the collector
  resolving races by atomically claiming/deleting registry entries.
- Earlier bridge state added a small always-on `CTState.fin_token` around the
  hidden `GCROOT_FFI_FIN` table. That serialized legacy GCtab mutation while
  the full lock-free FINREG protocol was still unavailable.
- Current slice adds the planned FINREG value-slot claim for entries that
  already exist. `lj_cdata_setfin()` claims an existing finalizer table slot by
  CASing its `TValue` to an internal lightuserdata sentinel, then publishes
  either the new finalizer or nil and updates `LJ_GC_CDATA_FIN` with atomic
  marked-byte helpers. Cdata finalization claims an existing non-nil slot with
  the same sentinel, stores nil, clears the FIN flag atomically, and only then
  calls user finalizer code.
- Enabled missing-key registration now tries lock-free insertion in the
  current hidden-table hash generation before FINREG grow.
  `lj_tab_try_newkey_anchor()` CASes an empty anchor's value from nil to the
  FINREG claim sentinel, release-stores `LJ_TKEYLOCK` into the key slot,
  publishes the cdata key, then lets `lj_cdata_setfin()` publish the finalizer
  value. Collision insertion claims an existing free node with the same value
  claim, marks the key slot with `LJ_TKEYLOCK`, CAS-prepends it into the anchor
  chain, then publishes the cdata key and finalizer value. Other FINREG
  inserters that encounter either a linked key lock or the older nil-key value
  claim before key publication pause and retry, avoiding duplicate first
  registrations for the same cdata. Legacy GC traversal of FINREG generations
  in both legacy GC and GC2 waits out both the value claim sentinel and
  `LJ_TKEYLOCK` before marking the strong finalizer value, so it does not
  observe a half-published table slot.
- The enabled missing-key full-generation path no longer calls the legacy
  `lj_tab_set()`/rehash path and no longer uses a FINREG grow token or active
  claim counter. `CTState.fin_head` is a CAS-published list of weak-key FINREG
  generations. When the current generation has no free node,
  `lj_ctype_fin_newgen()` waits out visible FINREG claim sentinels across all
  generations, rechecks for an existing cdata key, creates a private weak-key
  generation with the new key already claimed, and CAS-publishes it as the
  newest head. Existing generations are retained for lookup and close-time
  drain instead of being copied/resized.
- Legacy GC and GC2 now root every FINREG generation through
  `lj_ctype_fin_mark()`, identify every generation table through
  `lj_ctype_fin_istab()`, and wait out the claim sentinel before marking
  finalizer values. `lua_close()` keeps FINREG enabled until close-time
  cdata/userdata finalization reaches a fixed point, uses the generation list
  to detect pending cdata finalizers, and then disables every generation
  before state teardown. The initial FINREG generation is now created during
  `lj_ctype_init()` and release-published through `fin_gen_head_rel()`; the
  legacy `GCROOT_FFI_FIN` bootstrap root has been removed. `ffi.new()` ctype
  `__gc` registration still routes through `lj_cdata_setfin()` instead of
  duplicating table writes.
- The recorded `crec_finalizer()` path now emits `IRCALL_lj_cdata_setfin` for
  direct `ffi.gc(cd, fn)`, `ffi.gc(cd, nil)`, and ctype `__gc` registration.
  `lj_cdata_setfin()` temporarily anchors the cdata key and non-nil finalizer
  around FINREG lookup/insertion so traced calls have the same GC visibility as
  the interpreted `ffi.gc()` call frame. The guard runs `tests/t-ffi-gc-trace.lua`
  and checks the IR dump for `lj_cdata_setfin`.
- M8 replaced the shared `vmthread(g)` user-finalizer callback stack with the
  collector caller's `lua_State`, claimed through the existing `thr_owner`
  discipline for the callback window. The old reentrant
  `global_State.finalizer_token` bridge was removed after M8 added a GC2
  finalizer dispatch owner claim around `mmudata` draining; finalizer frame
  setup is now serialized by that owner claim. Normal and close-time
  `mmudata` cdata finalization rechecks the FINREG generation list and claims
  the finalizer slot before clearing/calling it.
  This still leaves legacy `mmudata` membership and ordering as bridges, not
  the final lock-free FINREG/finqueue design.
- Added `tests/t-ffi-gc-finreg.lua` and `tools/ci/m7_ffi_finreg.sh` to stress
  concurrent `ffi.gc()` registration, explicit clear, and finalizer execution
  across spawned Lua threads, including a finalizer that performs nested GC.
  The test now also races several workers over the same already-registered
  cdata finalizer slot, then installs a known finalizer and verifies exactly
  one closeout after collection. The CI guard runs the script with both `-joff`
  and the default JIT state; the latter now executes traced `ffi.gc()` loops and
  therefore also depends on the current M6 execute-stable mcode bridge.
  The runtime gate serializes each worker's fixed-size ctype setup, pre-grows
  worker stacks, avoids per-worker keep-table growth, and stops GC during the
  synchronized `ffi.gc()` window so it remains focused on finalizer registry
  mutation instead of the still-open CTState parser/hash, VLA arena, and worker
  stack-growth/collection work.
- Remaining finalizer work from the original report: move legacy `mmudata`
  execution toward the planned scalable dispatch/finqueue path and close the
  remaining generation-publish edge cases as part of that design. Performance
  tuning remains deferred to M9.

FFI pin userdata root:

- Original plan state: `plan/11_ffi_concurrency.md` calls for
  `ffi.pin(obj) -> pin` / `pin:release()` as a convenience root implemented as
  a registry-table insert/remove once the normal concurrent registry table is
  available.
- Current slice implements the same API contract without mutating the shared
  registry table. `ffi.pin()` returns a dedicated `UDTYPE_FFI_PIN` userdata
  whose hidden payload is one `TValue`; `CTState.pinmt` roots the handle
  metatable, and both legacy GC and GC2 traverse the hidden payload while the
  pin userdata is reachable.
- `pin:release()` release-stores nil into the hidden payload and is
  idempotent. The pin `__gc` path performs the same release so dropping the
  handle eventually drops the root even if user code forgets to call release.
- GC2 allocation-black construction now uses the same release-store discipline:
  `ffi.pin()` copies the payload with `copyTVrel()` and barriers the pin-to-value
  edge before release-publishing `UDTYPE_FFI_PIN`.
- Follow-up helper slice routes the `CTState.pinmt` root through
  `ctype_pinmt_*()` in pin construction, module initialization, legacy GC/GC2
  root scans, and GC2 paranoia checks. The `m7_ffi_pin` guard rejects raw
  implementation-side `cts->pinmt` access.
- Added `tests/t-ffi-pin.lua` and `tools/ci/m7_ffi_pin.sh` to cover Lua-object
  weak retention, cdata finalizer retention/release, idempotent release,
  handle `__gc` release, and a small normal-build threaded construction/release
  smoke. Threaded exact collection timing is deliberately not asserted because
  worker stack lifetime and scheduling can retain temporaries past an
  individual collection boundary.
- This is a correctness-oriented M7 representation. The original
  concurrent-registry representation can still replace it later if that becomes
  cleaner, and performance cleanup remains deferred to M9.

FFI CLibrary cache fill bridge:

- Original plan state: `plan/11_ffi_concurrency.md` section 11.7 says
  `dlopen`/`dlsym` are thread-safe, the CLibrary cache table should be a normal
  concurrent table, and symbol lookup writes into `cl->cache` are plain table
  sets.
- Earlier bridge state added an always-on per-`CLibrary` `cache_token` around
  legacy `GCtab` cache miss insertion. That preserved correctness while the
  normal concurrent table write protocol was still incomplete.
- Current slice replaces the bridge with a CLibrary-owned side cache.
  `lj_clib_index()` first checks `lj_clib_cache_get()`, resolves the ctype and
  symbol on a miss, roots the temporary result on the current Lua stack, then
  publishes an immutable `CLibCacheEntry` by CAS-prepending it to
  `CLibrary.cache_head`. Concurrent duplicate publishers drop their side entry
  and return the already-published value. The recorder uses the same
  acquire-load helper and no longer reads `cl->cache` directly. A successful
  CAS marks the raw side-entry allocation before publishing key/value barriers,
  so a mark cycle that already traversed the CLibrary cannot sweep the new
  entry out from under `cache_head`.
- The legacy `cl->cache` GCtab is left as the userdata environment anchor for
  now, but cache misses no longer mutate it. Legacy GC and GC2 both traverse
  the side cache, mark side-entry memory, mark the string key, and mark the
  cached TValue. `__gc` unload/finalization frees the side entries, and
  `lj_udata_free()` repeats the same idempotent unload as a close/sweep
  backstop for the raw side allocations.
- The side-cache key and value payloads now publish and snapshot through
  shared `lj_clib_cache_*_{acq,rel}` helpers. This keeps release payload stores
  paired with the acquire GC/GC2/diagnostic readers instead of open-coded raw
  field access at each traversal site.
- The same helper boundary now covers the side-cache head and `next` links,
  including the release CAS head publish, acquire head/next traversals, and
  unload-time acquire-release head exchange. The CLibrary cache guard rejects
  raw list-link atomics in the implementation files.
- The JIT recorder now acquire-snapshots a CLibrary cache hit before
  specializing `ffi.C` constants, externs, or cdata constants, so it no longer
  dereferences the side-cache `TValue` payload through a raw cache pointer. The
  CLibrary cache gate runs a small JIT-enabled pass in addition to the threaded
  interpreter cache-fill race.
- C extern cache entries now allocate their pointer cdata with
  `lj_cdata_new_l(L, cts, ...)`, so this path no longer falls back to
  `cts->L` for the cache-fill allocation.
- Added `tests/t-ffi-clib-cache.lua` and `tools/ci/m7_ffi_clib_cache.sh` to
  race first access to multiple `ffi.C` externs plus an FFI constant from
  spawned Lua threads, with cdefs completed before the synchronized window.
- Still remaining from the original M7 target: a future normal concurrent
  `GCtab` string-key insertion protocol can subsume the side cache, and direct
  CTState table/hash RCU work remains separate. Performance cleanup stays
  deferred to M9.

FFI callback setup install bridge / slot-CAS follow-up:

- Original plan state: `plan/11_ffi_concurrency.md` calls for callback scratch
  and callback slot state to move out of shared `CTState.cb`, with callback
  entry/runtime state made safe for concurrent callbacks.
- Earlier bridge state: `lj_ccallback_new_l()` was made explicit-`L`, the
  callback id/owner arrays and callback `miscmap` array were preallocated at
  FFI module initialization, and `CTState.misc_token` temporarily covered slot
  allocation plus callback-function `miscmap` writes.
- Current follow-up replaces the setup-time slot bridge and the callback
  function `miscmap` slots. `CTState.cb.func` is a preallocated, nil-initialized
  `TValue` side array published with the callback id/owner arrays. Callback
  creation scans the preallocated slot table from zero, reserves a free slot
  with an owner-pointer CAS (`owner == NULL -> L`), release-stores the function
  into `cb.func[slot]` with a root barrier, then release-publishes `cbid`.
  Runtime entry acquire-loads `cbid` and the side function slot; a racing free
  that leaves a non-function value is handled as `LJ_ERR_FFI_BADCBACK`. Both
  legacy GC and GC2 scan the side array as a CTState root.
- Callback free now clears `cbid` before niling the function slot and only then
  releases the owner pointer to make the slot reusable. A new installer cannot
  claim that slot until the old function slot is no longer visible as a live
  callback target.
- Earlier bridge state: callback mcode allocation remained a rare one-time
  `misc_token` bridge after the callback slot-CAS follow-up. The current slice
  allocates and publishes callback mcode during `luaopen_ffi()` via
  `lj_ccallback_init_l()`, before any spawned Lua thread can create callbacks.
  `lj_ccallback_new_l()` now only reads the already-published mcode and no
  longer locks around lazy mcode creation. `CTState.misc_token` and the
  `lj_ctype_misc_lock()`/`lj_ctype_misc_unlock()` helpers were removed.
  Callback function slots now live in `CTState.cb.func`; `miscmap` is allocated
  without callback array capacity and remains only for the FFI function-pointer
  metatable.
- Follow-up: `luaopen_ffi()` now CAS-publishes the callback table under the
  `cts->miscmap` empty-string key and runs the table/object publication barrier
  after the successful store, so callback metatable discovery does not rely on a
  direct post-lookup table slot write.
- `ffi.cast()` now anchors the newly allocated destination cdata in a temporary
  stack slot while conversion may allocate a callback, preserving the source
  value until conversion finishes.
- Added `tests/t-ffi-callback-install.lua` and
  `tools/ci/m7_ffi_callback_install.sh` to stress concurrent callback creation
  and explicit free below the fixed x64 callback slot cap, plus static
  guardrails for explicit-L setup, preallocated shared callback bookkeeping,
  anchored cast conversion, owner-CAS slot claiming, callback publish/free
  ordering, and runtime non-function rejection. The focused test
  serializes worker type setup, stops GC during the synchronized setup/free
  window, and pre-grows worker stacks so it does not accidentally turn into the
  still-staged worker stack-growth/sweep bridge.
- Still remaining from the original M7 report: direct CTState table/hash
  duplicate handling and broader bridge-token replacement remain separate.
  Performance cleanup stays deferred to M9.

FFI duplicate cdef worker stack-growth fix:

- Original M7 stress target included same-name `ffi.cdef()` races where both
  threads get identical ctype semantics. The focused repro also called
  string-based `ffi.sizeof()`/`ffi.typeof()` from spawned workers, which forced
  both worker Lua stacks to grow while racing duplicate parser work.
- Investigation showed the crash was not caused by the ctype ticket/header
  path. The two spawned `lua_State` stacks were created by the main thread
  before the worker TG existed, so their initial stack blocks lived in the main
  TG arena. Concurrent worker stack growth then routed `realloc` by the old
  pointer's main-arena owner and could hand two live workers the same resized
  stack block.
- Added `lj_state_rehome_stack(L)` and call it from
  `threading_spawn_core()` after the worker TG owner id is assigned and before
  the child is published or `pthread_create()` runs. The helper copies the
  child stack into the worker TG arena, adjusts `stack`/`maxstack`/`base`/`top`
  and open-upvalue pointers with the same delta rule as stack resize, accounts
  the new owner allocation, then frees the old main-arena stack while it is
  still single-threaded.
- `lj_ctype_parse_lock()` now treats the Linux futex wait as native time:
  waiters enter native state, leave after wake/timeout, and process stop
  actions before retrying. This keeps the parser token's allowed blocking path
  aligned with the existing channel/join/sleep discipline.
- Added `tests/t-ffi-cdef-dup-stack.lua` and
  `tools/ci/m7_ffi_cdef_dup_stack.sh`, wired into `tools/ci/m7_ffi.sh`. The
  guard intentionally runs under `-joff` to isolate the allocator/stack-growth
  correctness bug; the default-JIT versions of the original duplicate-cdef and
  struct `typeof` repros were separately stress-run after the fix.
- Remaining M7 work from the original report: final lock-free/CAS replacements
  for the remaining bridge tokens remain separate. Callback setup slot claiming
  and metatype CAS publication have the follow-ups recorded above. Performance
  and cleanup remain deferred to M9.
