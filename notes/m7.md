# M7 Notes

FFI parser CTState token bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for lock-free
  CTState table growth, ticket ID allocation, CAS hash chains, eventual
  removal of `cts->L`, and a small futex-backed `cts->parse_token` around
  parser-driven mutation.
- Current slice implements the parser token bridge first. `CTState` uses
  `parse_token`, and `lj_ctype_parse_lock()` parks waiters with
  `la_futex_wait()` while the owner runs `lj_cparse()`.
- Wrapped all current `lj_cparse(&cp)` entry points:
  - public `ffi.cdef()`;
  - public string-based abstract type parsing through `ffi_checkctype()`
    (`ffi.typeof`, `ffi.new`, `ffi.cast`, `ffi.istype`, `ffi.sizeof`,
    `ffi.alignof`, `ffi.offsetof`, `ffi.metatype`);
  - recorder string type specialization in `lj_crecord.c`.
- Parser allocation/error context now uses the parse owner where needed:
  parser diagnostics use `CPState.L` instead of `cts->L`. A later explicit-L
  slice below removed the temporary `parse_L` bridge and old non-`_l`
  `lj_ctype_new()`/`lj_ctype_intern()` APIs.
- Added `tests/t-ffi-cdef-token.lua` and `tools/ci/m7_ffi_cdef_token.sh` to
  stress concurrent `ffi.cdef()` from spawned Lua threads, and to guard that
  the current parser call sites remain wrapped.
- The runtime gate intentionally avoids concurrent `ffi.typeof()` cdata
  allocation and post-thread ctype lookup walks. Those exposed the still-open
  cdata allocator and CTState hash/table reader work from the original M7 plan,
  so this bridge test keeps to parser mutation only.
- At this point in the work, remaining M7 work from the original report was:
  RCU/table/hash conversion, direct non-parser `lj_ctype_intern()` races,
  metatype/miscmap CAS, ffi.gc registry concurrency, callback scratch
  relocation, and clib/cache review. Later sections below record the bridge
  slices that have since landed; performance tuning and narrowing the
  serialization belong to M9.

FFI cdata allocation publication bridge:

- Concurrent `ffi.typeof()` stress after the parser-token slice exposed a
  final-sweep crash caused by concurrent publication to the legacy `g->gc.root`
  list. This is separate from raw per-TG arena routing: the allocation can come
  from the right arena while the root-list prepend is still racy.
- Added `lj_gc_linkobj()` as a CAS-prepend helper for `g->gc.root`; new cdata
  paths initialize `gct`, `ctypeid`, and color before release-publishing the
  object to the root list.
- `lj_cdata_new()` / `lj_cdata_new_()` now allocate with the unlinked
  traversable-GC wrapper over `lj_mem_newgco_raw()` and publish after
  initialization. `lj_cdata_newv()` does the same for aligned/VLA cdata.
- `ffi.typeof()` and `ffi.metatype()` now allocate their returned CTypeID cdata
  through the explicit-`L` constructor instead of relying on shared `cts->L`.
  `ffi.new()` and `ffi.cast()` use explicit-`L` fixed/VLA allocation for the
  same reason.
- Added `tests/t-ffi-cdata-alloc.lua` and
  `tools/ci/m7_ffi_cdata_alloc.sh` to stress fixed-size cdata, VLA cdata, and
  CTypeID cdata allocation from spawned Lua threads, followed by full
  collection. The gate checks object shape only; concurrent struct
  initialization/readback remains part of the broader cdata access work.
- Still remaining from the original M7 report: a broader `cts->L` removal for
  lower-level conversion/call helpers, JIT CNEW header-before-publication
  cleanup, and finalizer registry concurrency.

JIT CNEW cdata allocation publication:

- x64 `asm_cnew()` no longer calls generic `lj_mem_newgco()` for fixed-size
  CNEW/CNEWI. It now calls `lj_cdata_new_forjit(L, id, sz)`, which initializes
  `gct`, `ctypeid`, and color before CAS-publishing the object to `g->gc.root`.
- Removed x64 post-call cdata header writes from `asm_cnew()`; payload stores
  still happen after allocation, but the GC-visible header is valid before root
  publication.
- VLA/aligned trace-side cdata already routes through `lj_cdata_newv()`, which
  was converted in the previous cdata allocation slice.
- Added `tests/t-ffi-jit-cnew-alloc.lua` and
  `tools/ci/m7_ffi_jit_cnew.sh`. The gate runs with `-sink` and checks the JIT
  dump for materialized `CNEW` and `CNEWI`, plus static guardrails that x64
  `asm_cnew()` no longer uses generic GC allocation or post-publication header
  writes. It also runs assert/paranoia stock FFI JIT cases that catch
  trace-side fixed-size cdata allocation/free size mismatches.
- Remaining cdata/FFI work from the original report: direct CTState RCU/hash
  conversion, lower-level `cts->L` removal, concurrent field access semantics,
  ffi.gc finalizer registry races, metatype/miscmap CAS, callback scratch, and
  the CLibrary cache work tracked below.

FFI JIT snapshot restore explicit-L bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for deleting
  `cts->L` and passing the active `lua_State *L` through FFI cdata allocation
  paths.
- Current slice routes JIT snapshot unsinking of sunk `CNEW`/`CNEWI` cdata
  through `lj_cdata_newx_l(L, cts, ...)` instead of the old
  `lj_cdata_newx(cts, ...)` wrapper.
- Removed the now-unused `lj_cdata_new()` and `lj_cdata_newx()` wrappers that
  allocated through `cts->L`; fixed-size and arbitrary cdata allocation callers
  now use explicit-`L` entry points or the JIT-only constructor.
- Added `tests/t-ffi-snap-restore-l.lua` and
  `tools/ci/m7_ffi_snap_restore_l.sh` to trigger side exits that restore sunk
  struct and int64 cdata from a spawned Lua thread, plus static guardrails that
  the old cdata allocation wrappers remain removed.
- Still remaining from the original `cts->L` target: parser allocation context
  still keeps the temporary `cts->L` bridge while CTState table/hash RCU is
  pending, recorder setup has one `cts->L = J->L` bridge, and callback runtime
  entry still uses shared callback state.

FFI cdata finalizer registry bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for a concurrent
  FINREG registry keyed by cdata, with `ffi.gc(cd, nil)` and the collector
  resolving races by atomically claiming/deleting registry entries.
- Current slice adds a small always-on `CTState.fin_token` around the hidden
  `GCROOT_FFI_FIN` table. This is a correctness bridge for the existing legacy
  GCtab registry; the full lock-free FINREG table/claim sentinel remains open.
- `lj_cdata_setfin()` now serializes finalizer table insert/clear with
  finalizer flag and FINREG telemetry updates. `ffi.new()` ctype `__gc`
  registration routes through `lj_cdata_setfin()` instead of duplicating the
  table write.
- Cdata finalization no longer inserts missing finalizer keys while resolving
  callbacks; it claims existing non-nil values under the finalizer token,
  clears the slot, drops the token, and only then calls user finalizer code.
- The legacy finalizer callback path still runs through the shared VM thread
  stack, so a separate reentrant `global_State.finalizer_token` now serializes
  `gc_call_finalizer()` frame setup and protected calls across worker threads.
  This is a correctness bridge for the current VM-thread callback mechanism,
  not the final lock-free/per-thread finalizer design.
- Added `tests/t-ffi-gc-finreg.lua` and `tools/ci/m7_ffi_finreg.sh` to stress
  concurrent `ffi.gc()` registration, explicit clear, and finalizer execution
  across spawned Lua threads, including a finalizer that performs nested GC.
  The runtime gate serializes each worker's fixed-size ctype setup, pre-grows
  worker stacks, avoids per-worker keep-table growth, and stops GC during the
  synchronized `ffi.gc()` window so it remains focused on finalizer registry
  mutation instead of the still-open CTState parser/hash, VLA arena, and worker
  stack-growth/collection work.
- Remaining finalizer work from the original report: replace this bridge token
  with the planned lock-free FINREG registry and atomic claim/delete protocol,
  and replace shared-VM-thread finalizer serialization with the planned
  scalable dispatch path. Performance tuning remains deferred to M9.

FFI metatype/miscmap bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for pure RCU
  metatype reads and `ffi.metatype()` one-shot installation enforced by CAS on
  the `miscmap` slot.
- Current slice adds `CTState.misc_token` as a correctness bridge around the
  structural `cts->miscmap` write in `ffi.metatype()`. Readers continue to use
  acquire snapshots through `lj_ctype_metatv()`.
- The protected-metatable error path now releases the bridge token before
  throwing `LJ_ERR_PROTMT`; successful installs publish the metatable before
  returning the CTypeID cdata.
- Added `tests/t-ffi-metatype-miscmap.lua` and
  `tools/ci/m7_ffi_metatype.sh` to stress distinct concurrent metatype
  installs and a same-type race where exactly one thread may win.
- Remaining miscmap/callback work from the original report: replace this bridge
  with a slot CAS protocol, and move callback setup scratch out of shared
  `CTState.cb`.

  through parser, conversion, cdata, callback, and C call paths instead.

- Public cdata `__index`, cdata `__newindex` address resolution, C library

  `cts->L` wrappers.
- Added `tests/t-ffi-cdata-get-l.lua` and `tools/ci/m7_ffi_cdata_get_l.sh` to

- Still remaining from the original M7 report: write-side conversion and setter
  paths, callback setup scratch, CTState table/hash RCU, full `cts->L` removal,

  Performance tuning and cleanup remain deferred to M9.

FFI arithmetic/raw C-to-C explicit-L bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for deleting
  `cts->L` and passing active `lua_State *L` explicitly through FFI conversion
  paths.
- Current slice removes the legacy `lj_cconv_ct_ct()` wrapper that forwarded
  through `cts->L`. Numeric C-to-TValue conversion, FFI pointer arithmetic,
  FFI 64-bit arithmetic, and bit-library cdata argument conversion now call
  `lj_cconv_ct_ct_l()` with the active state.
- Arithmetic result cdata allocation for pointer arithmetic and 64-bit integer
  arithmetic now uses `lj_cdata_new_l(L, cts, ...)` instead of the shared
  `cts->L` fixed-size wrapper.
- Added `tests/t-ffi-carith-l.lua` and `tools/ci/m7_ffi_carith_l.sh` to stress
  concurrent int64/uint64 arithmetic, bit operations with cdata operands, and
  pointer arithmetic/comparison, plus static guardrails that the old
  `lj_cconv_ct_ct()` wrapper remains removed. The runtime test serializes
  worker type setup, stops GC during the synchronized arithmetic window, and
  reuses each worker's pointer backing array so it stays focused on arithmetic
  conversion rather than the broader staged arena/stack-growth bridges.
- Still remaining from the original M7 report: direct non-parser
  `lj_ctype_intern()` races still require the planned CTState table/hash RCU
  work, callback runtime scratch remains shared, and bridge tokens still need
  lock-free/CAS replacements. Performance cleanup stays deferred to M9.

FFI CLibrary cache fill bridge:

- Original plan state: `plan/11_ffi_concurrency.md` section 11.7 says
  `dlopen`/`dlsym` are thread-safe, the CLibrary cache table should be a normal
  concurrent table, and symbol lookup writes into `cl->cache` are plain table
  sets.
- Current slice adds an always-on per-`CLibrary` `cache_token` as a correctness
  bridge around legacy `GCtab` cache miss insertion. `lj_clib_index()` first
  performs an acquire cache read with `lj_tab_getstr()`, resolves the ctype and
  symbol outside the token, then re-checks/fills the cache while holding the
  token.
- C extern cache entries now allocate their pointer cdata with
  `lj_cdata_new_l(L, cts, ...)`, so this path no longer falls back to
  `cts->L` for the cache-fill allocation.
- Added `tests/t-ffi-clib-cache.lua` and `tools/ci/m7_ffi_clib_cache.sh` to
  race first access to multiple `ffi.C` externs plus an FFI constant from
  spawned Lua threads, with cdefs completed before the synchronized window.
- Still remaining from the original M7 target: replace the per-library bridge
  with the planned normal concurrent table write protocol/CAS cache publish,
  and keep direct CTState table/hash RCU work separate. Performance cleanup
  stays deferred to M9.

FFI callback setup install bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for callback scratch
  and callback slot state to move out of shared `CTState.cb`, with callback
  entry/runtime state made safe for concurrent callbacks.
- Current slice handles setup-time mutation only. `lj_ccallback_new_l()` now
  receives the active `lua_State *L`, and callback mcode/slot allocation plus
  the callback function `miscmap` install no longer route through shared
  `cts->L`.
- The existing `CTState.misc_token` bridge now covers the callback slot table
  (`cts->cb.cbid`, `sizeid`, `topid`) and callback-function `miscmap` write.
  The callback id table and callback `miscmap` array are allocated once at FFI
  initialization using the fixed callback slot cap, avoiding worker-owned
  shared callback bookkeeping realloc/free during concurrent setup. Slot id
  entries use acquire/release loads and stores. Explicit callback overflow/mmap
  errors release the bridge token before throwing.
- `ffi.cast()` now anchors the newly allocated destination cdata in a temporary
  stack slot while conversion may allocate a callback, preserving the source
  value until conversion finishes.
- Added `tests/t-ffi-callback-install.lua` and
  `tools/ci/m7_ffi_callback_install.sh` to stress concurrent callback creation
  and explicit free below the fixed x64 callback slot cap, plus static
  guardrails for explicit-L setup, preallocated shared callback bookkeeping,
  anchored cast conversion, and misc-token coverage. The focused test
  serializes worker type setup, stops GC during the synchronized setup/free
  window, and pre-grows worker stacks so it does not accidentally turn into the
  still-staged worker stack-growth/sweep bridge.
- Still remaining from the original M7 report: runtime callback entry still
  uses shared trampoline scratch (`cts->cb.gpr`, `fpr`, `stack`, `slot`,
  `was_native`) that is written before C-side locking is possible. That needs a
  dedicated x64 ABI scratch relocation rather than a cosmetic lock. The
  lock-free replacement for this setup bridge remains open, and performance
  cleanup stays deferred to M9.

FFI callback runtime scratch relocation:

- Original plan state: `plan/11_ffi_concurrency.md` calls for callback scratch
  and callback slot state to move out of shared `CTState.cb`, with runtime
  callback state safe for concurrent callbacks. It also says native callback
  entry remains on the carrier thread for now; foreign-thread auto-attach is a
  later step.
- Current slice moves x64/Linux runtime callback scratch to per-`TGState`
  storage. `CTState.cb` keeps shared registration data (`mcode`, `cbid`,
  callback owners, `sizeid`, `topid`), while `TGState.cb` carries the active
  callback's GPR/FPR arguments, stack pointer, owner `lua_State`, slot, and
  native-region state.
- Callback slots now record their owner `lua_State *` before publishing the
  slot id. The x64 trampoline uses that side table to find the owner TG, writes
  all entry scratch into `TGState.cb`, passes that scratch block to
  `lj_ccallback_enter()`/`lj_ccallback_leave()`, and reads results back from the
  same per-TG block. The continuation no longer writes `cts->L`.
- `lj_ccall_func()` now uses the current TG callback scratch for the
  callback-blacklist marker instead of `cts->cb.slot`.
- Added `tests/t-ffi-callback-runtime.lua` and
  `tools/ci/m7_ffi_callback_runtime.sh` to stress concurrent direct callbacks
  and libc `qsort()` callbacks across GPR, FPR/result, and stack-passed
  arguments. The gate also keeps the stock FFI callback test and static
  guardrails that reject x64 runtime writes back into shared `CTState.cb`.
- Remaining from the original M7 report: this intentionally covers x64/Linux
  only; ARM/aarch64 callback trampoline cleanup is out of scope for this branch.
  The callback setup bridge still needs its eventual lock-free/CAS replacement,
  direct CTState table/hash RCU work remains separate, and performance cleanup
  stays deferred to M9.

FFI ctype allocation/intern explicit-L bridge:

- Original plan state: `plan/11_ffi_concurrency.md` calls for deleting
  `cts->L` and passing active `lua_State *L` explicitly through parser,
  conversion, C-call, callback, and recorder paths.
- Current slice removes `CTState.L` and the temporary `parse_L` bridge.
  `ctype_cts(L)` now only returns the shared `CTState`; it no longer writes a
  shared Lua-state pointer on every FFI access, and thread teardown no longer
  needs to patch a dangling `cts->L`.
- `lj_ctype_new_l(L, cts, ...)` and `lj_ctype_intern_l(L, cts, ...)` now carry
  allocation/error state explicitly. Parser sites pass `CPState.L`, direct
  runtime conversion/arithmetic/cdata/C-call sites pass their active `L`, and
  recorder sites pass `J->L`.
- `lj_ccall_ctid_vararg()` now takes `lua_State *L` because vararg type
  inference can intern pointer/reference helper types.
- Added `tools/ci/m7_ffi_ctype_intern_l.sh` and wired it into M7. The gate
  rejects `cts->L`, `parse_L`, and old non-`_l` ctype allocation/intern APIs,
  then re-runs parser, cdata write, and arithmetic stress paths.
- Remaining from the original M7 report: CTState table growth, ticket
  allocation, and hash-chain publication are still the planned RCU/CAS work.
  This slice only removes the shared Lua-state bridge used for allocation and
  errors; performance cleanup stays deferred to M9.

FFI ctype hash publication prep:

- Original plan state: `plan/11_ffi_concurrency.md` calls for widening ctype
  hash heads from `CTypeID1` to CAS-able words, publishing fully initialized
  records into hash chains with lock-free prepend, and pairing that with
  ticketed ID allocation and RCU-safe ctype table growth.
- Current slice widens `CTState.hash[]` to `uint32_t` while preserving the
  original low-16-bit `CTypeID` payload. All ctype hash head readers now use
  `ctype_hash_load()` with acquire ordering, and all local hash head publishers
  use `ctype_hash_store()` with release ordering.
- `LJ_CTYPE_SAVE`/`LJ_CTYPE_RESTORE` still snapshot and restore the hash array
  during parser rollback. That remains covered by the parser mutation token; it
  is not the final parse rollback design for table RCU.
- Added `tools/ci/m7_ffi_ctype_hash_publish.sh` and wired it into M7. The gate
  rejects raw ctype hash head reads/stores in `lj_ctype.c`, then reruns parser,
  cdata write, and metatype/miscmap stress paths.
- Remaining from the original M7 report: this is publication plumbing only.
  Hash insertion is not yet CAS-prepend, ID allocation is not yet ticketed, and
  `CTState.tab` growth is not yet RCU-safe. Pointer-stability hazards around
  raw `CType *` values and `ctype_typeid(cts, ct)` must be handled before RCU
  table growth is enabled. Performance cleanup stays deferred to M9.
