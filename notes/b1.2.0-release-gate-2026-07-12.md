# b1.2.0 release gate (2026-07-12)

The plan files are unchanged. This note records the release sequencing chosen
during implementation.

Status: this is the gate definition, not a declaration that the gate has passed.
The Linux correctness, sanitizer, stress, and performance checks below remain in
progress until a release-candidate result is recorded explicitly.

## b1.2.0 scope

`b1.2.0` is the first functional GC2-and-JIT beta. Its hard gate is:

- GC2 is the only runtime and shutdown collector; no legacy collector fallback
  is reachable.
- GC2 allocation, tracing, weak/finalizer processing, sweep, reclamation, and
  `lua_close` work reliably in ordinary and stressed Linux x86_64 use.
- The x86_64 JIT can record, compile, enter, exit, link, flush, retire traces,
  and reclaim trace/machine-code storage while GC2 is active.
- Known hangs, memory corruption, use-after-free, double-free, shutdown leaks,
  or failures in ordinary LuaJIT/FFI use are release blockers.
- Representative interpreter/JIT/GC workloads receive a performance sanity
  comparison against stock LuaJIT. Every default comparison row must stay at
  or below the existing `3.0x` ceiling; a timeout or runaway CPU, latency,
  throughput, or memory regression is also a release blocker. The final
  parity-or-better target is not a b1.2.0 gate.
- Linux assertion/stress/sanitizer coverage passes. Cross-platform CI may keep
  providing useful build/smoke evidence, but macOS and Windows completion is
  not a hard gate for this Linux x86_64 functional beta.
- The temporary internal-allocator-only policy remains explicitly documented:
  the `lua_Alloc` ABI parameter is accepted but ignored for now.

This narrower beta gate does not waive correctness failures found while making
GC2 and JIT usable. In particular, an FFI finalizer or ordinary library action
which can hang the collector is still a GC2 release blocker even though the
complete lock-free FFI redesign is scheduled later.

## Current correctness checkpoint (not yet a release candidate)

The 2026-07-12 checkpoint passes the GC2 assert/paranoia fixtures, 509 stock
tests with JIT, 387 stock tests in the no-JIT profile, no-drop recovery,
pending-root races, terminal THREAD preparation, live threading roots, JIT
trace publication/retirement, the recorder-token/secondary-JIT gate, recursive
JIT retention, FNEW allocation, and ordinary FFI cdata allocation including
over-aligned/huge progress. The deterministic JIT/full-GC sweep livelock is
fixed and its focused fixture passed 20 consecutive runs.

The release gate remains open for the full Linux sanitizer/stress pass and the
representative performance sanity comparison. The closure-heavy GC-active
path is still under optimization and is not being treated as release-ready by
this checkpoint.

### 2026-07-13 recovery and generational boundary

The recovery worker/public-edge split now bounds cyclic table, self-metatable,
closure, and userdata replay while preserving semantic barrier REDIRTY. Exact
huge-lane accounting, rollback fail-stop, and non-destructive terminal
reconciliation are covered by the focused normal/paranoia matrix. See
`gc2-recovery-cycles-and-b1.2-minor-fallback-2026-07-13.md`.

For this beta, generational remembered publication remains active but physical
minor sweep and minor-root elision are explicitly disabled. Generational
requests fall back to complete major cycles. This is an accepted correctness
fallback for b1.2.0, not completion of generational GC, and its performance and
feature restoration is release debt for b1.2.1.

## b1.2.1 continuation

The following full-project requirements continue immediately after b1.2.0 and
are targeted at `b1.2.1`:

- eliminate the remaining peer-dependent waits and blocking SMR readers;
- complete nonblocking/thread-safe ordinary FFI, VM, table, string, callback,
  and JIT control paths (with `cdef` and module loading remaining scoped control
  plane exceptions);
- complete adversarial racy-Lua semantic coverage and the final performance
  parity-or-better work;
- complete macOS and Windows validation and platform-specific correctness work;
- resolve documented temporary compatibility limitations.
- audit every IDLE parent-qualified non-table remembered barrier and re-enable
  physical minor sweep/root elision with adversarial mutation coverage;

The requested `atomic` library remains a later tranche and is not part of the
b1.2.0 gate.
