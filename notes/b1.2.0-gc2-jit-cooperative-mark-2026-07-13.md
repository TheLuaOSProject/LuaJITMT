# b1.2.0 GC2/JIT cooperative MARK admission (2026-07-13)

This tranche extends the x64 native-entry protocol from IDLE and the physically
safe part of SWEEP into the logically concurrent part of MARK. It deliberately
does not admit native execution during activation, MARK root closure, WEAK, or
any physical reclaim boundary.

## Phase contract

The public `jit_phase_gate` remains the VM-visible two-sided admission word.
MARK adds three C-owned scheduling fields:

- `jit_mark_resume` is the exact GC2 cycle generation whose activation
  handshake completed. A MARK entry is valid only when it equals `gc2.cycle`.
- `jit_mark_auto_yield` is the remaining bounded pre-dispatch allowance. It
  lets the automatic driver reach a native entry without forgiving any
  collector debt.
- `jit_mark_yield_until_ns` is the end of the current 50 microsecond mutator
  lease. It is phase-local and is cleared by every owned close.

The fields are separate from `jit_sweep_displaced` and
`jit_sweep_yield_until_ns`. MARK never borrows the SWEEP displacement token, so
a late MARK owner cannot manufacture a SWEEP reopen and a SWEEP owner cannot
consume a stale MARK scheduling request.

The IDLE -> MARK order is now:

1. claim the collector worker token and preserve the exact cycle request;
2. close `jit_phase_gate`, execute the SC fence, and reject any still-active
   trace without consuming the request;
3. stage and recheck typed activation, publish MARK, reset cycle state, and
   increment the cycle generation;
4. synchronously consume
   `ENABLE_BARRIER|ALLOC_BLACK|EXIT_TRACES|REDISPATCH|FLUSH_SSB` on every live
   TG;
5. consume the exact cycle request (`cycle_leader -> 0`);
6. publish `jit_mark_resume = cycle`, publish the 64-opportunity pre-dispatch
   allowance and a bounded MARK deadline, and only then release-open native
   entry.

A failed request CAS pins typed activation `NO_RECLAIM` and leaves native MARK
entry closed. A TG attached after the activation handshake adopts MARK barrier
and black-allocation state before it becomes live, so it may use the already
published generation after attach completes.

## Bounded scheduling

An ordinary MARK worker honors an unexpired mutator lease. At expiry it closes
the entry gate and takes the matching SC fence. If any TG still publishes
`jit_base` (including a traced call blocked in foreign code), the worker returns
immediately. It never waits for that TG. XPOLL, allocation cadence, or ordinary
trace/foreign return later clears the publication. The close helper also drops
its Boolean fixpoint intent on this deferral; retaining it would make a parked
worker report fake progress and busy-loop for the duration of the foreign call.

After one bounded logical mark/recovery/SSB quantum, a worker which is still in
MARK grants a fresh bounded native lease. A bounded fixpoint miss likewise
clears its close intent and grants a fresh lease; barriers and black allocation
make already-completed logical work stable.

The automatic driver may stop its remaining batch after one completed
collector unit while the MARK gate is open and one of the cycle's 64
pre-dispatch opportunities can be consumed. Crucially, that handoff stores the
allocation threshold at exactly `gc.total`, so the very next allocation still
owes collector work. If no native entry occurs, interpreted allocation
therefore pays one unit per opportunity and exhaustion resumes the full
automatic batch. All three x64 native-entry paths clear the remaining allowance
before publishing `jit_base`; their existing gate publication/recheck protocol
rejects a racing close. Once the allowance is zero and no TG is active, a
worker elides the unused remainder of the 50 microsecond lease. This reaches
JLOOP without permitting either indefinite interpreter starvation or hidden GC
debt.

Trace recording is admitted between close attempts during an authorized MARK
generation. `J->cur` and `J->curfinal` are token-private NOBARRIER construction
state, so they are never used as a persistent root certificate. Every close
which observes a non-IDLE recorder requests an asynchronous abort, reopens the
root state, and returns without waiting—even when the root scanner is nested on
the exact TG which owns the JIT token. The precheck, post-handshake recheck,
fixpoint test, and MARK -> WEAK transition all enforce the same rule, including
the owner-only reuse path after an earlier state-1 certificate.

A full collection invoked recursively by that recorder owner cannot wait for
its own unwind, because the unwind is sequenced after the API returns. It now
publishes the same abort and defers the collection without starting a cycle.
Peer-owned recorders use the ordinary nonwaiting retry. WEAK remains a
recording/native-entry veto. New recording is also denied throughout SWEEP for
b1.2: published traces still execute after the safe bridge, but newly appended
IR KGC/snapshot edges need a dedicated sweep-rescue publication before
post-bridge recording can be sound.

## Root-snapshot certification

Each reclaiming phase owns its exact root certificate. MARK's persistent state,
WEAK's close state, and SWEEP's mandatory pre-bridge snapshot all use `0` for a
needed scan, `2` for the current provisional handshake, and `1` for a completed
certificate. Any root walk which cannot prove a publication calls the shared
phase-dispatched retry path. MARK invalidates provisional or reusable state;
WEAK invalidates both its root certificate and `weak_mark_closed`; SWEEP resets
only its current provisional `2 -> 0` scan, so a later barrier/NEEDSCAN pass
cannot retroactively revoke an already-published safe bridge. Every path charges
`marks_this_round` and wakes a worker. The corresponding final `2 -> 1` CAS
therefore cannot certify a truncated scan.

`SWEEP_READY` now enforces that certificate at its own publication edge. The
raw latch setter refuses `sweep_root_scanned != 1`, so an early internal or
white-box caller cannot manufacture the permanent and contradictory
`READY=1/root_scanned=0` state. Synthetic sweep fixtures explicitly model a
completed certificate; the paranoia generational fixture drives the real
bounded bridge instead. A phase regression calls the raw setter at state 0 and
proves that both READY and native admission remain closed.

This tranche applies that rule to:

- any active recorder, including same-owner RECORD/ASM state and persistent
  MARK-certificate reuse (after requesting an asynchronous trace abort);
- partial/dead cdata preclaim-vector publication and invalid head/count/cap
  snapshots;
- live threading nodes, THREAD identity-registry entries, and active/retired
  userdata FINREG metadata whose exact allocation cannot be admitted;
- a finalizer FIFO owned by a foreign TG: root marking now uses `try_enter`,
  invalidates the phase certificate, and returns instead of waiting behind an
  arbitrary user `__gc`/FFI callback;
- malformed or cyclic stable native-root chains.

The live/thread/FINREG walks no longer retry forever at
`LJ_GC2_ROOT_SCAN_LIMIT`. They follow the finite successor suffix captured from
the list head, holding exact admission across each link handoff, and use Brent
cycle detection without an allocation or count cap. Concurrent publication is
head-only and marks after publication; removal only shortens these stable-link
paths. Thus a valid registry larger than one million entries still completes,
while a corrupt cycle reopens the snapshot instead of trapping the handshake.
TG root anchors retain their producer-enforced one-million-slot bound; dynamic
block admission now releases its scope on every failure path before retrying.

The same uncapped rule now covers retired string-table/quarantine/body records,
table node/array storage, CType tables, CLibrary cache entries, TraceVec/trace
bodies, and active/retired mcode sidecars. Their reclaim and terminal validators
require every published node to remain registered under the surrounding SMR
generation; an invalid node is therefore corruption/incomplete observation,
not a stale end-of-list sentinel. Root marking reopens the phase certificate on
an invalid node or Brent-detected cycle. The former silent table/CLibrary
one-million-node truncation is gone, and trace/mcode scanners propagate failure
back to the phase-aware retry owner.

Table graph and weak clearing also no longer wait behind a descheduled
structural writer. GC snapshots return TRANSIENT after one changed-generation
observation; KEYLOCK, FORWARD, FFI claim, or temporary lifetime admission makes
the table retain NEEDSCAN (or leaves the weak cursor unadvanced) and retries on
a later bounded worker turn. Collector `__mode` lookup uses a separate
FOUND/ABSENT/RETRY API under the exact table scope and SMR reader, so generic
mutator lookup policy is unchanged and RETRY can never be misclassified as an
absent weak mode.

Userdata finalizer discovery uses the same tri-state `__gc` lookup. A transient
metatable generation retains and marks the FINREG node/userdata, reopens the
WEAK certificate, and performs no finalized-bit, unlink, discovery, or enqueue
mutation. Cdata ordered FINREG discovery likewise preserves transient object
admission as RETRY (rather than MISS), treats liveness as a tri-state, and
reopens/breaks the P_WEAK scan on resolve, slot, or claim RETRY. This prevents a
temporary lifetime/FIN-table handoff from being silently skipped under a
completed WEAK certificate.

Successful userdata and cdata discovery also retain the exact object admission
through finalizer publication. Once a finalizer slot/root has been consumed,
the enqueue helpers no longer perform a second observational admission which
could transiently fail and silently discard the callback. Finalized state,
phase retention, queue accounting, and callback publication are now one
scope-held success path. The still-existing per-callback allocation and CAS
publication debts are listed below; this change closes semantic loss, not their
progress guarantees.

## Known nonblocking boundary after this checkpoint

This tranche removes waits inside the newly cooperative MARK/WEAK root and
table paths, but it does **not** complete the repository-wide nonblocking GC
claim. `lj_safepoint_handshake()` is still a synchronous soft-handshake state
machine: leader contention, an unfinished prior epoch, a descheduled VM TG
which has not acknowledged, trace quiescence, consumed-poll release, and its
final SMR-reader acquisition can wait without a caller-visible bound. MARK,
WEAK, and SWEEP root certificates all currently use that primitive. A future
tranche must split publication from cooperative completion, let any helper
advance the exact epoch without retaining a thread-owned leader, and leave the
phase certificate open while an unacknowledged TG continues or is descheduled.
Until that conversion and its stalled-owner tests land, phase work is safe but
strict lock-free/nonblocking progress is not yet a release claim.

Finalizer publication has additional follow-on debt. The current queue allocates
one libc node per callback, aborts on allocation failure after destructive
discovery has begun, and publishes through a retrying Treiber CAS. The first
cdata preclaim-vector preparation can also use a throwing allocation while the
worker token is held. These paths need preallocated/arena-owned no-throw records
and a wait-free publication or persistent retry identity before the eventual
fully nonblocking GC/FFI claim. Generic pending-root splicing and some arena
reader/rescue operations also retain starvation-prone CAS loops; they are
lock-free at the system level but not yet wait-free for an individual GC owner.

## Closed boundaries

The following boundaries unconditionally close the gate, execute the SC fence,
and observe zero active native JIT users and zero active recorder state before
proceeding:

- MARK global/owner root snapshots;
- every MARK fixpoint round;
- the successful MARK -> WEAK CAS.

`jit_mark_resume`, the pre-dispatch allowance, and the MARK deadline are cleared
at MARK -> WEAK. WEAK never opens native entry. IDLE and SWEEP open helpers also
clear MARK scheduling state before publishing their own phase admission.

The common allocation checkpoint performs bounded assist first, then requests
an asynchronous MARK close, and only then advances `hard_check_bytes`. The JIT
hard-cadence path uses the same order. Thus an allocating trace cannot consume
the cadence and continue indefinitely past a required closed mark quantum.

## Deterministic coverage

`tests/t-gc2-jit-mark-coop.c` is wired into both the normal
`m6_jit_gc2_readiness` build and the helper-instrumented
`m6_jit_alloc_account` build. It checks:

- activation actions and the request token are consumed before the generation
  and gate open;
- a real x64 allocating trace executes while phase is MARK;
- the zero-worker common allocation checkpoint closes MARK and advances the
  hard cadence;
- a table retained only by an active trace frame/snapshot survives an
  asynchronous XPOLL close, closed root snapshot, and the rest of the cycle;
- a recorder stalled on a foreign JIT token makes its root snapshot retry and
  prevents MARK -> WEAK until the asynchronous abort is observed and the token
  is released;
- a same-owner recorder reached through a nested GC check cannot certify its
  mutable private geometry, and a nested full collection aborts/defer-returns
  instead of waiting for its own recorder unwind;
- an active native `jit_base` held across a modeled blocking traced-FFI interval
  makes MARK completion return promptly rather than wait or spin a worker;
- a worker attached in MARK drives a closed quantum and republishes a bounded
  background mutator lease;
- successful MARK -> WEAK keeps the gate closed and clears the MARK generation;
- late worker attach, preserve-abort, and repeated activation/abort cycles do
  not leak MARK admission into IDLE or WEAK.

The GC2 phase/traversal fixtures additionally hold the finalizer token on a
foreign thread and prove root scan returns before a watchdog releases it,
revoke a completed MARK certificate with a synthetic retired-table cycle, and
hold `__mode`/weak-table KEYLOCK values to prove lookup, weak scan, and weak
clear return RETRY without consuming their cursor. Repairing the synthetic
publication lets the same item complete normally. Separate userdata-metatable
and cdata-finalizer-table RETIRING-generation cases prove that WEAK reopens,
performs no destructive state change, and dispatches each callback exactly once
after the publication is repaired.

The blocking interval is modeled at the exact `jit_base` publication boundary,
so the collector-side proof is independent of C signature and ABI argument
shape. Production no longer has the superseded explicit ordinary-FFI
signature-matcher matrix: it has one generic ABI-driven `IR_CALLXS` seam.
Ordinary calls remain interpreted only while the generic traced-call native
frame/root/unwind protocol is unfinished; enabling that seam safely is a
separate tranche, not an invitation to restore per-signature matchers.

## Validation

Completed in the shared implementation worktree:

- successful default, `LJ_GC2_TEST_HELPERS`, and
  `LUA_USE_ASSERT|LJ_GC2_PARANOIA=1` builds. GCC still emits the documented
  false-positive null-region diagnostic while inlining
  `gc2_root_rescan_later`; it does not fail the build;
- `t-gc2-jit-mark-coop` normal, helper, and assertion/paranoia runs, including
  the deterministic stalled-recorder snapshot retry;
- `t-gc2-traverse` with direct worker/fixpoint fixtures explicitly pinning
  native resumption closed, so their tight ownership loops do not race the
  production 50 microsecond lease;
- `t-gc2-alloc-account`, whose direct fallback worker closes the intentional
  fresh MARK predispatch lease before requiring immediate progress;
- `m6_jit_gc2_readiness`, including TNEW, CNEW, SNEW, existing SWEEP
  cooperation, and the new MARK fixture;
- helper accounting, arena-sweep, worker-scheduler, phase, traversal, and
  paranoia-oracle fixtures;
- existing cooperative SWEEP and JIT hard-cadence fixtures.

The helper SWEEP checkpoint now warms a stable root-trace TNEW and places the
allocation before volatile FFI telemetry. Its global hard cadence is one byte
short while the TG batch retains 4096 bytes of headroom: the unavoidable
interpreted prologue stays below the flush line, then a real native TNEW crosses
the common accounting checkpoint with `jit_base` live. This preserves the
production close assertion and avoids relying on a growing hash insertion
which legitimately side-exits while SWEEP denies new side recording.

The earlier `0.063s`/7.3x result was invalid: it came from an unconditional
automatic-driver lease break which moved the threshold forward and therefore
measured deferred collector debt, not a completed workload cycle. With the
bounded pre-dispatch allowance and exactly-due threshold, a fresh helper VM
running the representative forced-unsunk `200000` non-empty table-allocation
loop finishes in IDLE after roughly 57-67 cycles, retains about 0.47-0.76 MiB
above its baseline, and accounts roughly 22 MiB of allocation. Shared focused
runs were about 0.118 seconds; independent runs measured about 594-603 ns per
table. The invalid debt-deferring variant instead remained in an active
collection with roughly 22.5 MiB retained after only a few cycles. Closure
counts for the corrected scheduler remained near the prior cooperative baseline
(about 377-386 in focused runs), whereas the invalid variant reached about
1241-1275 without completing MARK. These are bounded-memory and progress
checks, not a throughput claim; forced table allocation is still roughly 7x
stock (about 71 ns per table), so the b1.2 performance gate remains closed.

The existing IDLE and SWEEP close/reopen protocols are unchanged except that
their open helpers defensively clear the disjoint MARK scheduling fields.
