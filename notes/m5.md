M5 internal tag audit:

- Tried the straightforward section 6.1 approach of moving `LJ_TNUMX` /
  `LJ_TISNUM` down to make room for `LJ_TKEYLOCK` and `LJ_TFORWARD`.
- Reverted it after stock tests showed NaN comparisons failing. On this x64
  dual-number representation, the canonical hardware NaN pattern occupies the
  `~15u` itype range, so making `LJ_TISNUM == ~15u` causes `tvisnum(0/0)` to
  fail and comparison operators raise `"attempt to compare two number values"`.
- The table sentinel representation needs a design that preserves canonical
  NaN and integer tagging. Do not blindly lower `LJ_TISNUM` for M5 tables.

M5 source child-cell JIT slice:
- Removed the parser-side PROTO_NOJIT mark for source child protos whose
  upvalue descriptors capture parent local cells. Runtime FNEW already promotes
  the parent raw slot to a closed GCupval cell for PROTO2_CELLUV protos, and
  child bytecode records through the existing closed-upvalue UGET/USET path.
- Extended tools/ci/m5_cell_ops.sh to statically guard fs_has_celluv against
  reintroducing PROTO_NOJIT and to require traces for repeated numeric and
  GC-valued child-upvalue closure loops.
- Subagent CNEW audit: keep the self-captured local-function CNEW/FNEW/CSET
  guard for now. Removing it is runtime-correct in simple repros but exposes
  BC_CNEW to the recorder, which aborts as NYI, and implementing BC_CNEW alone
  immediately hits FNEW NYI in creation loops. The safe next path is a
  dedicated non-sinkable upvalue-cell allocation IR/path for BC_CNEW (not FFI
  IR_CNEW), forced snapshot correctness after the allocation, then FNEW
  recorder support before removing the guard or opening loaded v4 cell protos.

M5 string table CAS publication slice:
- Added an active-user pin in StrTabHdr.resize. Interners increment the count
  before walking/publishing through the current header; resize claims the high
  bit only when the count is zero, so the old vector is not freed while a
  string lookup or bucket CAS can still touch it.
- Changed string intern publication from plain prepend stores to a release CAS
  on the bucket head with an acquire duplicate recheck after CAS failure. Losing
  duplicate allocations are still unpublished raw string objects and are freed
  immediately.
- This is not the full 06 section 6.5 helping/Harris sweep protocol yet:
  resize currently skips if active interners are present, and secondary-chain
  rehash remains a follow-up audit point. A concurrent Lua stress also exposed
  an older allocator/TG crash in lj_arena_alloc during child-thread concat
  buffer growth; keep that as a separate allocator-concurrency item rather than
  treating it as a string-table CAS failure.
- Added tests/t-strtab-cas.c and tools/ci/m5_strtab_cas.sh; wired the guard
  into tools/ci/m5_concurrent_objects.sh.

M5 immutable local-cell capture slice:
- Fixed a source-v4 parser/runtime hazard where a local first captured after

- This restores ordinary immutable local-function capture patterns used by

M5 conservative owner local-cell emission slice:
- Replaced the captured-only owner-frame parser emission rule with a
  conservative source-v4 rule: active local reads emit raw-tolerant `BC_CGET`,
  local writes emit raw-tolerant `BC_CSET`, and table/key operands backed by
  active locals are materialized through `BC_CGET`.
- This preserves the original closed-cell mutable capture semantics when a

- Added parser and threading regressions for mutable pre-capture owner reads:

M5 string table active-drain resize slice:
- Changed string-table resize from "skip if active interners are present" to
  claim the `LJ_STRTAB_RESIZE` bit while preserving the active-user count, then
  wait for existing active interners to drain before copying the old buckets.
  New interners already spin on the resize bit, so inserts cannot keep extending
  a table after resize has claimed it.
- Retired old string-table headers onto `g->str.retired` instead of freeing
  them immediately after publishing the replacement header. This is a
  conservative stopgap for readers that have loaded the old RCU pointer but not
  yet incremented its active count; the retired raw blocks are marked during GC
  and released at state close.
- Fixed current-header string scans to snapshot one `StrTabHdr` and use its
  `mask`, avoiding a transient mix of `g->str.mask` with a different published
  header during resize.
- Kept the original 06 section 6.5 target intact: this is still an intermediate
  pin-and-drain protocol, not the final bounded helper-copy/Harris unlink/epoch
  retirement design.
- Updated `tests/t-strtab-cas.c` so it no longer relies on the old active-pin
  resize skip behavior and instead verifies the last active interner can leave
  a resize-claimed header and that resize retires the old header.
