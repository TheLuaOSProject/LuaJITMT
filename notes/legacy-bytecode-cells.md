# Original LuaJIT bytecode and shared local cells

## Compatibility defect and implementation

The source compiler and original LuaJIT bytecode previously used different
capture representations. Loading an original version-2 dump after threading
activation could silently copy a local into each closure. For example, two
closures capturing `x`, followed by an owner assignment `x = 7`, observed their
old values instead of the same local. Source-only stock tests and the fork's
version-4 dump/load tests did not cover that import path.

`lj_bcread.c` now normalizes legacy captures before publishing their prototype.
It accepts the existing version-2, transitional version-3, and explicitly legacy
version-4 formats and lowers captured local accesses into the existing `CNEW`,
`CGET`, and `CSET` operations. Original immutable capture metadata is retained;
it no longer implies distinct closure identities after the source capture fix.
The normalizer is reader-local and does not add locks or a runtime dispatch
layer. Version-4 dumps of normalized prototypes use the existing cell format.

The transformation uses control-flow dataflow over original register slots.
Actual captures persist until `UCLO`; speculative cells created by the recorder
are tracked separately and can be discarded by raw definitions and temporary
register windows. Backward pending-capture analysis accounts for promotion
before a branch that skips its later `FNEW`. Branches and debug program counters
are relocated, including local-name scope intervals and 8-, 16-, and 32-bit line
information. `ITERN` must retain its immediately following `ITERL` instruction.

Closing a scope or exposing raw return/tail-call operands uses `CGET r,r`.
Both VM implementations load the source before replacing the destination, and
recording obtains the payload before setting the slot. This avoids a temporary
register overwriting dynamic multires results. The reader accepts self-`CGET`
while continuing to reject self-`CSET`.

The replacement prototype remains opaque until it is complete. Constants retain
the reader's existing semantic anchors. The replacement takes over the pending
prototype anchor before the old allocation is cancelled; temporary work and
unpublished allocations are freed by the existing protected error path.

The recorder also recognizes call clobber windows, vararg result windows,
loop-control writes, and all return/tail-call scan boundaries when finding
future captures. `tests/t-jit-cell-pending.c` exercises those production helpers
without requiring ARM64 upvalue machine-code admission. The old scan crossed
`RETM`/`CALLT`/`CALLMT`; the focused fixture failed before the correction and
passes with it.

## Checked evidence, 2026-10-22

Validation used disposable builds with assertions, deployment target 13.0,
`LUAJIT_MT_ARM64_BOOTSTRAP`, and `LJ_GC2_TEST_HELPERS`. The safe build additionally
used `LUAJIT_DISABLE_JIT`; the experimental build used
`LUAJIT_MT_ARM64_JIT_EXPERIMENTAL` and `LJ_TRACE_TEST_HELPERS`.

- `tests/t-legacy-bytecode-cells.c` passes on safe and experimental ARM64. Its
  checked-in artifacts were generated by original LuaJIT 2.1.1788856981, not by
  this fork. Cases cover stripped and unstripped little/big-endian v2, shared
  read-only and mutable identity, owner writes, recursive closures, numeric and
  generic loop scopes, optimized `pairs`, repeat scopes, conditional writes,
  skipped captures, varargs/multires, debug local names and writes, error lines,
  worker sharing, and normalized v4 round trips. The reader forces GC between
  17-byte input chunks, rejects truncated input, and collects afterwards. Cross-mode FR1
  prototypes remain loadable and dumpable; they are not executed on FR2.
- The original stock suite passes 509 source tests and 509 tests with each
  `load`/`loadstring` source compiled by a persistent original LuaJIT process
  and imported after threading activation. The latter is reproducible with
  `tools/ci/stock_bytecode_corpus.lua` and `LUAJIT_STOCK` pointing to an original
  v2 compiler, from `tests/stock/test`.
- The unchanged `tests/t-bcdump-current.c` passes on experimental ARM64. Its
  malformed-byte mutation test exposed an existing assertion on a nil template
  table key. Commit `795c27fb` replaces that assertion with a load error, with
  no change to constructor root cleanup.
- The unchanged `tests/t-legacy-upvalue-entering.c` and
  `tests/t-thread-gcprep.c` pass on experimental ARM64. Both construct true
  legacy open cells explicitly and still exercise admission vetoes and terminal
  close/count cleanup. Imported v2 is now normalized and no longer stands in
  for these internal runtime cases.
- `tests/t-threading-coroutine.lua` (including dead-resume),
  `tests/t-upvalue-identity.lua`, and the interpreter portion of
  `tests/t-threading-upvalue.lua` pass. The last fixture must hide global `jit`
  on ARM64 because it otherwise explicitly re-enables and requires an upvalue
  store trace outside current ARM64 admission.

Regenerate portable artifacts with:

```
python3 tools/ci/generate_legacy_bytecode_fixtures.py /path/to/original/luajit
```

The standalone C fixture accepts its fixture directory as its first argument,
or uses `$LJ_TEST_ROOT/tests/fixtures`, falling back to `tests/fixtures`.
The ordinary suite case is `m5_legacy_bytecode_cells`.

## Explicit limits and remaining work

This is a compatibility improvement, not a claim of full stock bytecode or JIT
conformance. ARM64's existing admission policy still rejects general generated
upvalue effects; these native suite passes therefore do not prove unrestricted
cell traces. An intermediate importer passed 509 imported tests on x86-64 via
Rosetta, but a later x86-64 run encountered a recursive JIT failure before the
subsequent `RETF`/CNEW fixes. Final x86-64 JIT validation is outstanding because
Rosetta LuaJIT processes on this host became uninterruptible. No new x86-64 pass
is inferred from the ARM64 evidence.

The load-time converter currently reserves three scratch slots in an owning
prototype. Original frames above 247 slots fail with “function or expression
too complex”; a genuine stock 248-slot fixture checks that explicit boundary.
Expanded jumps must still fit LuaJIT's signed 16-bit offsets. Unsupported raw
concatenation windows containing possible cells, actual captured locals in
implicit call/iterator/loop windows, and transformations that would break
`ITERN`/`ITERL` adjacency fail with “cannot load incompatible bytecode”. The
stock compiler normally stages those operands in temporary registers, and the
current corpus passes, but these rejection paths are not a full proof of all
valid original bytecode forms. There is no fallback to silent snapshots.

The lock-free legacy admission/count protocol remains required for genuinely
legacy runtime prototypes. It preserves ordinary owner aliasing before the
first secondary admission and allows activation after those captures normally
close. Its existing post-activation snapshot policy remains an internal legacy
limitation; normalized imports use shared cells instead. See
[legacy-upvalue-admission.md](legacy-upvalue-admission.md).
