# M9 Notes

Performance closing setup:

- Added `collectgarbage("stats")` as a read-only benchmark telemetry surface.
  It returns a table with existing GC2 counters for cycle requests/starts,
  allocation pacing, assist and worker progress, owner sweep progress, weak
  clearing, finalizer queueing, and live estimates. This wires the stats called
  out in `plan/13_testing_and_benchmarks.md` without changing collector pacing or
  phase behavior.
- Added `tests/t-gc-stats.lua` and `tools/ci/m9_gc_stats.sh`, covering the stats
  table under interpreter and default-JIT modes. The multi-thread benchmark now
  prints a stable subset of these fields while retaining a fallback for older
  binaries.
- The stats guard now also rejects raw production access to GC2 sweep-live
  estimate fields: `sweep_live_updates`, `sweep_live_huge_bytes`, and
  `live_estimate`. Stats and pacing read them through `gc2_*` helpers, matching
  the sweep-close publisher.
- Added safepoint poll-ack latency telemetry. Each handshake records a monotonic
  publish timestamp, and each successful TG ack contributes sample/sum/max
  nanosecond counters exposed through `collectgarbage("stats")`.
- Added a power-of-two poll-ack latency histogram to `collectgarbage("stats")`;
  `bench_mt.lua` now reports approximate P99 bucket bounds from per-benchmark
  histogram deltas.
- Exposed the remaining FINREG/finalizer bridge telemetry through
  `collectgarbage("stats")`: cdata/userdata FINREG registrations, queueing,
  P_WEAK/sweep fallback counters, ordered FINREG scan counters, weak-write
  marks, MPSC finalizer drains, finalizer enter/leave counts, sweep blocks, and
  finalizer-spawn deferrals. `tests/t-gc-stats.lua` now requires these fields
  and checks their monotonicity, while `bench_mt.lua` prints the most useful
  fallback counters for performance runs.
- Tightened the `collectgarbage("stats")` result construction so every scalar
  field and latency bucket entry is CAS-published, the nested latency bucket
  table reference is explicitly published to the parent result table, and the
  completed stats table is republished before returning it to Lua. The M9 guard
  now rejects the old direct stats-slot writes.
- Added `threading.now()` as the monotonic wall clock used by `bench_mt.lua`.
  The multi-thread harness now honors `BENCH_SCALE`, clamps zero-duration smoke
  runs, and skips pairwise channel benchmarks for odd thread counts instead of
  hanging the documented 1-thread scaling run. The synchronized benchmark
  runner accepts `BENCH_THREADS` and `BENCH_FILTER`, and
  `tools/ci/m9_bench_smoke.sh` exercises the scaled 1/2-thread benchmark path.
- Tightened `bench_mt.lua` to require `threading.now()` directly and reject
  `os.clock`, so multi-thread scaling reports cannot silently use process CPU
  time instead of monotonic wall time.
- Added `tools/ci/m9_m10_gc.sh` as the current GC telemetry/generational
  aggregate. The M9 stats smoke, M9 benchmark smoke, and M10 generational guard
  now each reject being left out of that aggregate.
- Exposed parked-worker scheduler telemetry through `collectgarbage("stats")`
  and the benchmark report: worker busy retries, idle declarations, wake
  publications, park events, and async progress. `tests/t-gc-stats.lua` now
  requires those fields and checks monotonicity alongside the existing worker
  drain counters.
- Removed the temporary `lj_gc2_worker_drain_progress()` compatibility alias.
  `lj_gc2_worker_drain()` already returns saturated total progress for grey
  work, SSB conversion, weak draining, and sweep batches, so all internal
  callers and guards now use the single worker-drain surface.
- Removed the remaining close-time FINREG generation-table pending/discovery
  scans. Every enabled `ffi.gc` registration publishes an ordered FINREG node,
  so `lj_gc_cdata_fin_pending()` and close-time cdata separation now use the
  ordered list directly. A later M8 cleanup removed the P_WEAK root-list
  fallback for preclaim side-vector failure; that branch now queues the same
  ordered cdata object directly. The sweep/free cdata queue remains as a
  defensive missed-publication path.
- Tightened FINREG ordered publication after removing those scans:
  `cdata_fin_store()` now CAS-publishes the ordered node while the FINREG slot
  still contains the claim sentinel, before setting the cdata FIN bit and
  release-storing the finalizer function. Ordered scans already wait out claim
  sentinels, so this avoids a candidate-visible window without restoring a
  generation-table fallback.
- Added canonical single-thread benchmark accounting for the M6/M9 performance
  gate. `bench/compare_baseline.sh` compares two `bench/run_baseline.sh` CSVs,
  fails missing or extra benchmark rows, computes the geomean over the
  `jit_ns_per_op` column by default, and enforces the documented `<= 1.10`
  threshold.
- Resynced the documented `aux/bench/` harness with the active M9 benchmark
  controls from `plan/aux/bench/` and retargeted benchmark CI plus
  `bench/run_baseline.sh` back to `aux/bench`. `tools/ci/m9_bench_smoke.sh`
  now rejects drift between the two copies. The harness supports `BENCH_SCALE`
  for smoke runs and `BENCH_GC_MODE` for generational/incremental probes, while
  canonical full runs still use default iteration counts.
- `tools/ci/m9_bench_regression.sh` self-checks the committed pinned baseline,
  verifies a synthetic regression fails, generates a scaled current CSV, and is
  wired into the M9/M10 aggregate.
- Verification for the `aux/bench` sync: clean `make -C src -j$(nproc)`,
  `tools/ci/m9_bench_smoke.sh`, `tools/ci/m9_bench_regression.sh`, and
  `tools/ci/m9_m10_gc.sh` pass.
- 2026-06-26 benchmark-evidence attempt on a 24-core/32-thread
  i9-13900F host: running `bench/run_baseline.sh src/luajit` with
  `BASELINE_OUT=/tmp/lj-lockless-current-20260626.csv` was interrupted after
  the full current run spent more than 20 minutes in the `-joff` phase without
  producing the CSV. Isolating the scaled closure/upvalue slice exposed an
  active-thread root regression from eager thread traversal during mark
  start/atomic: a forced full GC could drop standard-library globals such as
  `collectgarbage`. Added `m3_gc_active_thread_roots` as the focused guard.
  The larger `BENCH_SCALE=0.01 ... closures_upval` timeout also reproduces on
  `HEAD^`, so the canonical full-run geomean report remains pending as a
  separate benchmark-performance blocker.
- Resolved the scaled `closures_upval` blocker by keeping legacy open upvalues
  in the thread root traversal and preventing GC2 owner arena sweep from
  reclaiming traversable bodies before the legacy root sweep has published its
  close boundary. Closed upvalue bodies now use the accounting-only deferred
  body path, preserving stale root-chain `nextgc` links until a later legacy
  sweep can splice them. `m9_bench_smoke` now includes
  `BENCH_SCALE=0.01 ... closures_upval` as a regression guard; direct
  verification completed in about 0.03s for that scaled slice.
- Resolved the next full-baseline blocker where the interpreter
  `alloc_tables` row could run for minutes. The root cause was twofold:
  legacy `GCthreshold` was still republished from the old absolute
  `estimate*pause/100` formula, and trace-side GC checks could reach the GC2
  hard limit before publishing a GC2 cycle request. GC2 now publishes an idle
  legacy threshold from current total plus remaining GC2 allocation budget,
  uses a 256 MiB tiny-heap trigger floor to avoid repeated arena-footprint
  sweeps on short-lived churn, and shares the trigger check with interpreter
  and JIT GC-step bridges. `m9_bench_smoke` now includes a scaled
  `alloc_tables` interpreter guard.
