# ARM64 numeric concatenation through `IR_TOSTR`

This slice admits only the numeric-input `IR_TOSTR` operation needed by ordinary concatenation of a number into a Lua string. It does not admit integer/character TOSTR modes, generic string concatenation, or general buffer operations.

## Why the folded trace still has a reset call

The recorder lowers concatenation through the per-thread temporary string buffer. The optimizer folds the one-put buffer chain to the resulting numeric `IR_TOSTR`, but retains an `IR_CALLS lj_buf_tmp_reset` effect. That `CALLS` is intentionally kept: ordinary side-effecting calls are not removed merely because their result is dead, and changing that optimizer rule would affect unrelated callers.

`lj_buf_tmp_reset` delegates to `lj_buf_tmp_`: it selects `L2TG(L)->tmpbuf`, records the current `lua_State` as owner, and resets the write pointer to the buffer's current base. `TGState` belongs to the current OS thread. This reset does not allocate, invoke GC, yield, or acquire a lock. Numeric formatting itself remains the stock `asm_tostr` path to `lj_strfmt_num`; that emitter prepares a snapshot and accounts for GC before the formatter calls `lj_str_new`.

The admission exception is for that exact dead-result effect only. Both semantic and post-RA passes require a zero-operand `IR_LREF` of `IRT_THREAD`, exactly one such LREF, and only exact `lj_buf_tmp_reset` calls consuming it. The LREF may have no other IR consumers, and neither it nor a reset result may appear in a snapshot; reset results may have no IR consumers. Each pass checks every snapshot's map offset/count against its own `nsnapmap` before scanning entries. The post-RA common allocation walk still validates the LREF's GPR or spill location; the local helper does not substitute an allocation verdict.

## Proof boundary

Both passes independently require `IR_TOSTR` mode NUM, a preceding value proven NUM, and a STR result. String PHIs are checked in both passes against their typed incoming TOSTR values. Post-RA call-survival checks include TOSTR so any live string value across its allocating formatter must have a valid preserved register or spill, and every snapshot use must resolve to a valid location. The initial FORL and while traces keep the pre-loop string in a spill, so the existing generic spill proof covers them. I did not retain an unneeded STR-specific RENAME exception: no captured native trace needed it, and the real traces had duplicate same-snapshot RENAME entries rather than the unique form that exception requires. The existing numeric CALLN-only RENAME proof is unchanged. The assembler and stock formatter were not changed.

The C fixture exercises semantic and post-RA corruption separately: wrong TOSTR modes/input/forward reference, altered string-PHI inputs, a source value moved from its real spill to volatile X0, wrong reset identity/type/argument, nonzero LREF operand or wrong type, malformed snapshot spans, and snapshots naming the reset result or LREF. It also retains positive ordinary traces for FORL and while loops, forced exits, peer activity, GC, and exact string comparisons for negative zero, infinities, and NaN. The Lua oracle compares the same returned strings; C string comparison is byte-for-byte so NaN formatting is checked without `NaN != NaN` ambiguity.

A separate `LJ_STR_TEST_HELPERS` fixture watches string publication only during the candidate call. It requires the exact final output `100020.125` to be published once while `lj_tg_jit_active_acq()` holds the trace lease, verifies the string's READY/traversable arena state, observes root entry and the terminal loop exit continuation, and checks retained output/code identity across full GC. `lj_tg_jit_active_acq()` is true for the published `jit_base` lease even though the separate native-depth counter is zero in this callback; the fixture follows the existing string-sub publication hook's `jit_base` criterion.
