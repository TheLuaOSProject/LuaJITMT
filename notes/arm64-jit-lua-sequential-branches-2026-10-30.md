# ARM64 Lua leaf sequential comparison branches — 2026-10-30

The bounded leaf recognizer and independent semantic and post-RA passes accept sequential chains of two through four numeric comparisons. Each comparison has one pure arm ending in `RET1` and one forward continuation; the final continuation reaches a common `RET1`. Comparison operands and return registers are checked against the prototype frame. The allocated liveness walk now transfers definitions backward through each resumed prefix, so a local assigned between decisions replaces the older value in the live set while arithmetic inputs needed for error and overflow behavior remain live.

Three- and four-decision fixtures use distinct computed operands at later comparisons. Experiments with nested thresholds on the same SSA value were rejected because optimized IR can fold or eliminate redundant comparisons, so those are not evidence for repeated independent guards. A five-comparison fixture executes under the interpreter and is refused by the bounded leaf recognizer. The implementation does not accept general CFGs, loops, calls, or arbitrary join/return layouts.

The C native fixture exercises cold exits from each comparison in the 2-, 3-, and 4-decision cases, post-GC same-trace reuse, a five-decision refusal, independent semantic/post-RA source mutation, and malformed low/high snapshot-size mutations on non-fourth snapshots. The older one-branch case also retains explicit malformed-size controls. The four-profile contract passed on ARM64 and ARM64e in assert and release configurations. The return fixture reported `cases=101`, `native=431`, `terminal=96`, `sequential-maps=3`, `reuse=335`, and `gc=101`; each four-profile return run reported 1,607 semantic and 1,617 post-RA negatives. Both targets observed the selected root's exact cold resume PCs for each decision (2-way: 5, 12; 3-way: 5, 14, 23; 4-way: 5, 14, 23, 32), matched an interpreted oracle, and retained the same self-linked loop root and machine-code address across full GC. The source grammar remains deliberately narrow: at most four comparisons, acyclic forward paths, one `RET1` at the end of each true arm, common final `RET1`, and existing pure-operation restrictions. Same-SSA comparisons that optimize away, more than four comparisons, calls, loops, and general joins remain closed.
