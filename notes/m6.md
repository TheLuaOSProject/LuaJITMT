M6 JIT recorder token scaffold:
- Added the first §8.2 recorder token bridge as `global_State.jit_token`.
  `lj_jit_token_try()` CAS-acquires the token with the current TG tid and never
  waits; hot root traces, hot side traces, and stitch attempts skip recording if
  another TG owns the token.
- Follow-up recorder-token helper slice: token acquire-load, release-store, and
  CAS now route through `jit_token_*()` helpers, and the M6 token guard rejects
  raw production/test fixture access to `global_State.jit_token`.
- Any TG with a nonzero tid may now try the recorder token. The earlier
  x64/POSIX main-TG validation guard was removed after the emitter stopped
  using recorder-TG-relative `RID_DISPATCH` addressing.
- `lj_dispatch_ins()` and `lj_dispatch_call()` now only feed record-mode
  callbacks into `J` when the current TG owns the token. This remains the
  C-side backstop for recorder state mutation.
- Recording dispatch is now TG-local: `lj_dispatch_update()` keeps the global
  dispatch template in the non-recording mode, syncs the current TG from that
  template, and overlays `lj_vm_record`/callhook only when the current TG holds
  the recorder token. Non-owner TGs no longer receive record hooks through the
  global template.
- The x64 hot-loop path passes the current `lua_State *` to `lj_trace_hot()`
  and no longer writes `J->L` in assembly before the token CAS. The C helper
  publishes `J->L` only after acquiring the recorder token.
- The x64 stitch path also passes `lua_State *` and the invoking trace number
  into C. `lj_trace_stitch()` publishes `J->L` and `J->exitno` only after it
  acquires the recorder token.
- The token is released when the trace state machine returns to
  `LJ_TRACE_IDLE`, including successful assembly, abort/error, and start-time
  refusal paths.
- `jit_State.state` now has explicit acquire/release helpers, and
  `lj_trace_abort()` is a CAS-based async abort publisher instead of the old
  plain `J->state &= ~LJ_TRACE_ACTIVE` macro. This tightens the existing
  `HS_EXIT_TRACES`/`HS_FLUSHJ` boundary without adding extra safepoints in
  places that are already covered by x64 loop/FUNCF `IR_XPOLL` and VM
  safepoint exits. The M6 token guard now rejects raw production `J->state`
  access outside the helper bodies.
- Follow-up trace-state helper cleanup routes the remaining `lj_trace_abort()`
  CAS loop through `lj_trace_state_abort()` and extends `tools/ci/m6_jit_token.sh`
  to require the trace-state helper surface while rejecting raw C-source
  `J->state` access. Verification: `tools/ci/m6_jit_token.sh` passed.
- Synchronous recorder errors pass through `lj_err_throw()`, which clears the
  `LJ_TRACE_ACTIVE` bit just like an async abort. `trace_state()` now treats
  inactive `LJ_TRACE_ERR` as the ERR cleanup state instead of fabricating a
  second RECERR object; the FFI callback STOPREQ path in
  `t-safepoint-handshake` covers this because a stale trace error used to
  corrupt the next cdata call's argument list.
- Hot side-exit counters still advance before the threshold, but once a side
  exit is hot enough to record, token-busy exits leave the retry budget and
  `SNAPCOUNT_DONE` sentinel untouched.
- The x64/POSIX trace-exit path passes `L`, the exited trace number, and
  snapshot number into `lj_trace_exit()`, and snapshot restore carries those as
  call-local values. These fields are published to shared `J` only after a hot
  side exit acquires the recorder token.
- Hot side-exit recording now revalidates that the parent trace slot still
  names the requested trace, is not marked `LJ_TRACE_SCOPE_FLUSHING`, and still
  has the requested snapshot before touching snapshot counters. After acquiring
  the recorder token, it repeats the same validation before publishing
  `J->parent`/`J->exitno`. Scoped root flush also has an idempotent unpatch
  fallback for roots already unlinked by another flush path; it only rewrites
  bytecode that still names the same trace number.
- Pending recorder bytecode re-patches now skip saved `J*` instructions if the
  saved trace number no longer names a live, non-flushing trace. The ASM state
  also checks for an async abort after `lj_asm_trace()` and before
  `trace_stop()`, so a flush request that lands during assembly routes through
  abort cleanup instead of publishing trace links and bytecode for an aborted
  trace.
- The x64/POSIX unwound-trace error code is stored in the current TG instead
  of shared `J->exitcode`.
- `lj_dispatch_update()` still rewrites the global dispatch template, but a
  mode transition now requests `HS_REDISPATCH` when more than one TG is live,
  so already-attached TG dispatch tables refresh through their own safepoint
  ack instead of being copied remotely.
- x64 VM entry paths now load `DISPATCH` from the running `L->tg_hint` plus
  `offsetof(TGState, dispatch)`, and `TGPOLL` checks the current TG's `poll`
  word. VM slow paths no longer derive `global_State *` or `jit_State *` with
  fixed offsets from `DISPATCH`; they load `g` from `TGState.gl` and `J` from
  `g->jitp`.
- x64 emitter fixed TG fields now use symbolic `DISPATCH_TG(...)` addressing
  for `jit_base`, `cur_L`, `tmptv`, and `gl` instead of recorder-TG pointer
  subtraction. Generic `dispofs()` has been removed from the x64 emitter; far
  non-MOV memory operands save a scratch GPR instead of clobbering
  `RID_DISPATCH`. `REF_NIL` GG-state FLOADs now use absolute/RIP/global-address
  forms, and the x64 exit patcher recognizes the resulting vmstate store
  patterns instead of scanning for `GG_OFS_TGDISP`.
- Removed the dead transitional `GG_OFS_TGDISP`/`GG_G2TGDISP` and
  `TG_DISP2G`/`TG_DISP2J` header macros after x64 stopped deriving `g` or `J`
  from the running dispatch table. The M6 dispatch guard now rejects their
  return in `lj_dispatch.h`.
- x64 `BC_JLOOP` no longer sends secondary TGs to the static original bytecode
  entry. With localized `DISPATCH`, secondary TGs enter trace mcode through
  their own TG dispatch table and save `jit_base`/temporary state in that table.
- Completed §8.2 dispatch localization for the current x64 bridge:
  `lj_dispatch_update()` keeps the global dispatch template non-recording,
  synchronizes the active TG from that template, and overlays record hooks only
  on the recorder-token holder's TG table.
- x64 trace loop backedges now emit explicit guarded `IR_XPOLL`, polling the
  current TG's `poll` word and exiting through the LOOP snapshot when a
  safepoint is pending. The VM trace exit path already calls
  `lj_safepoint_ack_check()`, so `HS_STOPREQ` and `HS_FLUSHJ` actions are
  observed without a special trace-exit kind.
- x64/GC64 recorder paths now also emit guarded `IR_XPOLL` at inlined Lua
  function entries once `framedepth >= 8`. The guard snapshots immediately at
  the callee entry, matching the profiler guard pattern and covering deep
  call-heavy traces that may run long between loop backedges.
- Safepoint-triggered trace exits skip hot-side recording until the pending
  poll is acknowledged, so a trace poll cannot try to acquire the recorder
  token before the VM safepoint path runs.
- This implements the LOOP-backedge and inlined-FUNCF-depth parts of the
  original §8.6 `XPOLL` requirement for the x64/GC64 path. The XBAR/TGMARK
  alias invalidation model remains as follow-up work.
- Trace write barriers are no longer CSE'd across `IR_XPOLL`. A safepoint can
  enable the GC2 `mark_active` mirror, so x64 `TBAR` and `OBAR` lowering now
  gate their GC2 barrier helper calls on `DISPATCH_TG(mark_active)` while
  preserving the existing legacy black/white repair checks. The long x64
  `TBAR`/`OBAR` helper sequences are split with internal `checkmclim()` calls
  so assert/paranoia builds do not trip the assembler red-zone guard.
- Existing FFI/raw-memory `IR_XBAR` alias limits now also honor `IR_XPOLL` as
  a poll-region boundary for `XLOAD` forwarding/CSE and `XSTORE` DSE. This is
  deliberately limited to the current XBAR surface and does not enable broad
  heap-store barrier tracing yet.
- The helper-backed table-store slice extends the same conservative poll
  boundary to `ASTORE`/`HSTORE` DSE, so stores on opposite sides of `IR_XPOLL`
  are not treated as redundant while the poll can enable GC2 barriers.
- Upvalue/cell and field optimizations now use the same poll/XBAR alias limit:
  `ULOAD`/`FLOAD` forwarding and `USTORE`/`FSTORE` DSE do not cross
  `IR_XPOLL` or `IR_XBAR`. This deliberately keeps a trace poll as a hard
  GC-barrier/handshake boundary for shared cells and field stores, even when a
  narrower optimization might be valid in single-threaded stock LuaJIT.
- Helper-backed indexed table stores can now trace on Linux/x64 through
  release-store helpers. x64 lowers `ASTORE` through
  `lj_tab_storetv_forjit_array()`, hash-slot `HSTORE` through
  `lj_tab_storetv_forjit_hash()`, and numeric `NEWREF` stores through
  `lj_tab_storetv_forjit_newref()` so a returned array slot is not treated as a
  `Node.val`. The helpers release-publish the value and run the GC2
  parent-aware value barrier instead of emitting raw TValue stores. The hash
  helper recovers `Node.key` from the resolved value slot and both hash/array
  helpers call the P_WEAK weak-write bridge, so existing weak table stores can
  trace too. This covers shared hash/array updates as well as PHI/upvalue/escaped
  table references after the slot has already been resolved, previous-nil
  in-bounds array slots, existing hash slots whose value is nil, non-numeric new
  hash keys through `NEWREF`, and fresh numeric insertions that `NEWREF` may
  place in the array part.
- The helper-backed store bridge now resolves a forwarded destination slot
  before publishing when the helper can prove the slot belongs to the parent's
  current array or hash generation. Array helpers route through
  `TabArrayHdr.next_gen`; hash helpers recover the old key, route through
  `TabNodeHdr.next_gen`, and keep weak-write barrier key context coherent.
- Helper-backed array/hash stores now CAS-publish after that routing step and
  retry if the destination becomes `LJ_TFORWARD` between route and publish. This
  prevents traced shared `ASTORE`/`HSTORE` helper calls from erasing a migration
  sentinel in that window. Numeric `NEWREF` stores now pass the original key
  pointer to their helper, so a late `LJ_TFORWARD` on the returned slot can
  re-resolve through `lj_tab_set()` against the table's current generation before
  retrying the CAS publish.
- Linux/x64 numeric `ASTORE` into a separated current array now has an inline
  single-slot CAS fast path before the helper. The fast path uses the `AREF`
  array pointer for the observed generation, rejects colocated arrays, retiring
  array headers, and parent-array mismatches, then release-publishes with
  `lock cmpxchg`; any CAS or generation check failure falls through to
  `lj_tab_storetv_forjit_array_nogc()`.
- Linux/x64 numeric `HSTORE` into an existing current hash slot now has the
  same style of inline single-slot CAS fast path before the helper. The fast
  path rejects tables with metatables, weak-table marks, retiring hash headers,
  and slots outside the current node vector, then release-publishes with
  `lock cmpxchg`; any CAS or generation check failure falls through to
  `lj_tab_storetv_forjit_hash()`.
- x64 numeric `NEWREF` helper calls now materialize their source value and
  original key in distinct TG temp slots (`tmptv` and `tmptv2`). This fixes
  traced `t[#t+1] = tostring(k)` appends where the key TValue could overwrite
  the source TValue before `lj_tab_storetv_forjit_newref()` ran.
- Recorder table-allocation bumping now snapshots the runtime/template array
  generation before comparing or cleaning array bounds. `TNEW`/`TDUP` bytecode
  patch decisions, TDUP template array cleanup, and TSETM pre-growth no longer
  read only the legacy `GCtab.asize` mirror while the interim array-header
  generation bridge is active.
- Constant-key hash lookups on Linux/x64 no longer record a legacy
  `GCtab.hmask` mirror equality guard before `HREFK`. The recorder loads the
  current node pointer and x64 `HREFK` guards its constant slot against that
  node header before reading the key, so the slot-bounds guard is paired with
  the same node generation used by the lookup. This is still only the HREFK
  node-header part of the original FLOAD header-indirection target; array header
  pairing and broad table-write tracing remain pending.
- x64 empty-hash misses no longer use the recorder's legacy
  `TAB_HMASK == 0` shortcut. They fall through to regular `IR_HREF`, so the
  generated lookup takes the mask from `TabNodeHdr` even for empty hash
  generations. Non-x64 keeps the old shortcut while those backends remain out of
  scope.
- The local-cell recording part of the original M6 target is now covered by an
  M6-level guard. The existing x64 recorder handles raw local-cell slots as SSA
  slots and promoted cells as `IR_UREFC` plus `IR_ULOAD`/`IR_USTORE`, with
  `IR_OBAR` for GC-valued stores. The first `BC_CNEW`/`BC_FNEW` slice records
  self-captured local-function creation through explicit-base helpers: `CNEW`
  writes the runtime stack cell and returns a fresh cell ref for immediate
  CGET/CSET use, while `FNEW` builds the closure from the current trace `BASE`.
- Follow-up: Linux/x64 GC-valued `IR_USTORE` into `IR_UREFC` now release-copies
  through `lj_func_storeuv_forjit()` before the `IR_OBAR` publication call, and
  the XPOLL guard checks this helper-before-`lj_gc_pubuv` mcode ordering.
  Source and loaded v4 self-cell creation loops can now trace. Mixed FNEW
  shapes with raw immutable captures now sync the traced value into `BASE`
  before the helper call. Mutable captures now trace both after promotion at
  trace entry and when the hot trace performs the first raw-slot promotion,
  provided unrelated loop-carried slots are type-stable.
- The root-trace pending-promotion lookahead now skips pre-promoting a mutable
  local-cell slot when an earlier destination bytecode in the same loop body
  overwrites that slot before `FNEW`. The `FNEW` recorder still syncs the
  current traced value into `BASE` and lets `lj_func_newL_gc_forjit()` promote
  the real captured value, but avoids creating a discarded cell before patterns
  like `local x = i; local function f() ... end`.

- Added the first allocator accounting bridge toward §8.6 allocation pacing:
  allocation growth accumulates in `TG.local_total` and flushes into
  `GC2State.alloc_since_trigger` at 32 KiB, safepoint ack, and TG detach.
  GC2/legacy mark begin flushes TG-local totals and resets the trigger counter

M6 token-owned JIT flush:
- Full and scoped trace flush mutation now runs under the same non-reentrant
  recorder token that protects trace publication. A caller that already owns
  the token reuses it; other callers abort any active recorder, wait through
  the normal native sleep path, and release only tokens they acquired.
- Public full `jit.flush()` still uses the `HS_EXIT_TRACES|HS_FLUSHJ`
  safepoint boundary before the leader clears trace slots and frees mcode.
  Numeric scoped flushes and function/prototype JIT mode changes acquire the
  token around bytecode unpatching, proto trace-chain updates, dependency
  marking, the scoped `HS_EXIT_TRACES` boundary, and post-boundary slot
  retirement.
- `tests/t-jit-token.c` now covers this behavior at runtime: it keeps the old
  impossible-owner recording-skip check separate from public mode calls, then
  uses a helper pthread to release a foreign token after `jit.flush()` and
  `jit.flush(1)` have already attempted to enter, proving the public flushes
  wait for token ownership and leave the token free afterward.
- Follow-up STOPREQ slice: recorder-token wait now checks for a fresh
  `LJ_GC2_HS_STOPREQ` after each native sleep and raises the normal VM-shutdown
  error before claiming the token. Full `jit.flush()` also acquires the recorder
  token before entering the `HS_EXIT_TRACES|HS_FLUSHJ` handshake, so the
  handshake leader never blocks on a token wait while a STOPREQ publisher is
  waiting for the leader word. `tests/t-jit-token.c` covers `jit.flush()`,
  `jit.flush(1)`, and `jit.opt.start()` with a helper pthread that publishes
  STOPREQ while the caller is parked on a foreign token.

M6 GC2 stock-pacing compatibility:
- Lowered `LJ_GC2_TRIGGER_MIN` from a 256 MiB floor to 256 KiB. The old floor

M6 active-MT recorder table boundary:
- Removed the coarse `mt_active && n_threads > 1` trace-start refusal from
  `lj_trace_hot()`, hot side-exit recording, stitching, and `lj_trace_ins()`.
  The recorder token once again permits secondary TGs to record/re-enter
  non-table traces.
- Moved the temporary MT fence down to table-specific recorder operations.
  After `mt_active` is latched, `next()` traversal recording and
  metatable-bearing non-trace-local indexed table stores raise NYI and stay on
  the interpreter path. Same-trace store/load forwarding, non-trace-local raw
  indexed table reads and writes, trace-local table operations, and
  `TNEW`/`TDUP` allocation recording remain enabled; single-threaded stock JIT
  table recording is unchanged.
- This keeps generated mcode from carrying old shared array/hash generation
  pointers across later worker waves, while preserving the M6 recorder-token
  guarantee for numeric, non-table, and fresh table-allocation code.
- Non-trace-local shared table reads now trace under active MT through
  `lj_tab_gettv_forjit()`. The recorder snapshots the current raw result for
  type prediction, preserves stock `__index` handling when the raw value is nil,
  then emits a side-effecting helper call that copies the linearized lookup
  result into a TG temp `TValue` and `VLOAD`s it with the predicted type guard.
  The helper retries if the selected slot turns into `LJ_TFORWARD` between
  lookup and copy, so traced reads do not dereference retired array/hash
  generations.
- Non-trace-local raw shared table writes now trace under active MT through the
  existing helper-backed `ASTORE`/`HSTORE` bridge. The recorder acquire-copies
  the observed old value before making previous-nil/type decisions, while
  preserving the `niltvg` pointer identity used to distinguish an absent key
  from an existing nil slot. Metatable-bearing shared stores remain fenced
  because `__newindex` dispatch still depends on inline raw-value guards; those
  need the same helper-snapshot treatment before this edge can trace safely.
