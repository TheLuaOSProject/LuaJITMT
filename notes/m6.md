M6 JIT recorder token scaffold:
- Added the first §8.2 recorder token bridge as `global_State.jit_token`.
  `lj_jit_token_try()` CAS-acquires the token with the current TG tid and never
  waits; hot root traces, hot side traces, and stitch attempts skip recording if
  another TG owns the token.
- Any TG with a nonzero tid may now try the recorder token. The earlier
  x64/POSIX main-TG validation guard was removed after the emitter stopped
  using recorder-TG-relative `RID_DISPATCH` addressing.
- `lj_dispatch_ins()` and `lj_dispatch_call()` now only feed record-mode
  callbacks into `J` when the current TG owns the token. This remains the
  C-side backstop for recorder state mutation.
- Recording dispatch is now TG-local: `lj_dispatch_update()` keeps the global
  dispatch template in the non-recording mode, syncs the current TG from that
  template, and overlays `lj_vm_record`/callhook only when the current TG holds
  the recorder token. Non-owner TGs no longer receive record hooks through the
  global template.
- The x64 hot-loop path passes the current `lua_State *` to `lj_trace_hot()`
  and no longer writes `J->L` in assembly before the token CAS. The C helper
  publishes `J->L` only after acquiring the recorder token.
- The x64 stitch path also passes `lua_State *` and the invoking trace number
  into C. `lj_trace_stitch()` publishes `J->L` and `J->exitno` only after it
  acquires the recorder token.
- The token is released when the trace state machine returns to
  `LJ_TRACE_IDLE`, including successful assembly, abort/error, and start-time
  refusal paths.
- Hot side-exit counters still advance before the threshold, but once a side
  exit is hot enough to record, token-busy exits leave the retry budget and
  `SNAPCOUNT_DONE` sentinel untouched.
- The x64/POSIX trace-exit path passes `L`, the exited trace number, and
  snapshot number into `lj_trace_exit()`, and snapshot restore carries those as
  call-local values. These fields are published to shared `J` only after a hot
  side exit acquires the recorder token.
- The x64/POSIX unwound-trace error code is stored in the current TG instead
  of shared `J->exitcode`.
- `lj_dispatch_update()` still rewrites the global dispatch template, but a
  mode transition now requests `HS_REDISPATCH` when more than one TG is live,
  so already-attached TG dispatch tables refresh through their own safepoint
  ack instead of being copied remotely.
- x64 VM entry paths now load `DISPATCH` from the running `L->tg_hint` plus
  `offsetof(TGState, dispatch)`, and `TGPOLL` checks the current TG's `poll`
  word. VM slow paths no longer derive `global_State *` or `jit_State *` with
  fixed offsets from `DISPATCH`; they load `g` from `TGState.gl` and `J` from
  `g->jitp`.
- x64 emitter fixed TG fields now use symbolic `DISPATCH_TG(...)` addressing
  for `jit_base`, `cur_L`, `tmptv`, and `gl` instead of recorder-TG pointer
  subtraction. Generic `dispofs()` has been removed from the x64 emitter; far
  non-MOV memory operands save a scratch GPR instead of clobbering
  `RID_DISPATCH`. `REF_NIL` GG-state FLOADs now use absolute/RIP/global-address
  forms, and the x64 exit patcher recognizes the resulting vmstate store
  patterns instead of scanning for `GG_OFS_TGDISP`.
- x64 `BC_JLOOP` no longer sends secondary TGs to the static original bytecode
  entry. With localized `DISPATCH`, secondary TGs enter trace mcode through
  their own TG dispatch table and save `jit_base`/temporary state in that table.
- Completed §8.2 dispatch localization for the current x64 bridge:
  `lj_dispatch_update()` keeps the global dispatch template non-recording,
  synchronizes the active TG from that template, and overlays record hooks only
  on the recorder-token holder's TG table.
- x64 trace loop backedges now emit explicit guarded `IR_XPOLL`, polling the
  current TG's `poll` word and exiting through the LOOP snapshot when a
  safepoint is pending. The VM trace exit path already calls
  `lj_safepoint_ack_check()`, so `HS_STOPREQ` and `HS_FLUSHJ` actions are
  observed without a special trace-exit kind.
- x64/GC64 recorder paths now also emit guarded `IR_XPOLL` at inlined Lua
  function entries once `framedepth >= 8`. The guard snapshots immediately at
  the callee entry, matching the profiler guard pattern and covering deep
  call-heavy traces that may run long between loop backedges.
- Safepoint-triggered trace exits skip hot-side recording until the pending
  poll is acknowledged, so a trace poll cannot try to acquire the recorder
  token before the VM safepoint path runs.
- This implements the LOOP-backedge and inlined-FUNCF-depth parts of the
  original §8.6 `XPOLL` requirement for the x64/GC64 path. The XBAR/TGMARK
  alias invalidation model remains as follow-up work.
- Trace write barriers are no longer CSE'd across `IR_XPOLL`. A safepoint can
  enable the GC2 `mark_active` mirror, so x64 `TBAR` and `OBAR` lowering now
  gate their GC2 barrier helper calls on `DISPATCH_TG(mark_active)` while
  preserving the existing legacy black/white repair checks. The long x64
  `TBAR`/`OBAR` helper sequences are split with internal `checkmclim()` calls
  so assert/paranoia builds do not trip the assembler red-zone guard.
- Existing FFI/raw-memory `IR_XBAR` alias limits now also honor `IR_XPOLL` as
  a poll-region boundary for `XLOAD` forwarding/CSE and `XSTORE` DSE. This is
  deliberately limited to the current XBAR surface and does not enable broad
  heap-store barrier tracing yet.
- Broad indexed table stores remain untraced until the full XBAR/TGMARK
  generation-aware table-write protocol lands. `tools/ci/m5_jit_hash_store_nyi.sh`
  still guards shared existing-table update loops. The first M6 bridge only
  records stores to non-nil slots of trace-local `TNEW`/`TDUP` tables; x64 lowers
  those `ASTORE`/`HSTORE` IRs through `lj_tab_storetv_forjit()`, which
  release-publishes the value and runs the GC2 value barrier instead of emitting
  raw TValue stores. New-key/nil-slot stores and shared table stores stay NYI.
- Constant-key hash lookups on Linux/x64 no longer record a legacy
  `GCtab.hmask` mirror equality guard before `HREFK`. The recorder loads the
  current node pointer and x64 `HREFK` guards its constant slot against that
  node header before reading the key, so the slot-bounds guard is paired with
  the same node generation used by the lookup. This is still only the HREFK
  node-header part of the original FLOAD header-indirection target; array header
  pairing and broad table-write tracing remain pending.
- The local-cell recording part of the original M6 target is now covered by an
  M6-level guard. The existing x64 recorder handles raw local-cell slots as SSA
  slots and promoted cells as `IR_UREFC` plus `IR_ULOAD`/`IR_USTORE`, with
  `IR_OBAR` for GC-valued stores. The first `BC_CNEW`/`BC_FNEW` slice records
  self-captured local-function creation through explicit-base helpers: `CNEW`
  writes the runtime stack cell and returns a fresh cell ref for immediate
  CGET/CSET use, while `FNEW` builds the closure from the current trace `BASE`.
  Source and loaded v4 self-cell creation loops can now trace. Mixed FNEW
  shapes with raw immutable captures now sync the traced value into `BASE`
  before the helper call. Mutable captures now trace both after promotion at
  trace entry and when the hot trace performs the first raw-slot promotion,
  provided unrelated loop-carried slots are type-stable.
- Added `tests/t-jit-token.c`, `tests/t-jit-secondary.lua`, and
  `tools/ci/m6_jit_token.sh` to verify a secondary TG can acquire/release the
  token, a spawned secondary TG can record and re-enter x64 traces, a fake busy
  token prevents new traces without blocking, and recording resumes after
  release.
- Added `tools/ci/m6_jit_cell_ops.sh` to require CGET/CSET recorder markers,
  x64 direct-cell `IR_UREFC` lowering, CNEW/FNEW helper markers, IR dumps for
  owner numeric cells, GC-valued cell stores, loaded v4 CGET/CSET traces, and
  source/loaded self-cell CNEW/FNEW creation traces, source/loaded mixed
  raw-local sync-helper FNEW traces, promoted-cell pre/post FNEW update loops,
  and source/loaded first-promotion FNEW traces.
- Added `tools/ci/m6_jit_barrier_xpoll.sh` to guard the post-XPOLL `TBAR` and
  `OBAR` barrier shape and the x64 `mark_active` gating.
- Added `tools/ci/m6_jit_xbar_xpoll.sh` to guard the FFI/raw-memory
  XBAR/XPOLL alias boundary and keep shared indexed table stores NYI.
- Added `tools/ci/m6_jit_table_store_helper.sh` to guard the trace-local
  helper-backed `TDUP`/`TNEW` table-store bridge, including positive
  `HSTORE`/`ASTORE` IR dumps and negative shared/new-key store cases.
- Added `tools/ci/m6_jit_hrefk_nodehdr.sh` to guard that Linux/x64 HREFK
  traces use the loaded node pointer without a `tab.hmask` mirror guard and
  still exit/recover correctly after a hash resize.
- Added `tools/ci/m6_jit_href_nodehdr.sh` to guard the regular dynamic
  string-key `IR_HREF` lowering: x64 loads `GCtab.node` first and masks against
  the loaded node header instead of using the legacy `GCtab.hmask` mirror.
- Added the x64 shared-array AREF pair-stability bridge. For shared table array
  reads, `rec_idx_key()` records the array pointer before the bounds load, emits
  the `TAB_ASIZE` bounds guard, then emits a second fresh `TAB_ARRAY` FLOAD and
  guards it equal to the first pointer before `AREF`/`ALOAD`. Trace-local
  `TNEW`/`TDUP` tables skip the extra guard. This closes the current
  old-array/new-asize replacement window without claiming the full `AHdr`
  FLOAD-indirection target is done.
- Added `tools/ci/m6_jit_aref_pair_guard.sh` to require the shared-array IR
  shape, an `XPOLL` in the loop trace, and a grow-after-trace smoke case.
- Added `tools/ci/m6_jit.sh` as the current M6 aggregate for x64 dispatch
  redispatch, recorder-token, CGET/CSET recording, XPOLL-barrier,
  XBAR/XPOLL alias, trace-local table-store helper, shared AREF pair guard,
  HREF/HREFK node-header guards, allocator-accounting, GC-step, and
  mcode-publication guardrails.
- Added the first allocator accounting bridge toward §8.6 allocation pacing:
  allocation growth accumulates in `TG.local_total` and flushes into
  `GC2State.alloc_since_trigger` at 32 KiB, safepoint ack, and TG detach.
  GC2/legacy mark begin flushes TG-local totals and resets the trigger counter
  for the new cycle. `GC2State.trigger_bytes`, `hard_bytes`, `gcpause_pct`, and
  `assist_shift` are initialized and updated from `lua_gc` pause/stepmul
  controls. When flushed bytes pass `trigger_bytes` while GC2 is idle, the
  bridge requests a cycle by lowering the legacy `gc.threshold`, while still
  honoring `collectgarbage("stop")`. That request now claims a nonblocking
  `GC2State.cycle_leader` token, publishes `cycle_requests` telemetry, and is
  consumed at mark begin through `cycle_starts`; the legacy threshold lowering
  remains the current cycle-driver bridge. The first bounded-assist bridge now
  has `lj_gc2_account_alloc()` call `lj_gc2_assist()` past `hard_bytes` during GC2
  MARK/WEAK. Assists use `TGState.gc_assist` to prevent reentry, a nonblocking
  assist-owner token for the current global grey deque owner side, bounded
  active/published SSB conversion, and at most `1 << assist_shift` grey-object
  traversals. During `P_WEAK`, the same assist token now spends any remaining
  bounded work budget on `lj_gc2_weak_drain()`, advancing the weak clear cursor
  without adding locks and attributing the cleared weak tables through
  `assist_weak_drained`. The current `lj_gc_step_jit` / `IR_GCSTEP` pacing path
  remains guarded until independent concurrent cycle leadership, worker
  ownership, and trace allocation checks fully replace legacy pacing.
- The existing `lj_gc_step_jit` trace-side GC check now also runs
  `lj_gc2_assist()` before legacy stepping. This is a staged bridge only: the
  original §8 allocation-pacing target remains to remove `IR_GCSTEP` once
  allocator-side trace checks and concurrent cycle leadership replace it.
- x86-64 `asm_gc_check` now calls the same helper when either the legacy GC
  threshold is reached or the GC2 hard allocation threshold is exceeded.
  `lj_gc_step_jit` only performs legacy `lj_gc_step()` work for the legacy
  threshold case; a GC2-hard-only check runs bounded GC2 assist work without
  adding extra legacy collector steps.
- Added `GC2State.jit_hard_checks` telemetry and
  `tests/t-gc2-jit-hard-check.c` so the readiness guard verifies a real
  x86-64 allocation trace enters `lj_gc_step_jit` through the GC2 hard-limit
  path while the legacy threshold is disabled.
- Split the enlarged x86-64 GC-check lowering with an internal `checkmclim()`
  guard, and split the final trace-head GC check after snapshot preparation,
  plus between the GC2-hard and legacy threshold tests, so assert/paranoia
  builds do not overrun the assembler red zone.
- Added `tools/ci/m6_jit_alloc_account.sh` and `tests/t-gc2-alloc-account.c`
  for the allocation accounting bridge.
- Added `tools/ci/m6_jit_gc2_readiness.sh` as the companion guard for the
  allocation-pacing transition: it requires the GC2 trigger/assist bridge and
  still requires allocation traces to emit `GCSTEP` until a real trace-side
  replacement lands.
- `GC2State.marks_this_round` progress accounting now uses atomic reset/add
  operations and atomic test reads, so concurrent assists/workers do not race
  the fixpoint progress counter while the full worker protocol is staged.
- GC2 SSB and grey-work telemetry counters now initialize and test through the
  same atomic helpers used by their runtime increments, keeping the scaffold
  counters race-clean for concurrent assist/worker tests.
- GC2 bounded assists now publish atomic telemetry for assist runs, SSB entries
  converted into grey work, and grey objects traced, giving follow-up pacing
  tests direct counters instead of inferring assist work from mark side effects.
- Added `tools/ci/m6_jit_gcstep_guard.sh` to keep the current
  `lj_gc_step_jit`/`IR_GCSTEP` pacing path guarded until independent GC2
  trace pacing, cycle leadership, and worker ownership fully replace it.
- GC2 now has a bounded `lj_gc2_worker_drain()` steal-side traversal surface
  with worker telemetry and pthread traversal coverage. This advances the
  worker-ownership prerequisite for removing legacy trace GC pacing, but does
  not yet install the full worker scheduler or fixpoint loop.
- GC2 also has bounded `lj_gc2_fixpoint_round()`/`lj_gc2_fixpoint_run()`
  leader surfaces that perform root-rescan/drain rounds, publish fixpoint
  telemetry, and now run from the legacy atomic bridge before weak clearing.
  GC2 now also exposes the legacy `P_WEAK` bridge before `gc_clearweak()`.
  New weak keys/values inserted during `P_WEAK` are marked by GC2 weak-write
  barriers, with first-time key/value mark telemetry. x64 VM single-value
  array stores now use a direct TValue GC2 barrier so weak-value array writes
  mark the new value, and x64 `TSETM` batch constructor stores now range-mark
  copied values through `lj_gc2_barrier_tvn_g()` before the table barrier.
  This advances the cycle-leadership prerequisite, while the full scheduler
  loop and independent weak processing remain staged.
- Added the first §8.5 mcode publication bridge for Linux/x64: VM
  initialization now records whether private expedited sync-core membarrier
  registration succeeded, and `trace_stop()` calls `lj_mcode_sync_core()` after
  committing mcode RX but before `trace_save()` publishes the final trace slot
  and before bytecode/exittab/link release stores are enabled. Dual mapping and
  removal of the legacy `mcode_protect` W^X state machine remain follow-up
  work.
- Added the write-view metadata scaffold for the original §8.5 memfd dual-map
  target. `MCLink` now carries an `rw` alias and the mcode area
  registration/free path goes through RX/RW translation helpers, so the
  allocator and emitters can keep published addresses in RX space while using a
  writable alias for stores.
- x64 exit-stub and per-trace exit-row generation now keep their cursors in the
  published RX address space while writing bytes through `lj_mcode_rw()`. This
  converts the first emitter surface to the dual-map write-view convention
  without changing generated addresses under the current single-map bridge.
- x64 bottom-of-area 64-bit constant pools now also write through the same
  `lj_mcode_rw()` helpers while preserving their RX-relative offsets.
- x64 trace-tail fixups now use the same write-view helpers for stack-adjust
  bytes, direct/indirect exit branches, and NOP tail fill while keeping `mcp`
  and `mctop` as RX cursors. This removes another late fixup surface from the
  future memfd dual-map cutover.
- The x64 main emitter now has `asm_mcode_put_*()` helpers for RX-addressed
  stores and routes the core opcode, ModRM/SIB, immediate, branch, and selected
  generation-time fixup writes through them. `as->mcp`, labels, and `mctop`
  stay in RX coordinates for relative-address math; only the write address is
  translated to the RW view.
- x64 committed-code exit patching now uses `asm_mcode_patch_i32()` for the
  parent-exit and exit-branch rel32 updates in `lj_asm_patchexit()`. The
  function still decodes and computes displacements against RX addresses and
  keeps the existing `lj_mcode_patch()` protection/sync protocol, but the
  actual stores go through the current area's RW view.
- Linux/x64 secure mcode allocation now uses the original §8.5 memfd dual-map
  write view: each area is mapped once RX and once RW from the same memfd,
  `MCLink` metadata is initialized through the RW header, unwind metadata is
  written through RW while registered at RX addresses, and teardown unmaps both
  aliases. The conservative fresh-area bridge remains until M9 cleanup/perf,
  but it no longer relies on RW/RX flips for correctness.
- Added `tools/ci/m6_jit_mcode_publish.sh` and wired it into
  `tools/ci/m6_jit.sh` to guard the sync-core registration and publication
  ordering.
- Follow-up bridge update: traced FINREG stress exposed the other half of
  §8.5's warning. Reusing the active mcode area with RW/RX page flips can
  fault peer TGs already executing traces from the same area. Current bridge
  state: Linux/x64 secure builds keep W^X with the memfd dual-map write view
  and still allocate a fresh unpublished mcode area once the current area
  contains committed trace bytes. The M6 mcode guard now requires dual-map
  markers, the fresh-area marker, reserve-time `maxmcode` accounting, no
  `LJ_MT`/threadsafe build gate, and
  `tests/t-jit-mcode-fresh.lua`'s concurrent publish/execute stress so
  whole-area W^X flipping or secure-mode RWX is not silently reintroduced.
- Fresh-area stress also exposed that final JIT teardown must not allocate SMR
  retirement records after `lj_gc_freeall()` has already freed the GC object
  graph and possibly the last recorder state. Normal trace flushes still use
  `lj_mcode_free()` plus epoch-delayed retirement. `lj_trace_freestate()` now
  uses `lj_mcode_freeall()` to deregister/free active and already-retired mcode
  immediately during final close teardown, after the close path has disabled
  JIT entry and left no published trace executors.
- Recorder-internal full-flush recovery now routes trace-table exhaustion and
  mcode-allocation failure through `lj_trace_flushall_hs()`, preserving the
  `HS_EXIT_TRACES|HS_FLUSHJ` boundary before the leader clears trace slots.
- Added `tools/ci/m6_jit_flush_hs.sh` and wired it into `tools/ci/m6_jit.sh`
  to guard internal full-flush handshake routing.
- Tightened scoped JIT flush publication without changing the full-flush
  `HS_FLUSHJ` protocol. Previous bridge state: public function/proto/trace
  flush modes always published `HS_EXIT_TRACES` after their scoped unpatch pass.
  Current bridge: scoped trace flush helpers report trace-exit publication work,
  proto disabling counts as boundary work even without existing traces, and
  `luaJIT_setmode()` publishes one `HS_EXIT_TRACES` boundary only for nonzero
  work. `tests/t-vm-safepoint.c` now checks full flush still advances the
  handshake epoch, scoped no-op flushes do not, proto disabling does, and
  flushing a real root clears its trace slot after the boundary. Repeated flushes
  of that trace number are no-ops because the scoped slot-retirement bridge has
  already removed the published slot.
- Scoped trace flushes now also mark dependent traces before the
  `HS_EXIT_TRACES` boundary. The original bridge retired side traces whose root
  was directly flushed; after CNEW no-JIT gates were relaxed, the stock
  `jit_flush.lua` path exposed cross-root links where a side trace rooted
  elsewhere still tail-jumped into the flushed trace. The current bridge walks
  trace links and side-trace immediate parents to closure, resets affected
  exit tables, and retires explicitly marked side slots after the boundary.
- Tightened the scoped-flush body-retirement bridge without adding direct GC-list
  unlinking. Previous bridge state: scoped slot retirement stamped a finite
  post-`HS_EXIT_TRACES` epoch, but later legacy sweep overwrote that epoch when
  it eventually moved the physical `GCtrace` body/exittab onto
  `J->retiredtraces`. Current bridge: `trace_retire()` preserves a finite
  scoped epoch and only replaces `0` or the pre-handshake
  `LJ_TRACE_SCOPE_FLUSHING` sentinel. The physical body still reaches
  `J->retiredtraces` through sweep; full per-root body ownership remains a
  follow-up.
- Extended `tests/t-vm-safepoint.c` and `tools/ci/m3_vm_safepoint.sh` with a
  trace-loop `HS_STOPREQ` publisher test; without the trace-loop poll the test
  would stay in compiled loop code until the script timeout.
