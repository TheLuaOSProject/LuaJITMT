M6 JIT recorder token scaffold:
- Added the first §8.2 recorder token bridge as `global_State.jit_token`.
  `lj_jit_token_try()` CAS-acquires the token with the current TG tid and never
  waits; hot root traces, hot side traces, and stitch attempts skip recording if
  another TG owns the token.
- Any TG with a nonzero tid may now try the recorder token. The earlier
  x64/POSIX main-TG validation guard was removed after the emitter stopped
  using recorder-TG-relative `RID_DISPATCH` addressing.
- `lj_dispatch_ins()` and `lj_dispatch_call()` now only feed record-mode
  callbacks into `J` when the current TG owns the token. This remains the
  C-side backstop for recorder state mutation.
- Recording dispatch is now TG-local: `lj_dispatch_update()` keeps the global
  dispatch template in the non-recording mode, syncs the current TG from that
  template, and overlays `lj_vm_record`/callhook only when the current TG holds
  the recorder token. Non-owner TGs no longer receive record hooks through the
  global template.
- The x64 hot-loop path passes the current `lua_State *` to `lj_trace_hot()`
  and no longer writes `J->L` in assembly before the token CAS. The C helper
  publishes `J->L` only after acquiring the recorder token.
- The x64 stitch path also passes `lua_State *` and the invoking trace number
  into C. `lj_trace_stitch()` publishes `J->L` and `J->exitno` only after it
  acquires the recorder token.
- The token is released when the trace state machine returns to
  `LJ_TRACE_IDLE`, including successful assembly, abort/error, and start-time
  refusal paths.
- Hot side-exit counters still advance before the threshold, but once a side
  exit is hot enough to record, token-busy exits leave the retry budget and
  `SNAPCOUNT_DONE` sentinel untouched.
- The x64/POSIX trace-exit path passes `L`, the exited trace number, and
  snapshot number into `lj_trace_exit()`, and snapshot restore carries those as
  call-local values. These fields are published to shared `J` only after a hot
  side exit acquires the recorder token.
- The x64/POSIX unwound-trace error code is stored in the current TG instead
  of shared `J->exitcode`.
- `lj_dispatch_update()` still rewrites the global dispatch template, but a
  mode transition now requests `HS_REDISPATCH` when more than one TG is live,
  so already-attached TG dispatch tables refresh through their own safepoint
  ack instead of being copied remotely.
- x64 VM entry paths now load `DISPATCH` from the running `L->tg_hint` plus
  `offsetof(TGState, dispatch)`, and `TGPOLL` checks the current TG's `poll`
  word. VM slow paths no longer derive `global_State *` or `jit_State *` with
  fixed offsets from `DISPATCH`; they load `g` from `TGState.gl` and `J` from
  `g->jitp`.
- x64 emitter fixed TG fields now use symbolic `DISPATCH_TG(...)` addressing
  for `jit_base`, `cur_L`, `tmptv`, and `gl` instead of recorder-TG pointer
  subtraction. Generic `dispofs()` has been removed from the x64 emitter; far
  non-MOV memory operands save a scratch GPR instead of clobbering
  `RID_DISPATCH`. `REF_NIL` GG-state FLOADs now use absolute/RIP/global-address
  forms, and the x64 exit patcher recognizes the resulting vmstate store
  patterns instead of scanning for `GG_OFS_TGDISP`.
- x64 `BC_JLOOP` no longer sends secondary TGs to the static original bytecode
  entry. With localized `DISPATCH`, secondary TGs enter trace mcode through
  their own TG dispatch table and save `jit_base`/temporary state in that table.
- Completed §8.2 dispatch localization for the current x64 bridge:
  `lj_dispatch_update()` keeps the global dispatch template non-recording,
  synchronizes the active TG from that template, and overlays record hooks only
  on the recorder-token holder's TG table.
- x64 trace loop backedges now emit explicit guarded `IR_XPOLL`, polling the
  current TG's `poll` word and exiting through the LOOP snapshot when a
  safepoint is pending. The VM trace exit path already calls
  `lj_safepoint_ack_check()`, so `HS_STOPREQ` and `HS_FLUSHJ` actions are
  observed without a special trace-exit kind.
- x64/GC64 recorder paths now also emit guarded `IR_XPOLL` at inlined Lua
  function entries once `framedepth >= 8`. The guard snapshots immediately at
  the callee entry, matching the profiler guard pattern and covering deep
  call-heavy traces that may run long between loop backedges.
- Safepoint-triggered trace exits skip hot-side recording until the pending
  poll is acknowledged, so a trace poll cannot try to acquire the recorder
  token before the VM safepoint path runs.
- This implements the LOOP-backedge and inlined-FUNCF-depth parts of the
  original §8.6 `XPOLL` requirement for the x64/GC64 path. The XBAR/TGMARK
  alias invalidation model remains as follow-up work.
- Trace write barriers are no longer CSE'd across `IR_XPOLL`. A safepoint can
  enable the GC2 `mark_active` mirror, so x64 `TBAR` and `OBAR` lowering now
  gate their GC2 barrier helper calls on `DISPATCH_TG(mark_active)` while
  preserving the existing legacy black/white repair checks.
- Existing FFI/raw-memory `IR_XBAR` alias limits now also honor `IR_XPOLL` as
  a poll-region boundary for `XLOAD` forwarding/CSE and `XSTORE` DSE. This is
  deliberately limited to the current XBAR surface and does not enable broad
  heap-store barrier tracing yet.
- Indexed table stores remain untraced until the full XBAR/TGMARK table-write
  protocol lands; `tools/ci/m5_jit_hash_store_nyi.sh` still guards the current
  `ASTORE`/`HSTORE` safety boundary.
- Added `tests/t-jit-token.c`, `tests/t-jit-secondary.lua`, and
  `tools/ci/m6_jit_token.sh` to verify a secondary TG can acquire/release the
  token, a spawned secondary TG can record and re-enter x64 traces, a fake busy
  token prevents new traces without blocking, and recording resumes after
  release.
- Added `tools/ci/m6_jit_barrier_xpoll.sh` to guard the post-XPOLL `TBAR` and
  `OBAR` barrier shape and the x64 `mark_active` gating.
- Added `tools/ci/m6_jit_xbar_xpoll.sh` to guard the FFI/raw-memory
  XBAR/XPOLL alias boundary and keep indexed table stores NYI.
- Added `tools/ci/m6_jit.sh` as the current M6 aggregate for x64 dispatch
  redispatch, recorder-token, XPOLL-barrier, XBAR/XPOLL alias,
  allocator-accounting, GC-step, and mcode-publication guardrails.
- Added the first allocator accounting bridge toward §8.6 allocation pacing:
  allocation growth accumulates in `TG.local_total` and flushes into
  `GC2State.alloc_since_trigger` at 32 KiB, safepoint ack, and TG detach.
  GC2/legacy mark begin flushes TG-local totals and resets the trigger counter
  for the new cycle. `GC2State.trigger_bytes`, `hard_bytes`, `gcpause_pct`, and
  `assist_shift` are initialized and updated from `lua_gc` pause/stepmul
  controls. When flushed bytes pass `trigger_bytes` while GC2 is idle, the
  bridge requests a cycle by lowering the legacy `gc.threshold`, while still
  honoring `collectgarbage("stop")`. The first bounded-assist bridge now has
  `lj_gc2_account_alloc()` call `lj_gc2_assist()` past `hard_bytes` during GC2
  MARK/WEAK. Assists use `TGState.gc_assist` to prevent reentry, a nonblocking
  assist-owner token for the current global grey deque owner side, bounded
  active/published SSB conversion, and at most `1 << assist_shift` grey-object
  traversals. The current `lj_gc_step_jit` / `IR_GCSTEP` pacing path remains
  guarded until independent concurrent cycle leadership, worker ownership, and
  trace allocation checks fully replace legacy pacing.
- Added `tools/ci/m6_jit_alloc_account.sh` and `tests/t-gc2-alloc-account.c`
  for the allocation accounting bridge.
- Added `tools/ci/m6_jit_gcstep_guard.sh` to keep the current
  `lj_gc_step_jit`/`IR_GCSTEP` pacing path guarded until allocator-side
  assists exist.
- Added the first §8.5 mcode publication bridge for Linux/x64: VM
  initialization now records whether private expedited sync-core membarrier
  registration succeeded, and `trace_stop()` calls `lj_mcode_sync_core()` after
  committing mcode RX but before `trace_save()` publishes the final trace slot
  and before bytecode/exittab/link release stores are enabled. Dual mapping and
  removal of the legacy `mcode_protect` W^X state machine remain follow-up
  work.
- Added `tools/ci/m6_jit_mcode_publish.sh` and wired it into
  `tools/ci/m6_jit.sh` to guard the sync-core registration and publication
  ordering.
- Recorder-internal full-flush recovery now routes trace-table exhaustion and
  mcode-allocation failure through `lj_trace_flushall_hs()`, preserving the
  `HS_EXIT_TRACES|HS_FLUSHJ` boundary before the leader clears trace slots.
- Added `tools/ci/m6_jit_flush_hs.sh` and wired it into `tools/ci/m6_jit.sh`
  to guard internal full-flush handshake routing.
- Extended `tests/t-vm-safepoint.c` and `tools/ci/m3_vm_safepoint.sh` with a
  trace-loop `HS_STOPREQ` publisher test; without the trace-loop poll the test
  would stay in compiled loop code until the script timeout.
