# b1.2.0 arena bump-priority fix

## Problem

`lj_arena_alloc()` continued searching owner-local free-run bins while its
private bump window could satisfy the request.  If it selected a large binned
run, allocated a small prefix, and already had a usable bump, it republished the
shrinking suffix with `arena_insert_run()`.  That calls
`arena_set_free_run()`, which validates and clears the whole suffix, followed by
another interior-range clear.  Repeating this for each allocation makes the
work quadratic in the cells of a reclaimed run.

In a forced-unsunk traced table loop (`x = {i, i+1, i+2}`), the pushed
`7d09a64c` baseline spent about 75% below `arena_insert_run()` and its two
full-suffix scrub paths.  Pinned CPU 8, 200,000 allocations took a median
0.438 seconds versus about 0.00434 seconds for system LuaJIT.

## Change and ownership proof

When the active bump can fit `ncells`, allocation now goes directly to the
existing `bump_alloc` path.  Bins are consulted after the bounded private
window is exhausted.  This matches the bump-first design in the allocator
plan without changing any allocation publication LP.

- `TGAlloc.bump`, the bin heads, and `binmask` have one structural owner.
- The active bump interval is owner-private and absent from every bin.
- Sweep preparation records and detaches the private interval at the owner
  safepoint before changing arena ownership state.
- Reclaimed arenas are rebuilt privately and only become allocator-visible
  after adoption.
- Remote producers can free allocated starts, but cannot target a never-used
  bump cell: it has no allocation-start bit and its traversable lifetime is
  `FREE`.
- The existing allocation path still performs extent preflight, lifetime/root
  construction claims, allocation-start publication, header/READY publication,
  and exact rollback on a veto.
- A too-small bump tail is still published before searching bins.  Therefore a
  bin cannot be lost.  Ordinary owner allocation revisits bins after the
  current sub-64-KiB private interval is exhausted; a sweep may replace that
  interval and defer the address of one particular reusable run without
  losing the run or growing memory without bound.

Lua exposes neither allocation address order nor immediate reuse order.  Tests
that intended to verify a particular freed-run protocol now explicitly exhaust
their independent private bump before asserting exact address reuse.  Separate
assertions verify that a usable bump advances contiguously while the binned run
remains published.

## Results

Pinned CPU 8, seven-run medians for 200,000 forced-unsunk nonempty table
allocations:

- pushed baseline: 0.437644 seconds;
- bump-first: 0.090156 seconds;
- system LuaJIT: 0.004338 seconds.

This is a 4.85x improvement over the fork baseline.  Stopped-GC measurements
were effectively unchanged (0.0208 versus 0.0214 seconds), which is expected:
the pathological suffix-reinsert branch is created by reclaimed/binned runs.
An escaping 64-table ring improved from 0.265 to 0.189 seconds with active GC.

Post-fix LBR profiling at 500,000 allocations found:

- direct synchronous GC2 stepping: 74.2% inclusive;
- rooted table construction: 24.9% inclusive;
- generic arena allocation: 17.1% inclusive;
- `arena_set_free_run`: 2.7% self;
- `arena_clear_extent_range`: 7.4% self;
- no reportable `arena_insert_run` or `arena_find_run` samples.

The quadratic allocator cliff is removed, but the diagnostic remains about
20.8x slower than system LuaJIT.  Synchronous collector cadence is now the
dominant blocker; this change alone does not satisfy the b1.2 performance gate.

## Validation

- `m2_arena_all`: pass.
- `m6_jit_gcstep_pacing`: pass.
- clean production and debug-symbol builds: pass.
- `m3_gc2_scaffold` stopped at the pre-existing
  `t-gc2-traverse.c:1632` assertion on both the unchanged base and this patch.
- `m6_jit_alloc_account` stopped at the pre-existing interpreter hard-check
  fixture assertion on both the unchanged base and this patch.

The exact four-file implementation diff was independently developed and
benchmarked in an isolated worktree, then applied atop the pushed
terminal-unlink commit.  Independent review also removed the now-unreachable
old `bump_ready` suffix-reinsert branch.  White-box exact-reuse fixtures use
their established direct cursor-exhaustion idiom; this intentionally abandons
only fixture-local unpublished tails and is not a production transition.
