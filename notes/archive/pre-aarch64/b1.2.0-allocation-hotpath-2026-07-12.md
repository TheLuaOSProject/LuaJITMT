# b1.2.0 allocation hot-path profile and IDLE publication fast return

## Scope and profile result

This pass profiled the remaining Linux/x86-64 `closures_upval` and
`tab_insert_newkey` outliers from checkpoint `a77da662`. Pinned
`BENCH_SCALE=.05` runs measured closure churn at roughly 405--414 ns/op and
unique string-key insertion at roughly 760--805 ns/op; the system LuaJIT
measured about 39 and 69 ns/op respectively.

The closure gap is primarily GC2 ownership work, not closure body
initialization. With automatic collection stopped, 250,000 one-upvalue
closures cost about 111 ns/op. A one-million-operation active run started
about 291 major cycles, moved about 1.995 million closure/upvalue headers from
pending ownership chains, and swept about 2,033 arenas. Native profiles were
led by exact unmarked-object classification, queued-object validation, arena
extent clearing/free-run rebuilding, and root-link validation.

Unique-key insertion costs about 400 ns/op with automatic collection stopped.
Its remaining native profile is spread across dynamic string construction and
interning, generic arena lifetime admission, table/string resize, and repeated
marking of the growing live table and string set. There was no narrow table
insertion change with a material, repeatable win in this pass.

## Retained change

Two already-defined incremental-IDLE no-op cases now return at their outermost
publication boundary:

- FNEW operand preservation samples phase and generational mode once and skips
  three out-of-line root-barrier calls in non-generational IDLE.
- Generic TValue root publication skips the TValue acquire copy/tag test and
  GC2 TValue barrier in the same non-generational IDLE state.

The deeper barriers already performed no mark, rescue, or remembered-set work
under exactly these predicates. This does not remove an edge or weaken object
lifetime admission. If a cycle starts after the acquire observation, the
value's already-published source or the caller's publication precedes mutator
acknowledgement; the activation root scan covers it. MARK, WEAK, SWEEP, and
generational IDLE retain the complete existing barrier paths.

On the same pinned CPU immediately before and after rebuilding, active closure
churn moved from 412.8--414.4 ns/op to 403.5--405.5 ns/op (about 2.2--2.6%).
GC-stopped closure construction moved from 110.6--113.0 ns/op to
97.9--100.8 ns/op (about 10--12%). Unique-key results remained noisy and
essentially unchanged; this change is not presented as a table-cliff fix.

## Rejected experiments and remaining work

- Raising the tiny-heap trigger floor reduced closure churn to about 379 ns/op
  by cutting a one-million-operation run from roughly 291 to 244 major cycles.
  It was rejected because the focused x64 JIT readiness fixture no longer
  reached its required hard-assist cadence. No pacing constant or test was
  changed.
- A sole-mutator string bump constructor removed generic per-object extent
  validation while retaining lifetime, mark, READY, block, and accounting
  publication. Its roughly 1--3% noisy unique-key improvement did not justify
  adding another specialized constructor and was removed.
- Larger pending-root trigger caps had already shown nonlinear ownership-chain
  costs and were again not viable. String-table active-pin/CAS removal remains
  rejected by the earlier full-GC regression evidence.

A substantial closure improvement now requires reducing the number or cost of
exact ownership entries, rather than skipping validation. A substantial
unique-key improvement requires a bounded way to avoid repeatedly tracing an
ever-growing live string/table set without allowing unbounded pending-root
batches. Both remain structural performance work after this narrow fast return.

Focused verification passed `m6_jit_fnew_bump`, `m5_gc2_pacing_atomic`,
`m3_gc_root_pending`, `m3_gc_root_pending_race`, `m2_arena_gcsweep`, and GC2
recovery in normal and assertion/paranoia profiles. The
`m6_jit_gc2_readiness` TNEW hard-cadence failure reproduced after completely
reverting this delta in the isolated worktree and is therefore independent of
the retained change.
