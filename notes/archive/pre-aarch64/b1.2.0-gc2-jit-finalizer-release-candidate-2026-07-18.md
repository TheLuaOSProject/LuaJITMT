# b1.2.0 GC2/JIT finalizer release-candidate evidence (2026-07-18)

The plan files are unchanged. This note records the final Linux x86_64
correctness and performance-sanity tranche for the narrowed functionality-beta
gate. The core Linux implementation checkpoint is `16aa5cac`; the Windows
release-preflight TLS correction is `0fe693bf`. Documentation-only evidence
commits follow those implementation checkpoints.

## Beta gate used here

`b1.2.0` is a beta, not a claim that the implementation is bug-free. It is
allowed to contain ordinary beta defects and performance debt. Its hard gate is
no known breaking bug in ordinary Linux x86_64 GC2/JIT operation: no
reproducible crash, memory corruption, use-after-free, double-free, deadlock,
unbounded runtime loop, or unusable ordinary GC2/JIT path. A representative
regression is performance debt unless it approaches the accepted catastrophic
scale of roughly 100x, times out, or runs away in CPU or memory use.

This does not claim completion of the full project. Fully nonblocking generic
FFI/VM paths, removal of every peer-dependent wait, performance parity, custom
`lua_Alloc`, physical minor collection, the `atomic` library, and exhaustive
macOS/Windows correctness remain b1.2.1 work.

## Release-blocking failures found and corrected

### Process-wide finalizer hook versus peer JIT control

The larger JIT/GC2-worker stress found `bad action while in __gc metamethod`
when one TG called `jit.flush()` while a different TG owned a finalizer. GC2's
`HOOK_GC` bit is process-wide, but LuaJIT's no-JIT-action rule describes the TG
currently executing the callback.

`lj_gc2_finalizer_owned_by_current()` now distinguishes those cases. Same-owner
`jit.off`, `jit.on`, and flush operations retain the stock error. A peer uses
the normal `EXIT_TRACES|FLUSHJ` safepoint handshake and suppresses only the
TRACE VM event while the global hook exclusion is active. The raw,
non-handshaked `lj_trace_flushall()` path deliberately keeps its conservative
process-wide veto; peer relaxation exists only on the handshaked path.

`t-jit-flush-peer-finalizer.lua` forms a real trace, parks a peer finalizer,
performs engine control and full flush from the other TG, verifies that the
trace set is empty, and separately proves same-owner rejection.

### Finalizer-to-peer full-collection join deadlock

A deterministic reducer exposed this dependency cycle:

1. TG A entered a finalizer and joined an already-existing TG B.
2. TG B called `collectgarbage("collect")`.
3. B waited for `finalizer_active` to clear while A waited for B to exit.

Explicit full collection now defers whenever any finalizer is active, including
a recheck inside the phase-driving loop. The already-open outer SWEEP, bounded
mutator steps, or GC workers continue after the callback releases its retained
body scope. `t-gc2-finalizer-peer-collect.lua` reproduces the exact join graph
with JIT both off and on and verifies eventual return to IDLE.

This is an accepted beta semantic boundary: a racing explicit full collection
may return as a deferral rather than a synchronous completion boundary, and no
separate pending-full-GC bit is published. Ordinary callbacks run inside an
outer SWEEP which resumes afterward. A durable pending-full-GC request is a
b1.2.1 strengthening, not a liveness prerequisite for this beta.

### Synthetic sidecar shutdown abort

The complete M8 run initially aborted after the sidecar-publication fixture.
Optimized DWARF attributed a shared cold `abort()` to `lj_gc2_worker_stop()`,
but instruction-boundary inspection showed worker shutdown returned success.
The actual failure was `lj_threading_live_retry_tgs_terminal()` correctly
rejecting a synthetic non-null live node whose fake `LJThread` had no TG,
state, join, or lifecycle.

The fixture now tombstones that synthetic root before `lua_close`, matching the
state ordinary threading shutdown publishes. Close still owns and frees both
raw node lists. No runtime invariant was weakened.

### JIT constant-fold signed overflow

UBSan found inherited C undefined behavior when loop reassociation folded
`INT32_MAX + 1` in `kfold_intop()`. ADD, SUB, MUL, and BSHL now operate in the
unsigned domain and cast the modulo-2^32 result back to `int32_t`. The exact
stock reducer is `tests/stock/test/lang/compare.lua`, case 8. This changes no
runtime hot path.

### MinGW GC2 ownership markers were process-global

The pre-tag Windows UCRT cross-build exposed GCC warnings that five GC2
reclaimer/SMR ownership markers ignored `__declspec(thread)`. COFF inspection
confirmed that MinGW GCC 14 had placed them in ordinary `.bss`. In a real
multi-threaded process, one thread could therefore mistake another thread's
nested SMR read or reclaimer/gate ownership for its own and allow premature
reclamation.

Non-MSVC Windows builds now use GCC/Clang `__thread`; MSVC retains
`__declspec(thread)`. A build-time COFF gate checks all five actual object
symbols, rejects ordinary or mixed storage, accepts only one consistent native
TLS or GCC emutls backend, and requires `__emutls_get_address` for the latter.
The gate is part of both Windows platform CI and release artifact construction.
The release smoke now performs a real `threading.spawn`, full GC in the worker,
and timed join before the existing FFI/loadlib checks. The staged and extracted
Windows UCRT binaries pass that smoke under Wine.

This is a correctness-first beta repair, not the final lockless Windows
backend. MinGW GCC emutls may allocate and synchronize on first access. Moving
these fields into the already-admitted process-lifetime Windows thread cell is
b1.2.1 work; the ordinary GC/JIT hot paths must not retain emutls as the final
nonblocking design.

## Fixture-only oracle and isolation corrections

These four commits correct test accounting, isolation, or build scoping. They
do not weaken a runtime safety invariant and are not presented as runtime bug
fixes.

### Retained meta-store accounting (`7ed86c63`)

The direct meta-store fixture still expected telemetry from before retained
table lookup added conservative publication routes. Exact debugging showed the
missing-key operation filters four old edges and pushes one remembered owner;
the existing-key operation brings the cumulative totals to nine filtered and
three pushed edges. The assertions and route comments now match those safe,
additional publications.

### Frozen-SMR entry probe isolation (`011a855e`)

The JIT idle-reclaim fixture deliberately froze the exclusive metadata SMR
writer, then attempted retained global/table/FFI metadata lookups which
correctly waited for that same writer. It now preloads stack-rooted inputs before
the pause and uses closed numeric and scalar generic probes while the gate is
frozen; the instrumented FFI/vmstate probe remains before and after the pause.
This removes the fixture's self-deadlock while retaining JFUNCF, JLOOP, ISNEXT,
ITERN, and generic JITERL invalidation/recovery coverage.

The complete `m6_jit` aggregate passed at `011a855e`, including the peer
finalizer/flush reducers, combined JIT/GC2 worker stress, idle reclaim entry,
native STOPREQ, environment/upvalue flush, and mcode/trace retirement cases.

### Certified huge-sweep stale oracle (`17c24180`)

The stable-preadmission recovery fixture expected operation-local retry state
from before the huge-table writer gained a certified fresh-reader path. The
writer now safely observes late MARK+PENDING, reanchors the live object, and
retires its ticket; local result/pending telemetry is therefore `1/0` while the
durable recovery item remains pending and vetoes reclamation. The refreshed
oracle also checks the retained root, cleared ticket, zero readers, and exact
flags. Focused M3 recovery and GC2-paranoia reruns pass.

### Helper-only grey-steal gate (`16aa5cac`)

The synthetic grey-deque steal race calls helper-only publication and steal
entry points. Its context, helper threads, publication routine, and invocation
are now compiled only with `LJ_GC2_TEST_HELPERS`, leaving production/paranoia
fixture builds to exercise the ordinary worker-drain paths without unresolved
test-helper references.

## GC2-only runtime proof

The operational audit found no target runtime path to classic LuaJIT
mark/sweep. Allocation checks, `lua_gc` collect/step, GC workers, JIT GC IR,
and shutdown are GC2-only. Build-host `src/host/minilua.c` retains its private
bootstrap collector and is not linked into the target.

`gc2_no_retired_symbols.sh` now rejects the retired full/step/atomic/mark/sweep
entry points in both source and artifacts. Its comment/string-aware token scan
also rejects target writes to compatibility-only `g->gc.state` unless they
assign exactly `GCSpause`. Ordinary and amalgamation
`m3_gc2_no_legacy_runtime` runs pass, including IDLE and active-SWEEP
`lua_close()`.

## Stress and sanitizer evidence

The combined stress runs trace recording, execution, side exits, scoped and
full flush, short-lived TG churn, weak tables, closures, strings, tables and
userdata finalizers while background GC2 workers drive repeated cycles. Its
default 4-mutator/128-round/256-short-lived-TG/2-GC-worker gate passed ten
consecutive runs. An enlarged 8/256/512/4 run also passed after exposing the
peer-hook defect above.

Clang ASan (`detect_leaks=0`, fail-fast) passed the two new reducers, combined
worker stress, finalizer-spawn coverage, 509 stock JIT tests, and 387 stock
interpreter tests. Clang UBSan, excluding the already documented alignment,
function, pointer-overflow, and shift categories, passed the same 509/387 stock
corpora after the wrapping-fold correction. Focused M3/M6/M8 concurrency gates
also passed under both sanitizers.

The complete M8 weak/finalizer matrix passes in normal and
assertion/GC2-paranoia builds. Focused checkpoint reruns of the peer JIT flush,
combined JIT/GC2-worker stress, peer full collection, and ordinary/amalgamation
no-legacy gate pass.

Focused M3 recovery and GC2-paranoia runs pass at the refreshed huge-sweep
oracle. The complete `m3_gc2_scaffold` aggregate then passed uninterrupted at
`16aa5cac`: helper and release-like paranoia profiles, GC2 recovery, background
workers, active roots, native and VM safepoints, JIT-off/JIT-on cases, ordinary
and amalgamated builds, the M2 arena cases, both strict M0 builds, and 2,179
stock-test executions. The runner restored the default build afterward.

The aggregate runner records dependency metadata but does not expand it. The
six M3 targets absent from the aggregate body were therefore run explicitly at
the same checkpoint. Pending-root publication, the pending-root activation
race, runtime GC2 activation, ordinary and amalgamated no-legacy-runtime
proofs, ordinary and `LUAJIT_USE_SYSMALLOC` internal-allocator-only proofs, and
native VM-event STOPREQ/stdio recovery all passed. The final target reused and
left a successful default build.

## Performance sanity, not parity

The pinned stock comparator is upstream commit
`b925b3e3fc6771171602323b45fbe9fb8fc90369`. A three-sample, CPU-pinned
representative comparison at scale 0.2 passed the beta's 100x ceiling. The
largest slow rows were `tab_insert_newkey` at 9.45x and `closures_upval` at
8.39x; `fib30` was 1.42x, `tab_hash_write` 1.57x, `alloc_tables` 1.11x, and
`ffi_struct` 1.06x. Other selected rows were at parity or faster in this run.

Three 4-mutator `gc_churn-MT` runs with two background GC2 workers completed
with checksum 4000 at 37.50, 41.87, and 42.00 seconds (213k, 191k, and 190k
ops/s). Every run reported a major cycle, three major-root scans, thousands of
worker runs, and nonzero asynchronous progress. This is considerably slower
than the long-term target but neither a timeout nor a roughly 100x regression;
it is accepted b1.2.1 optimization debt.

## CI and remaining accepted boundaries

GitHub CI for `17c24180`, the later `16aa5cac` helper-only fixture gate, and the
Windows TLS correction at `0fe693bf` is green on Linux, macOS, and Windows UCRT.
The beta's hard correctness gate remains Linux x86_64, but those builds provide
additional ABI/build and native Windows thread/GC smoke evidence.

Accepted release boundaries remain:

- arbitrary custom `lua_Alloc` callbacks are ABI-visible but intentionally
  ignored in favor of the internal arena allocator, as detailed in
  `lua-alloc-temporarily-disabled-2026-07-10.md`;
- generational requests fall back to complete major cycles because physical
  minor sweep/root elision remains disabled;
- traced active-MT shared cdata access retains conservative interpretation in
  cases without a complete ownership proof;
- the exact deterministic pause between traced CNEW allocation and snapshot
  restoration remains an evidence gap, not a known failing path;
- generic FFI call-shape cleanup, the `atomic` Lua library, deep platform
  validation, and performance parity are b1.2.1 work.
- MinGW's temporary emulated TLS isolates the GC2 ownership fields correctly
  but is not accepted as the final lockless Windows implementation; the
  admitted-cell backend and a deterministic two-thread field-overlap fixture
  remain b1.2.1 work.

The one observed M6 FIFO STOPREQ harness schedule with an unmatched blocking
writer is recorded separately under `notes/complaints/`; its exact focused
target and the full M6 aggregate passed on retry, and the captured stacks did
not show a GC2/JIT dependency cycle.
