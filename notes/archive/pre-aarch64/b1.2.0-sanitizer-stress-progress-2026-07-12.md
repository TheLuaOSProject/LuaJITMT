# b1.2.0 Linux sanitizer and stress progress (2026-07-12)

This is a release-gate progress record, not a declaration that the b1.2.0 gate
has passed. The current b1.2.0 scope is Linux x86_64 with GC2 and the JIT
basically operational, ordinary FFI use intact, no known lifecycle hang or
corruption, and no major representative performance cliff. Exhaustive
nonblocking-path/platform work remains scheduled for b1.2.1.

## Clang ASAN

The target-only ASAN build used Clang with `-O1 -g`, frame pointers and
`-fsanitize=address` on target compile/link/shared-link flags. Runtime checks
used `detect_leaks=0`, `halt_on_error=1` and `abort_on_error=1`; leak detection
is separately unsuitable for GC2's retained arenas and process-lifetime
registries.

Passing coverage on checkpoint `57d36165` included:

- 509 stock tests with the JIT and 387 stock tests with `-joff`;
- 1,000 sequential spawn/join cycles and 300 join/GC scan cycles;
- secondary-TG JIT recording, explicit exits, util flush, threaded flush and
  VM-event coverage;
- ordinary FFI cdata allocation/get/set, JIT CNEW, FINREG and GC-trace cases;
- sanitizer-linked native GC2, threading and FFI fixtures.

ASAN also made two release blockers deterministic:

1. The synchronous shutdown STOPREQ broadcast left its synthetic one-shot edge
   armed on the initiating main TG. It interrupted the children correctly, but
   later escaped as an unprotected error from `lua_close()`. The main closer now
   consumes only its own completed shutdown edge and preserves any unrelated
   counted request. The canonical shutdown suite and 25 consecutive direct
   shutdown runs pass with the fix.
2. Fresh cdata construction aborted when an exclusive reclaimer held the SMR
   admission gate. The allocation was valid `CONSTRUCT + LINKING + READY`; the
   failure came from trying to rediscover an allocator-owned base through a
   transient global SMR reader and mutable CType metadata. The replacement
   protocol carries allocator-issued base identity through fresh publication.
   Fixed objects use their object address, while interior cdata supplies its
   true allocation base. This is being integrated with the GC2 hot-path
   performance tranche. JIT-on and JIT-off 6-thread/24,000-iteration cdata
   hammers pass in the candidate tree, including repeated runs.

## Clang UBSAN

Alignment-enabled probing found two ordinary C abstract-machine issues which
do not need to remain undefined:

- the `jit_init` unaligned hardware probe now copies four bytes with `memcpy`,
  preserving the target load without a misaligned typed dereference;
- parser fixed-name and break sentinels are stored and loaded as direct GCRef
  pointer bits, rather than forming member addresses through fake GC objects.

The x64 instruction and callback emitters intentionally patch unaligned encoded
fields. The broad UBSAN gate therefore excluded `alignment` for those emitters,
plus the stock-intent `function`, `pointer-overflow` and `shift` categories:

```
make -C src clean
make -C src -j2 CC=clang CCDEBUG=-g \
  TARGET_CFLAGS='-O1 -fno-omit-frame-pointer -fsanitize=undefined -fno-sanitize=alignment,function,pointer-overflow,shift' \
  TARGET_LDFLAGS='-fsanitize=undefined' \
  TARGET_SHLDFLAGS='-fsanitize=undefined'
```

With `UBSAN_OPTIONS=halt_on_error=1:abort_on_error=1:print_stacktrace=1`, the
same 509 JIT and 387 interpreter stock tests plus the representative
threading/JIT/FFI/native fixture set passed. The only abort after deliberately
removing the local constructor workaround was the known fresh-constructor race,
with no UBSAN diagnostic.

## Additional focused stress

The checkpoint or candidate fixes have also passed no-drop recovery in default
and assertion/paranoia builds, the deterministic pending-root activation race,
channel MPMC stress, 1,000 sequential spawn/join cycles, trace publication and
retirement, threaded JIT flush, recursive-call/retention workloads, recorder
token coverage, FFI cdata allocation and clib-cache stress, and repeated shared
cdata hammers. The performance gate and final post-integration sanitizer/stress
rerun are still open.
