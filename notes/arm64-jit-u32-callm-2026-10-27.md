# ARM64 U32 CALLM composition

This increment follows the U32 numeric-return and renamed-snapshot work in
`arm64-jit-u32-results-2026-10-27.md`. The intended extension is a native U32
producer used as the last argument of an adjacent Lua CALLM consumer, including
fixed `double`/`float` arguments and promoted variadic tails.

## Production proof

Both independent graph walks retain the certified U32-to-NUM result as the
completed producer, with Lua type NUM, only after the existing native-leave
protocol succeeds. The raw U32 result remains restricted to its exact conversion
and cannot appear in a snapshot. The existing BC_CALL B=0 producer, adjacent
BC_CALLM, argument-count and final-argument checks then bind the consumer to
that Lua number. Fixed float arguments use the already-validated NUM-to-FLOAT
conversion; variadic number arguments remain doubles.

The ABI operand classifier recognizes the exact NUM-from-U32 conversion only
when its source is an earlier CALLXS with exactly U32 type. Its flags may contain
only the existing NUM type and ISPHI bit. The semantic and allocated walks still
independently prove the active native call, unsigned four-byte ABI result,
conversion, source/result snapshots and lifetime. No emitter, shared runtime,
recorder, lock, or x64 production change is included.

Fixed CALLM consumers now also run each walk's existing argument source-frame
proof. The native CARG already matched the completed producer, but a cloned
fixed-double consumer's XSAVE could previously substitute another valid NUM in
the saved Lua argument slot and still pass semantic admission. The focused
mutation reproduced that acceptance (`mutation=18`) in
`/tmp/ljmt-u32-callm-source-red.log`. Applying the source proof to CALLM binds
both fixed and variadic saved arguments to their native carriers, including
NUM-to-FLOAT conversion. The two proofs remain independent.

## Validation

The runtime fixture extends the existing U32 cases with four CALLM shapes:
fixed double, fixed float, variadic double/int/double tail, and the same tail
after nine fixed integer arguments. The ninth fixed argument overflows the
GPR bank onto the stack. All shapes exercise ten zero, signed-boundary,
unsigned-boundary and high-bit patterns. Native finish observations distinguish
producer and consumer function addresses. Forced POSTCALL exits target each
call separately; exact helper counts check that completed native effects are
not replayed. Existing errno and frame/root/pin cleanup checks remain active.

A separate authentic-trace fixture checks semantic and allocated admission
independently, including malformed producer/consumer relationships, converted
operands, source snapshots and promoted-tail markers. It is registered in the
focused U32 contract and M7 scalar CALLXS suite.

## Remaining scope

This is a bounded extension of the experimental ARM64 JIT. U32 enum results,
general 64-bit arithmetic, aggregate/sret results, arbitrary trace shapes and
full sustained multithreading parity remain outside this increment. The full
lockless AArch64 port is not complete.

A higher-value next investigation is a shared table's callable CData read
composed with CALLXS in the same loop (`registry[key](i)`). Current native-call
fixtures cache callable CData before the loop. The bounded read certificate
would need its own hit-try helper graph, success guard, post-effect snapshot and
typed CData VLOAD, distinct from the mutable cdata base `__call` lookup.
Both admission passes must bind that exact CData through pointer loading,
XSAVE's callable slot and native-frame publication.

The actual order is table read/VLOAD, `__call` lookup overwriting `tmptv`,
XSAVE, then native entry. Investigate the full lifetime handoff through the
rooted read's `lj_gc_pubroot`, active JIT phase protection, restored exit frames
and final native-frame root; a live register/spill is not a GC root. Require
peer replacement/GC, pre-call no-effect exits and post-call no-replay evidence
before opening this composition. Mutable global-environment reads need their
own root proof and remain separate. This candidate is not implemented or
validated by the present increment.
