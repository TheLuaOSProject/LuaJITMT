Public multiworker buffer churn protocol

Binary: frozen GCC static executable d092d949bbbae32eed53f05e1ee679be33dd30c96cc62ade7bb64e6302ee88a9, source snapshot used for commit 78f117627. All work uses public Lua threading.spawn, channels, join, gcstats, gcworkers and string.buffer APIs. No runtime source changes or internal allocator probes are part of this package.

Each churn worker creates one buffer and waits on a per-worker command channel. A batch executes 20,000 reset/put/get cycles with a 1 KiB immutable payload and compares every returned string. The worker sends its numeric id to a shared completion channel, then parks waiting for the next command. The main thread receives every distinct completion and checks that every worker is still running before emitting a sample. The external Python controller captures /proc memory and thread counts and then acknowledges the Lua sample over stdin. Thus active-batch samples retain all worker handles and live worker buffers at a defined public API boundary. They do not claim that workers are executing instructions at the exact RSS read.

Ordinary matrix: interpreter/JIT, zero/two GC workers, and one/two/four churn workers. Each process performs eight waves of five batches per worker. Completed thread handles intentionally remain rooted across waves one through four, retaining their returned buffers. Every join result is verified, including one repeated join before the retained handles are explicitly dropped. Waves five through eight drop handles and transient join results after each wave. No full GC is requested during these eight waves; normal automatic GC remains enabled throughout.

Sentinel matrix: interpreter/JIT, zero/two GC workers, and one/four short churn workers. One additional long-lived thread remains parked on a public channel while twelve short-worker waves finish and drop all handles/results. After waves six and twelve, three separately labeled full collections run while the sentinel is still alive. This separates repeated worker exit retention from both deliberately retained results and a trivial lack of GC progress. These full-GC checkpoints supplement the preceding automatic-only wave groups; they are not substituted for automatic operation.

After all waves, the main thread runs five more automatic buffer batches, frees its buffer, and records three labeled full collections. The sentinel (when present) then exits and its handle is dropped. The GC worker pool is stopped, followed by three further labeled full collections. These tail stages distinguish active peer/pool retention from the state after all extra threads have stopped.

Canaries use two waves of two batches of 2,000 cycles: ordinary interpreter with one worker and no GC pool, then sentinel JIT with four workers and two GC workers. Full matrix processes are sequential. Runtime affinity is CPUs 8–15; controller/summary work uses CPU 0. A watchdog kills any process exceeding 512 MiB resident memory or 120 seconds; individual channel/join operations use explicit bounded timeouts.

The measurement reports physical RSS, virtual reservation, Lua logical byte accounting, collector phase and cycle/progress counters. RSS includes allocator/native-thread/runtime caches and cannot by itself identify unreachable or reusable arena capacity. Root's independent exact TG/arena census supplies that attribution. This package demonstrates public spawn/exit/join/handle-drop behavior, not an unjoined-thread destructor stress test, a complete lock-freedom proof, or a universal multiworker heap bound.
