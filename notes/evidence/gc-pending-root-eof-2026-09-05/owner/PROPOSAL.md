# Bounded pending-root EOF work: design only

The current EOF unit has no root-count-independent work bound. A bounded sibling is plausible only as a durable, resumable publication/repair protocol. Replacing the complete flush at SWEEP EOF with a prefix pop is not sound. This package proposes the next design scope, not an implementation approved for promotion.

The exact source base is eb8a5b2f9ce2fd6128f4dbeef25b03896b81cfcd. All source line references name `baseline/` in this package. No production source or shared file was changed. The separately proposed worker bridge is not applied; its call to the same public boundary motivates the investigation but is not needed for the measured main-caller EOF unit.

## The work that must be bounded

`lj_gc_sweep_gc2_unmarked` limits ordinary pruning to 256 visited entries (`src/lj_gc.c:1902`). On encountering EOF, it calls the complete pending flush and root repair (`:2048`). A nonzero flush or pending hint reopens the cursor at the global root head; only an empty result/hint allows root-done=1 and cursor=NULL.

The flush scans every TG plus the main/self fallback owners. It acquires SMR before exchanging either pending slot and retains it through all validation and splice work (`:5221`). For each detached nonempty chain it performs a complete Brent tail/count walk (`:5050`), then a complete head-to-tail containment check against the observed insertion head before the CAS (`:5105`, `:5126`). A successful splice increments the repair epoch. One final repair walk traverses the full global spine (`:975`); the explicit EOF repair normally sees the cached epoch and returns cheaply, but a racing publication can dirty it again. An overlap check is repeated after every insertion CAS failure. Malformed cycles require extra repair and restart walks.

For a healthy disjoint ordinary chain of N nodes inserted before R retained spine nodes with one successful CAS, this includes N tail visits, N containment visits, and N+R repair visits, in addition to the up-to 256 ordinary prune visits. Thus the structural healthy-path cost is at least 3N+R node visits for that shape. With two chains, containment work can repeat for both; the single final repair covers the combined spine. TG directory size, CAS retries and malformed/concurrently changing topology introduce further work. A wall-clock deadline check after these complete walks does not bound an individual unit.

The real oracle measures a single exact pruning invocation, not an entire cycle or allocation loop. It confirms that N=262,144 is processed in that invocation, for ordinary, after-main and mixed chains. A bound on the number of exchanged TGs alone would not change this result. A bounded tail finder that still invokes the old overlap or repair walks would not change the asymptotic unit bound either.

## Why an intrusive prefix cut is unsafe

`lj_gc_linkobj_new_chain` publishes a complete freshly initialized run through one pending CAS, then calls `gc_root_chain_commit_constructed` (`src/lj_gc.c:5366`, `:5386`). That commit loop commits one node, tests whether it is the caller-known original tail, and otherwise loads its next link to locate the next node to commit.

A legal preemption point is after committing the run head to MEMBER/LIVE but before loading its next link. Later nodes can still be LINKING/CONSTRUCT. Cutting that head's next link and redirecting it to the global spine would make the resumed constructor leave its own run. MEMBER proves a lifetime/membership transition; it does not prove that every publisher has finished reading that next link. Splitting at an arbitrary observed MEMBER node therefore has no valid ownership proof. Testing only the next node's LINKING state also cannot establish that the constructor has already consumed the predecessor link.

The existing whole-chain flusher changes only the actual drained tail. For a constructor's run, that is either its own known tail, at which the commit loop stops before following next, or a node beyond that run. Retaining whole-chain topology is the narrowest way to preserve this existing producer contract. Modern C and x64 pending publication both use CAS against the observed pending head; a losing producer rewrites its still-unpublished tail link before retrying. Preserve that contract, pre/post hint publication and the LINKING/CONSTRUCT ownership lanes. Older notes describing a pre-MT release-store fast path are historical; the inspected current source uses CAS.

## Recommended next scope

Design a persistent whole-chain continuation for a new SWEEP-only bounded *entry point*. Keep the complete public flush API and its consumers' behavior, but make complete callers recognize and finish any continuation. Do not split an in-flight constructor run, add a per-object producer allocation, or change C/JIT/VM publication in the first prototype.

A continuation needs at least: an exact source TG identity and ordinary/after-main lane; a durable detached-chain head; stage and progress revision; current validation/cycle-detection cursor and Brent state; eventual true tail and count; insertion anchor/observed head; the repair generation being certified; and whatever exact allocation/TG lifetime ownership makes those saved references valid after yielding. These are requirements, not a finalized struct layout. A raw pointer plus a sampled cycle number is not sufficient incarnation authority.

Conceptual stages are capture, bounded tail validation, bounded overlap validation, splice, bounded global repair, and complete. Every stage must consume a fixed combined node/directory/attempt budget and publish its next continuation state before releasing the existing worker claim. A detached suffix or the only head must never survive that release solely in the collector's C locals. A bounded refusal preserves the exact locator and publishes an explicit pending/deferred outcome. Counts and statistics should increase once for actual publication, not for retries or scan attempts.

For an initial capture performed under the existing claim, a short exchange-to-descriptor store sequence can remain within one nonthrowing unit; it must finish before claim release. This retains the current limitation that a preempted claim owner may block others. It is not a proof of arbitrary-instruction helpability. If the requirement is that another actor may complete even that preempted transfer, a separately proved descriptor publication/CAS protocol is required; two independent head and status stores do not supply it.

The splice should change the true tail only after complete bounded overlap validation of the particular insertion head. A failed insertion CAS invalidates that overlap decision. Limit attempts per unit and retain/restart the comparison durably. Do not fall back to an unbounded traversal on contention. It is not enough for a helper to observe the desired root head: a preempted splicer can have completed the root CAS before recording its stage, while another publisher has already prepended a newer head. Exactly-once completion needs an ownership rule or a helpable publication descriptor that resolves that ambiguity.

Global repair must also become resumable for this path, with a persistent detector and validated incarnation-safe references. Publish `gcroot_repaired_epoch` only after actually completing the required walk for the recorded publication generation; a budget expiration, stale cursor, changed producer generation or failed validation is not a repaired certificate. Root unlink can clear membership and allow address reuse after a claim release. Reopening an ordinary SMR scope later protects registry mapping, but does not by itself establish that a saved raw address is the same object incarnation. Either retain explicit lifetime authority or invalidate/restart the continuation safely before reading it. Keep the existing cycle-repair semantics and permanent main-thread anchor. Do not simply delete repair because recent normal executions are acyclic.

## Complete-flush consumers must participate

The existing API is not a global snapshot barrier against concurrent publishers; it can also return without detaching anything if try-SMR admission fails. Preserve its current empty fast path, hint races, all-visible-TG pass and main/self fallback. The new requirement is that an admitted complete caller must not silently treat a collector continuation as absent merely because the original pending slots are empty. It must finish or correctly account for that durable work before making the same decisions it makes today.

The complete consumer inventory is frozen in `caller-contexts.json` (40 flush/repair callsite contexts across the GC, TG, state, trace and table files). Important contracts include:

- Root/global and owned-NEEDSCAN snapshots need the same object frontier before their semantic scans and completion certificates.
- `gc_unlink_root_obj_mode` claims UNLINKING before flushing, then locates/removes the exact incoming edge. A continuation must not later republish that supposedly removed object.
- Userdata FINREG discovery flushes after-main nodes before unlink/requeue, preventing a second delayed publication of the same object.
- Root-body and arena sweep preservation keep side-vector storage valid without making the ownership spine a semantic live-root set. A body MEMBER bit alone does not preserve every child or table storage generation.
- Retired table-node reclamation (`src/lj_tab.c:3432`) flushes before testing whether storage is still published by a live table. Hiding a table in a collector-only continuation could turn that presence test into a false absence.
- Trace snapshot-PC and stale-instruction resolution flush before ownership-spine searches. A continuation cannot silently remove candidate prototype/trace ownership from those searches.
- TG attach, detach and reclaim, close-state reanchoring, terminal freeall and orphan cleanup rely on the full drain/absence ordering. The orphan path deliberately cannot repair roots after object storage is gone. Every continuation must be discharged or fail-closed before that point.
- Stats/oracle repair callers cannot mark the new continuation's publication generation repaired without covering it.

The public complete wrapper could drive the same continuation to completion, while SWEEP preparation uses its bounded sibling. That preserves call signatures, but it requires a proved common ownership and reentrancy protocol. Existing complete callers are not all serialized by `worker_active`; some already run inside a claim or stronger exclusive reclaimer. Blindly acquiring that token in the complete wrapper can self-deadlock, and letting another caller mutate a live continuation without authority can race the worker. This ownership rule is a still-open design prerequisite, not a solved implementation detail.

## Completion, hints, cancellation and graph preservation

An incomplete TG-directory pass, detached chain, overlap check or repair is durable work independently of `gcroot_pending_hint`. Keep a dedicated pending certificate while any such state exists. Clearing the hint and yielding halfway through a directory pass is unsafe: appending to an already nonempty TG stack need not dirty the hint again. A saved TG cursor also needs registry/lifetime protection across release, and newly attached TGs and main/self fallback owners must remain covered.

Root EOF and READY must require the continuation empty/completed, an actual completed producer-directory pass, no relevant new publication generation/hint, and every existing graph/root/reader/JIT/finalizer gate. Zero nodes published in one unit is not proof of empty work. A repair or flush cursor can advance without an unlink or change to the pruning cursor; the worker's explicit bridge outcome must recognize that actual durable advance under the same claim. An unchanged revision/refused gate must use existing backoff and must not count an attempt or retry wake as progress.

The ownership spine is not the semantic liveness root set. Do not mark all detached objects and their children merely to make a continuation safe. Retain the exact body/side-storage authority required by the old protocol, keep arena/READY closure vetoed while that authority is incomplete, and preserve normal semantic root/barrier tracing. New root scans/full consumers must see the continuation through the complete protocol. Unfinished constructors retain their original LINKING/CONSTRUCT lanes and publisher ownership; helpers must not manufacture MEMBER, clear ownership to NONE, or infer completed construction from a body tag.

A STOP request, worker pool join, phase/cycle abort or caller error cannot discard the chain or reset its continuation fields. Root publication work can outlive the scheduling cycle that discovered it. Transfer it durably to the next eligible caller, or complete it through the existing full-flush contract before terminal teardown. New continuation storage should be preallocated or installed before any detach, so OOM cannot leave the only chain in a local. Every partial stage must have an explicit cancellation/retirement rule. No raw pointer from an old stage may authorize an object or TG after reuse.

## Alternatives and implementation threshold

1. **Budget whole-chain continuation, then repair:** best candidate direction because it preserves current intrusive producer topology. It still needs the shared complete-consumer, lifetime and reentrancy proofs above. This is the recommended next design scope.
2. **Refuse chains longer than B without detaching:** can bound an observation attempt while leaving all roots discoverable, but cannot complete the demonstrated quiet long-chain workload by itself. It would retain the exact unfinished work indefinitely until some complete caller intervenes. It is a fallback safety behavior, not the requested progress repair.
3. **Prefix pop/cut and repush the suffix:** rejected without new producer-unit ownership metadata; the constructed-chain next-link dependency is a concrete blocker. Repushing also needs a safe tail and may reintroduce an unbounded walk or publication ABA.
4. **Producer-published bounded chunks with known tails:** could make bounded transfer natural, but changes C/JIT/VM publication and likely needs chunk metadata and allocation-failure handling. This is a broader redesign and is not the smallest follow-up.

No runtime patch is justified yet. Before implementation, settle the common continuation ownership/reentrancy and incarnation-retention rules, including full callers already holding a GC claim or exclusive registry scope. A claim-boundary continuation can be useful without solving arbitrary preemption helpability, but that limit must remain explicit. No arena rotation, iterator changes or string policy changes belong in this scope.

## Required acceptance oracles for a later implementation

Keep the current long-chain source/results unchanged as the full-flush baseline. A separate bounded fixture generation should require each SWEEP unit to spend at most the declared combined budget, and the union of source stacks, durable continuation and published spine to contain all 262,144 exact identities once at every yield. Preserve ordinary/after-main placement, payloads, fixed live sets and actual completed cycles. It must finish with a quiet producer; an explicit mutator complete flush cannot turn the bounded progress counterexample green.

Add deterministic schedules for: producer paused after first MEMBER commit but before loading the next run node; pending-head publication racing capture; failed insertion CAS and new head; source TG detach/reuse; full flush/reentrant root snapshot/FINREG/table-retired lookup meeting a continuation; reader admission failure; malformed cycles and overlap in both lanes; STOP/join and phase invalidation at each yielded stage; and descriptor-allocation failure before capture. Observe real operations and exact identities. In every negative case, refusal must preserve durable work and block EOF/READY; progress counts must require a stored frontier change. Normal/assertion/ASan validation must remain separate, and timing measurements cannot substitute for these ownership checks.
