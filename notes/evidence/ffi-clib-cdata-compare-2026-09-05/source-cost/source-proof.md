**Source review: a cdata-only comparison for shared CLibrary cache hits**

This review supports evaluating a JIT-only boolean comparison helper for nonnumeric CLibrary entries. It does not approve an implementation or claim a measured improvement. No runtime source was edited and no runtime was built. The existing two-file cache/lifecycle repair remains the correctness baseline. ROOT must review this proof before implementation.

The frozen normal source is `/tmp/lj-clib-cache-root-20260905-i59mqoic/v2/candidate`. All 224 runtime/generator inputs were compared byte-for-byte with commit `aee88db569b82216b705408f00295a337a7393fe`; all match. [reviewed-inputs.json](reviewed-inputs.json) records those hashes, the frozen binary/object hashes, and the existing cost inputs. This review does not concern the separately blocked attachment-during-recording test.

**The measured problem and what source inspection establishes.** ROOT's existing seven alternating pairs on CPU 31 report a candidate shared-lookup median of 251.144 ns. The seven process minima are 250.739, 251.3305, 251.277, 251.6595, 251.0045, 251.0135, and 251.144 ns. Each process keeps a real worker attached, captures the actual namespace builtin, executes an installed native loop, and takes the minimum of five timed passes of two million lookups with GC enabled. The old 0.688 ns median comes from code lacking the new authority/lifecycle checks. It is not a correctness-equivalent performance target. These are isolated lookup costs, not an application benchmark or the cost of an actual foreign call.

The candidate's 39-IR/515-byte root contains two static `hit_try` calls: one before `LOOP`, one in its body. It executes one such call per ordinary loop iteration, not two. The additional [shared-native-shape.json](shared-native-shape.json) / [shared-native-shape.txt](shared-native-shape.txt) probe reproduces that shape using the exact frozen executable. Its count of 80 is for shape evidence only. The later harness trace-2 `NYI: ISLT` abort is preserved and does not invalidate the installed root-1 witness; no timing from this probe is used.

The wrapper in the normal object is 34 bytes and calls a 2,309-byte general implementation. Its dependencies include 385-byte initial owner and 319-byte final owner checks, a 1,316-byte keyed resolver, and out-of-line lifetime admissions/releases. These sizes show the executed route, not percentages of CPU time. [cost-evidence.json](cost-evidence.json) and [inspection-commands.json](inspection-commands.json) retain the data and targeted object disassembly commands.

The ordinary successful path for a registered small table, nonempty string key, and small cdata result includes:

This path has 14 shared atomic read-modify-write operations and three explicit SC fences: three times four RMWs for the leases, plus two for outer SMR. Fence implementation is accounted for separately, not counted again as a shared counter mutation. Retries and lifecycle release edges can add work; nested SMR, Huge objects, the empty string, and custom allocators have different paths. This is a source operation count, not a hardware profile. No per-function percentage or wall-time reduction has been measured. In the stable incremental-IDLE case, GC queue allocation is not a credible explanation for the full 251 ns because `lj_gc_pubroot` returns before copying/tagging. Registry and arena admission are still paid on every lookup.

**The proposed contract.** Introduce an internal helper with the conceptual signature `int compare_cdata_rooted_try(lua_State *L, cTValue *tabroot, cTValue *keyroot, GCcdata *expected)`. Its sole initial caller would be the shared, nonconstant branch of `recff_clib_index`. The caller must pass the exact recorded cdata object as a typed `IR_KGC`/`IRT_CDATA` C argument. This is the GC object/header pointer, not the foreign function or extern payload address. A raw `IR_KPTR`, `KINT`, or `KINT64` containing the same number is forbidden because it does not retain the object graph. The helper is not a general public cdata validator and must never accept a newly observed raw cache result as its expected identity.

The recording-time `hit_try`, three recorder anchors, publication of source anchors, `lj_clib_cache_snapshot`, CType snapshots, and exact sampled-value agreement remain unchanged (`lj_crecord.c:3031`). They supply the admitted object from which `lj_ir_kgc` is constructed. The receiver and original cache table remain separate KGC operands. Only runtime handling of a nonnumeric shared result changes. Pre-MT raw lookup and all numeric actual-value loading retain their existing code paths and eligibility. The numeric branch must continue to handle signed zero, NaN, infinities, and large unsigned enum conversions through its current load/guard behavior.

A suitable first implementation keeps the existing TMPREF source geometry: IN1/OUT1 for the authoritative original cache table and IN2 for the name. It does not write either cell. Keeping IN1/OUT1 initially avoids combining this semantic change with a temporary-slot optimization. The expected KGC is a third C argument, so it remains a live IR dependency even for discarded function results and extern reads/stores whose useful address is otherwise a non-GC constant.

The helper must use the existing physical-owner snapshot/current routines, root stack-offset handling if retained by the shared implementation, one-shot SMR admission, exact table lease, exact key lease, key validation, and `tab_get_current_forjit`/`tab_resolve_current_keyed_held` path. It compares only a local acquired TValue copy using `tviscdata(&result)` plus raw GC pointer equality with `expected`, or an equivalent raw tagged-word equality constructed without reading the object header. It must not call `lj_obj_equal`, `lj_tv_gcref_type_match`, `tab_tv_forjit_loadable`, or any result header/layout probe on an unmatched value. `tviscdata` and `gcval` decode the local word only (`lj_obj.h:6211`, `:6514`); `lj_tv_gcref_type_match` does dereference the header (`:6547`) and is intentionally unsuitable here.

Return 1 only when a found value matches and both source roots plus the exact owner still confirm. Return 0 for all other outcomes. Release tactical SMR and the two source leases on every admitted path. Do not write output, publish a GC edge, acquire a result lease, wait for SMR to open, refill a cache, call a metamethod, or access an extern. As a conservative misuse check, require non-NULL owner-TG `jit_base` at entry and confirm the same value with the final owner check. That runtime check establishes native geometry but does not itself establish KGC provenance; the sole compiler call site and its typed operand must establish that fact. Do not test a closing phase gate as if it revoked an already published native interval: the existing exit protocol remains authoritative.

Keep the new call classified as side-effecting `CALLS`, with conservative `CCI_L|CCI_T` flags. Preserve the immediate post-helper snapshot and status guard, with the same `mergesnap` handling. After success, use the retained KGC as the result/identity. Keep the receiver's signed volatile lifecycle load and `GE 0` guard after this call and status guard, before returning a cdata or reading/writing an extern (`lj_crecord.c:3129`). No check may be hoisted past the call or out of the mutable shared loop.

**Why the expected object stays exact.**

1. During recording, the existing rooted cache admission and sampled side-cache agreement remain in force throughout fallible recording. `lj_ir_kgc` publishes an actual GC constant (`lj_ir.c:269`, `lj_ir.h:625`). Its NOBARRIER comment is supported by the recorder protocol, not by treating a transient `J->cur` scan as a lasting certificate: `gc2_scan_current_trace_root` requests asynchronous abort and prevents MARK closure until the recorder unwinds (`lj_gc2.c:9552`). This proposal does not alter that protocol or rely on an active recorder to authorize native access.

2. Before execution is enabled, `trace_stop` saves/publishes the finished trace before patching runnable bytecode/exits (`lj_trace.c:5945`). Live trace traversal marks each `IR_KGC` payload (`lj_gc2.c:20715`). GC root scanning retains published and retired JIT state in both major and minor cycles (`lj_gc2.c:9532`). Therefore a compiled expected operand is an independent root even after a debug mutation removes it from the original cache and Lua drops other strong references. Its exact object address cannot be a freed/reused successor while that root is valid.

3. Trace unlink/retirement does not immediately abandon operands that old native code or exit restoration may use. Published retired traces preserve the KGC/prototype/snapshot graph while the slot or grace interval can still name it (`lj_trace.c:2624`, `:2638`, `:2700`, `:2715`, `:3315`, `:3455`). Unpublished failed assembler scratch is explicitly a different body kind and cannot be runnable here. Ordinary retirement's best-effort walk is not a new stand-alone certificate for an arbitrary stale pointer. The proposal also requires the existing runnable/native lifetime protocol; it does not use the parked-FFI checked-preservation API to certify a raw argument.

4. Native entry already publishes TG `jit_base`, fences, and revalidates the phase gate. A collector closes the gate and fences before deciding that native users are quiescent (`lj_gc2.c:80`). MARK close and admitted SWEEP progress defer while a TG is native (`:22408`, `:22431`, `:22792`). XPOLL is the asynchronous exit path; its first-attach/profile/phase checks remain untouched (`lj_asm_x86.h:4210`). A gate close or OS preemption alone does not clear this native interval.

5. The proposed helper cannot create a quiescence boundary. Its string-key call path uses owner/TLS reads, `smr_read_try`, existing lease admission, the common acquired-copy resolver, confirmation, and releases. Those operations do not call Lua, allocate through `L`, resize the Lua stack, poll with `L`, invoke a foreign function, clear `jit_base`, or park a native CALLXS frame. Registry/arena release can wake existing progress machinery, and internal CAS retry loops remain; this is not a wait-free claim. Such wakes do not publish this TG as quiescent. The source audit covers entry through final source-lease release; the ordinary C ABI call emits no native-exit transaction. A future callback/allocation/L-aware poll inside this helper would invalidate this proof and require a separate retained/publication design.

6. After helper success, the compiled continuation uses the same KGC before another safepoint. Existing trace return/side-exit/store publication handles later exposure of that already retained object, exactly as it handles other KGC results. The helper does not discover or install a new root: its return is an integer, its source temporary cells remain the table and key, and the result identity was already in the trace. This is why it can omit result publication. It is not permission to omit publication when a general table lookup discovers a different collectable value.

**Authority, mutation, reuse, and refusal.** The original CLibrary `cache_env` retained during recording stays the runtime authority (`lj_clib_cache_env_acq`, `lj_crecord.c:3036`). `debug.setfenv` does not replace that authority. Neither the side-cache linked list nor a recorded node address may replace the lookup. Every successful helper call acquires the current root values and resolves the current paired vector generation, including resize-retiring flags, immutable side sizes/masks, collision bounds, locked keys, publication claims, FORWARD markers, `struct_owner`, and final root/metadata checks. A FORWARD from an active resize stays a retry; it is not repaired or followed through an unprotected pointer.

SMR must still start before source-root loads. Together with the exact table and key leases it prevents a copied source pointer from being validated as a recycled successor and keeps vector storage readable through resolution. Table generation and source-root confirmations still establish the same authority point as the existing helper. Keeping the expected object alive does not protect a stale table, collision key, or reused side vector; none of their existing admission checks are removed. No vector pointer escapes SMR. A concurrent value write after the accepted acquired snapshot remains a later operation, just as with the current helper; the proposal does not promise an indivisible transaction spanning lookup and subsequent use.

A nil/missing entry, false, number, another cdata, a different GC type, or a malformed/stale unmatched GC word returns 0. The shared resolver copies a found value when `out` is supplied without first dereferencing that value's header (`lj_tab.c:4240`); only its existing key/structure checks remain. The new comparison then inspects local tag/pointer bits. A newly allocated override is neither rooted nor dereferenced by this helper and must go through the interpreter's ordinary rooted lookup after exit. If pointer and cdata tag match, the independent KGC root proves that exact allocation's identity. Address reuse cannot manufacture a match against an object that has remained live. A malformed word encoding that exact live identity is observationally the same identity for this comparison, not a path for exporting a foreign or unchecked object.

Owner mismatch, source-root change, SMR refusal, either source-lease refusal, invalid key, or generation refusal remains a zero-status exit after releasing acquired resources. Sources are unchanged on both success and failure. There is no retry loop calling the waiting helper and no fallback lookup inside the C helper. The immediate post-helper snapshot retains all prior Lua effects; the interpreter may execute the still-uncompleted namespace operation but must not replay prefix stores/calls or a completed extern store. The generated status/close guards occur before any extern side effect.

This is Lua-visible refinement, not identical internal helper statuses. The old helper can admit and publish a different result, return 1, then fail the VLOAD type/identity guard. The comparison returns 0 at the combined post-helper guard instead. Likewise, the old result-specific lease refusal hook no longer fires because there is no discovery lease for that result; retained KGC authority replaces that obligation. All still-applicable table/key/source/owner/generation/SMR refusals remain. Validation must not silently report removed result-admission events as if they still occurred.

The signed volatile close sample remains after the helper and its status check. A close completed before that load must exit before result export or extern access, including a close injected after a successful comparison and before the generated load. Close after the accepted sample may overlap use under the existing semantic contract. Physical handles remain retired until joined-world trace teardown (`lj_clib.h:24`, `lj_clib.c:1194`); the optimization neither adds a reader-count wait nor makes physical unload immediate. Receiver KGC retention and its equality guard remain unchanged.

**Expected benefit and rejected extensions.** Removing the cdata result lease removes one ordinary small-object registry/arena handoff, one explicit SC fence, exact cdata layout discovery, output copying/publication, and the generated result VLOAD/type/pointer check. Nominal retained work is still ten shared RMW operations and two explicit SC fences for table/key leases plus outer SMR. The extra expected C argument and conservative native-geometry checks also have costs. This supports an isolated experiment, not a claimed one-third improvement or a promise of single-digit nanoseconds.

Do not hoist mutable shared lookup, substitute the internal linked side cache, add an unverified table-version shortcut, remove table/key leases or SMR because the expected value is rooted, or reuse the scalar-only helper with its different exclusions. Do not implement a generic cdata-value loader without publication. Do not apply the comparison to numeric enum results. Broad table writer epochs would need complete coverage of raw/JIT stores, clear, resize, weak transitions and every writer; that is a separate design. Do not reclassify the helper as a pure CSE-able call or alter pure-loop eligibility, phase gates, first attachment, XPOLL, or protected recorder cleanup.

**Required evidence after source review, before integration.** An implementation would stay isolated and first prove its IR has a real expected-cdata KGC C argument, one comparison per loop iteration, no result VLOAD for the cdata path, the old numeric helper/value path, the immediate refusal snapshot, and the later signed close guard. A negative control with absent/wrong expected identity or nonnative calling geometry must reject; a helper-name count alone is insufficient proof of native execution.

Use the accepted authority/root/installed-side, captured receiver, numeric, cache resize, original-environment lifetime, prior-close and between-close fixtures against the new helper in normal/assert/ASan builds with identical runtime inputs apart from flags. Adapt witnesses/wrappers in a new package; retain the accepted 444-process package unchanged. The close wrapper must call the real comparison and close only after actual native success, before the lifecycle load; verify zero extern side effects and no prefix replay. Existing real SMR/source-admission refusal controls must still cause native exit without a waiting helper or counter leaks. Result-specific old-helper refusal controls must remain assigned to the old/numeric/discovery path and must not be mislabeled as new-helper coverage.

Add a bounded KGC-lifetime case that removes the cached original value and drops external strong aliases, actually collects, and then reenters an old root/side before restoring the exact value; verify the original object survives through trace retention and the new override exits. Test original cache table growth/full collection and actual forwarding/retirement/reuse using existing supported table protocols. For in-helper lifetime overlap, use an already attached actor and real GC/flush requests while a wrapper pauses a genuinely native comparison; verify the native interval delays unsafe reclamation and releases normally. Do not delete runtime gates or claim a stopped-GC fixture proves overlap. Reuse root/phase/profile/first-attach regressions without reopening the separately blocked attachment-during-recording task. Preserve every first failure and any admission-limited witness.

Only after correctness and proof review should a matching seven-pair lookup study assess the reduction against aee88db5, with the old and new call-site shapes and all processes retained. If the comparison fails any source-lifetime or refusal obligation, keep the current v2 helper and its measured cost.
