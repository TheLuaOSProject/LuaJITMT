Automatic GC boundary review (source only; no new runtime claim)

Base: b4e26564. Ordinary lj_gc_step -> gc2_step_auto -> lj_gc2_step_explicit shares the synchronous phase path. A bounded outer step count does not bound any nested handshake.

MARK activation: gc2_mark_begin in lj_gc2.c retains worker_active while staging typed MARK, publishing legacy MARK, resetting marks/queues and performing ENABLE_BARRIER|ALLOC_BLACK|EXIT_TRACES|REDISPATCH|FLUSH_SSB. Only after that handshake returns does it clear the request leader and publish jit_mark_resume for the current cycle. Worker_claim rejects GCSCAN, not an ordinary outstanding initializer token. Simply changing this to a request and releasing worker_active would admit ordinary MARK drains before activation completion. A durable initializer stage and explicit admission predicate are prerequisites. Resuming initialization must not repeat resets, consume force-major twice, increment cycle twice or overwrite carried semantic work.

MARK root snapshot: gc2_mark_root_scanned 0/1 -> 2 currently owns a caller-stack continuation through the blocking FLUSH_SSB+SCAN_ROOTS/SCAN_OWNER_ROOTS call; cycle and thread_pending/actions are local. A paused driver strands state2. Persist exact cycle, request and completion evidence before allowing independent helpers to finish; distinguish merely claimed per-TG acknowledgements from completed root actions. Preserve root-scan retry on recorder/native changes and exact NEEDSCAN handoffs. A new helper must not re-run root callbacks concurrently on one TG or lose a later invalidation.

SWEEP grace: gc2_worker_sweep_progress owns worker_active while performing LJ_GC2_GRACE_EPOCHS successive synchronous FLUSH_SSB handshakes. Clearing sweep_grace_needed relies on no second retire producer during those complete epochs. Releasing the worker token changes that premise: new retirements must carry exact retire-frontier/epoch identity and cannot be covered by older completed grace. Persist both boundary count and captured retirement frontier before deferring. Later SSB rescue work must drain before destruction.

Native return: safepoint_wait_consumed_ack deliberately prevents mutation while the leader scans frozen owner state. A separate agent is preparing a real consumed-owner-root fixture, distinct from old synthetic poll-clear tests. hs_epoch_ack and reqmask=0 are action claims, not full completion. Study per-TG action-complete versus final leader-clear windows separately, accounting for trace-frame/FLUSHJ and reclamation grace. Do not delete waits based on counters alone.

Global dispatcher: lj_safepoint_handshake owns hs_leader and also performs global roots, trace quiescence/flush, retirement, and final consumed-poll clearing. Async STOPREQ publications sharing pending counters already require finish_prior_epoch. A reusable async GC request needs durable request/actions/target identity, complete attach/detach rules, and idempotent finalization; publishing a new epoch over unfinished counters is unsafe. Caller-owned TLS idle_transition_gate cannot simply outlive its caller.

Suggested implementation order: establish actual paused-scanner and paused-after-action native-return oracles; define a per-target root/trace action completion certificate; separately make MARK activation state durable with no partial-reset replay and no early drains; then root snapshot and exact-frontier SWEEP grace. Preserve all current waits until their authority replacement is tested. This is a source-derived prerequisite list, not implemented design or a nonblocking claim.
