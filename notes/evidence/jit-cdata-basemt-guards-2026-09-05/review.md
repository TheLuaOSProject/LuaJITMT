# Cdata recorder refusal and pre-MT method guards, 2026-09-05

The unchanged shared-cdata hammer exposes a real missing-native path. A separate, minimal recorder correction fixes a demonstrated pre-MT stale-method defect, but leaves that MT refusal in place. The correction passes semantic/native controls and the targeted regressions below. It also adds a substantial cost to tiny FFI loops; it is a review candidate, not a claim that the performance tradeoff is acceptable for release.

Everything in this study is isolated under `/tmp/lj-ffi-owned-trace-20260905-pmxukjxp`. The exact base is `dd2c439179b1e12564710484d8511e4cee617f7f`. No shared source, test, or suite file was edited. Root's optional interpreter cdata-method capture is a separate candidate and is absent from all four trees used for this recorder correction. The final handoff is `pre-mt-cdata-guards-review.patch`: `src/lj_record.c`, one dedicated Lua fixture, and one M6 registration. `source-binary-manifest.json` verifies all 224 tracked source/DynASM files in each of the fresh baseline, normal fix, assertion fix, and canonical trees. Only `src/lj_record.c` differs from the base production source. Generated sources, objects, archives, and executables are hashed too. `patch-verification.json` records exact reconstruction of the three-file patch.

## The unchanged hammer does not merely miss an existing trace

`initial-results.json` preserves fresh plain and `-jv` runs of root's frozen baseline and interpreter-capture candidate. All four exit 1 at `tests/t-ffi-cdata-shared-hammer.lua:80`, whose native assertion was left intact. The fixture SHA256 is `aa663307d03a08df0897954b3c069428d6518a8e712da29b022c4a3953c9ede3`. The verbose output reports recorder aborts at the constructor, rather than a successful native trace overlooked by the trace-count helper.

The first GDB attempt targeted a stripped binary and could not resolve the breakpoint; `abort-stack.*` preserves that setup failure. Relinking the exact frozen baseline `luajit.o` and `libluajit.a` without stripping gave symbol-level backtraces without rebuilding any source or object. `relink-source-hashes.json`, `relink-diagnostic-results.json`, and `symbols-gdb.stdout` preserve that distinction. The actual refusal is `lj_record_mm_lookup`'s `lj_record_mt_runtime_shared` fence (`LJ_TRERR_NYIBC`, error 7). For construction its caller is `rec_call_setup`; for fields it is `lj_record_idx`. Both paths refuse before the CNEW/CNEWI exception in `recff_cdata_index`, or before `recff_cdata_call` can allocate.

The general fence came from `7cbcaba74b2f108b9e237cc87163cf1ca6ecc020` (2026-07-19); the trace-owned cdata expectation came from `432b610875ea4037eba575ab27ff0440eb3bb456` (2026-07-08). This identifies the direct cause without a broad historical bisect. `hammer-fix-normal.stderr` confirms that the final narrow correction still reaches the exact original line-80 failure. Interpreter correctness is not substituted for the requested native coverage.

## A distinct stale-method defect and its minimal correction

`basemt-native.lua` is preserved unchanged from the initial native mutation control. It warms an 80-iteration constructor/field loop, requires both a recorded trace and real `texit` events, mutates the cdata base table, then invokes the loop again. On the base binary, replacing the base root flushes the old trace; the replacement method runs all 80 times through newly recorded native code. A flush-callback reentry probe also passes and produces zero callback traces. It does **not** reproduce a callback rerecord/publication race.

In contrast, changing the existing base table's `__call` field keeps the old trace and calls the replacement only once, rather than 80 times. Arithmetic still matches. The interpreter calls it 80 times. Those controls and failures are in `basemt-mutation-results.json`; the unchanged control passes all three modes in the final normal and assertion binaries (`guard-regression-results.json`, `original-v2-*`).

The fix removes only the cdata jump to the special-userdata immutable-method path and its now-unused label. Cdata now follows the existing base-metatable `lj_ir_ggfload` plus `lj_record_idx` path. The normal table lookup emits structural/key/value guards; `rec_call_specialize` emits the appropriate function identity or prototype guard. Special userdata behavior and the top MT refusal are unchanged. The final production source SHA256 is `e5d872f8fc9af3fe10643f6a328084d0d582c3a9753bb70bcccced1a0e65ef6e`.

The dedicated fixture starts its loop with an iteration that deliberately skips cdata dispatch. On a subsequent invocation the FORL can therefore enter old native code before the first missing/nonfunction method is used. This is essential: an interpreter error in the first iteration would not prove a native guard. Final modes cover changed `__call`, `__index`, `__newindex`, absent and nonfunction `__call`, base-table hash growth followed by full GC, recorded Lua method lifetime, and base-root replacement. Required method counts are 80 or 160, and every successful JIT-mode case requires actual native execution following mutation. Missing/nonfunction cases must side-exit and error. Root replacement must first leave zero old traces and subsequently execute a new native trace.

The method-lifetime case initially installs a Lua closure, retains only a weak Lua reference after replacement, and forces full collection. The recorded trace must keep the old method alive, then guard out and invoke the replacement 80 times. It passes normal/assert/canonical and fails the base on the stale-call count, while its interpreter control passes.

The early dedicated fixture unconditionally assigned nil to 256 cleanup keys. Such absent-key stores could reserve hash capacity before the intended growth. Its v1 source/results are preserved and are not accepted as hash-growth evidence. The corrected fixture only deletes keys that were actually inserted. The base FFI table is constructed from the 19-entry library initializer (`lj_libdef.h`, through `lib_create_table`/`lua_createtable`); adding 256 distinct live keys after warming forces growth. Corrected v2 baseline negatives fail six in-place modes, while root replacement passes. The final fixture adds method lifetime without changing those mode bodies; full final normal/assert/canonical runs pass all eight modes in both JIT modes. Final identities are in `candidate-source-hashes-final.json` and `final-canonical-result.json`. The v1 production build also had an unused-label warning; final normal/assert rebuilds remove the label and have empty stderr. Historical logs are retained.

## Lifetime and activation boundary of the correction

This change uses the existing pre-MT base-metatable protocol. `lj_record_mt_runtime_shared` is true for a non-main recorder TG, active/entering MT, nonzero live peers, or more than one registered GC2 thread. `lj_record_mm_lookup` rejects before either old or new cdata lookup when any of these conditions holds. The change creates no new MT source-capture authority and no new raw slot escape.

In the admitted pre-MT path the receiver is a Lua/recorder root; the base table is a global `GCROOT_BASEMT` root. Normal method lookup and specialization are used under the existing single-mutator recorder rules. `lj_ir_kgc` publishes method/prototype constants into the current trace. GC2 refuses to close MARK while token-private current-trace construction remains active (`gc2_scan_current_trace_root`), and published/retired trace traversal scans KGC entries (`gc2_traverse_trace`). `trace_start` admits recording only in IDLE or cooperative MARK with the entry gate open; it refuses SWEEP. The weak-method/full-GC control directly exercises retention after the base table stops owning the recorded closure.

Base-root replacement still depends on the API's existing flush protocol, just like other base-metatable receivers. The emitted base-root load assumes the recorded non-null root is safe; it is not an independent MT root-admission guard. `lua_setmetatable` calls `api_trace_flush_mutation_claimed` before the release store to the base root. The sequential replacement control demonstrates both old-trace invalidation and subsequent native dispatch through the new root.

First MT activation enters through `threading_entering_begin`, then `threading_mt_active_prepare_traces` acquires the JIT token and flushes existing traces. `threading_gc_enter_counted` sets the sticky `mt_active` flag while still owning that token and keeps `mt_entering` through live publication/rechecks. Pre-MT traces cannot continue as peer-mutating traces. The existing canonical thread-activation and GC-worker-activation flush cases pass, as does `m6_jit_xbar_xpoll`, including its runtime-shared cdata refusal assertion. These are tests of the existing exclusion; they are not evidence that general MT cdata metamethod recording is implemented.

## Remaining prerequisite for enabling the hammer's MT native path

A blanket cdata exemption is not justified. A trace-owned result does not own the shared cdata base table, and the constructor's ctype receiver need not itself be a CNEW result. `RecordIndex.tabv` is a copy, and `rec_call_setup` copies a real stack slot before method lookup. Opening SMR around a previously copied local cannot establish exact source-root/incarnation authority.

A future implementation needs a real stack/root slot or stable offset, source SMR before its first value load, exact receiver admission, base-root capture and expected-TAB admission, then a bounded held lookup such as `lj_tab_getstr_held_try`. That helper requires exact table lifetime plus SMR and distinguishes RETRY from absence. The copied method needs exact admission and publication into an owner-private enumerated root before either vector SMR or method admission ends. Only after every exact scope is released may recorder work allocate, wait, throw, or publish a KGC from that rooted value. The existing `lj_meta_lookuptv` is a waiting wrapper and cannot be called while outer recorder leases are held.

Recording-time retention alone is insufficient. Native code needs a rooted, nonwaiting lookup/guard at each semantic lookup boundary, or an equally strong mutation-version dependency. A CNEW receiver may require actual XSAVE/materialization into the helper ABI. Method/root changes, node forwarding/resize, denied admission, same-address reuse, and GC phase crossings must side-exit before the affected operation and preserve replay semantics. A once-per-loop cached proof does not cover a peer mutation.

The current root replacement flush cannot be assumed sufficient after such MT enablement: `lj_trace_flushall_hs` can release its newly acquired token before `lua_setmetatable` publishes the new base root. With relevant MT recording enabled, a peer could record against the old root in that interval. No such race was reproduced here; the present fence excludes the proposed recorder. Holding a suitable publication exclusion through the root store, or adding a correctly rooted runtime root/method guard, is an open prerequisite. The current repair does neither and makes no claim of enabling the hammer.

## Validation and measured cost

Final normal and assertion/helper static builds use GCC, `CCDEBUG=-g`, and default optimization. Assertion flags are `LUA_USE_ASSERT`, `LJ_GC2_TEST_HELPERS`, `LJ_TRACE_TEST_HELPERS`, and `LJ_TAB_TEST_HELPERS`. Build commands/hashes are in `guard-build-results.json` and `guard-build-v2-results.json`; the original build script preserves the historical label version. The canonical normal build and its exact child commands are separately recorded. Final validation includes:

- Fresh exact base and final normal stock suites: 387 interpreter and 509 JIT tests pass on each binary.
- Final normal and assertion FFI read, write, and traced-finalizer fixtures: all six pass.
- Unchanged original native mutation fixture: all three modes pass on both final binaries.
- Final eight-mode dedicated fixture: normal, assertion, and canonical binaries pass in both JIT modes; final canonical M6 registration passes.
- Existing canonical xbar/XPOLL, first-thread activation, and first-GC-worker activation cases pass.
- The original MT hammer remains a preserved failure; the new negative controls fail the exact base as specified above.

Costs use 42 fresh processes on CPU 31, seven alternating pairs for each of three workloads, exact matching normal builds, and no helper flags. The existing `aux/bench/bench.lua ffi_struct` is unchanged, `BENCH_SCALE=1`, and reports best of five at four decimal places. The custom constructor checks sums and a genuine warm native exit, detaches instrumentation before timing, and reports all five CPU-time samples. The host was not globally isolated. No runs were discarded. `guard-cost-results.json` retains commands, environments, source/executable hashes and all process logs; `guard-cost-summary.json` gives paired results.

Separate IR/mcode diagnostics explain the effect. The fixed field loop reloads the base root/node and repeats `__index`/`__newindex` HREFK, HLOAD, and function-EQ guards after each XPOLL. Its root trace is 501 bytes versus 198 bytes in the base. The constructor IR confirms sunk CNEW when sinking is allowed and materialized CNEW with `-sink`. These dumps are diagnostic runs, not timing samples. Repeated guards are the conservative existing generic-method behavior; a later pre-MT guard-hoisting optimization needs its own alias, callback, collection, activation, and side-exit proof. This evidence does not justify restoring immutable-method assumptions or removing the MT safety fence.
