# Source authority chain

All references below use `source/combined/src/lj_gc2.c` and the unchanged fixture copy.

1. `gc2_worker_main:2798` now schedules `gc2_sweep_prepare_bridge_result` after bounded graph/arena drain, outside an earlier worker claim. This is the explicit worker scheduling addition. The exact baseline/combined source diff is in `diagnostic/source-proof-3.stdout`.
2. `gc2_sweep_prepare_bridge_result:5619` claims `worker_active`, revalidates phase, and computes `prepare0`. At 5642 it issues the ordinary RESET_ALLOC handshake whenever a ready TG has an older preparation certificate, even when READY was already published. In captured synthetic cycle 4 this legitimately moves main and worker allocator preparation to the current epoch. Its production READY call at 5714 still owns that token through 5740.
3. `lj_gc2_sweep_to_idle:6468` claims the worker token, closes the JIT gate, and at 6494 claims the phase sentinel. It checks real queues/arena preparation/READY and then performs final FLUSH and post-handshake checks before publishing IDLE. At 6578 it releases the worker token while retaining GCSCAN and the closed JIT gate for the mandatory IDLE handshake.
4. `gc2_worker_claim:1511` rejects GCSCAN before its token CAS and rechecks it afterward. Ordinary production bridge/worker actors therefore cannot acquire a new competing worker token through this close interval.
5. `gc2_idle_transition_handshake:4338` requires IDLE, GCSCAN, JIT gate 0, and no existing borrowed TLS gate. The observed state has JIT gate 1. Its direct abort is retained; suppressing it would permit an invalid reclamation transition.
6. The fixture publishes synthetic SWEEP and root_scanned at 1375, but initially stamps only the extra allocator. It releases its finalizer blocker at 1402. After observing arena progress, it still asserts SWEEP, directly clears READY at 1428, and only then writes main/worker preparation epochs. Those observations do not own the phase or exclude a real close.
7. Its `sweep_to_idle()==0` at 1435 may simply mean the worker token is held by another actor. It then calls `lj_gc2_sweep_bridge_ready` at 1438 while a worker already owns the close gate (captured).
8. `lj_gc2_sweep_bridge_ready:6282` is a one-shot READY CAS followed by JIT entry opening. The CAS prevents redundant callers from reopening an already-admitted READY=1 quantum. The fixture defeats that safeguard by explicitly resetting READY to 0. `gc2_jit_phase_gate_open_sweep:150` checks SWEEP/READY and then publishes its scheduling lease and gate=1; it does not independently claim phase/worker authority. The fixture call can therefore reopen entry after the real close owner has closed it.

There is one production call to READY from the claimed bridge driver. The compatibility alias `lj_gc2_sweep_bridge_boundary_reached:6307` has no production C callers in these 225 inputs. The header currently declares these internal exports without an explicit ownership comment; that is a documentation issue to assess separately, not permission for a fixture to mutate a concurrently owned irreversible latch.

Other SWEEP gate reopening paths in this source run from worker-owned drain/reclaim or close rollback; cycle_leader's GCSCAN exclusion covers new claimants. No production path in this captured generation was observed violating the claim protocol. This bounded review is not a complete proof of every gate writer in the entire runtime.

The raw extra traversable allocation and extra_tg.cur_L alias are additional reasons not to let the synthetic fixture accidentally run a real semantic sweep preparation on unrelated main/worker arenas. The observed abort itself is the READY/JIT-gate ownership race, not evidence of a bad object classification or corruption of that raw allocation. A corrected setup must make its intended prepared owner set explicit before releasing asynchronous work.

Correction requirements from ROOT: READY=0 refusal must have demonstrably uncontended close admission; holding worker_active merely to force a zero is invalid. READY publication must occur under actual caller authority. The asynchronous physical progress case must allow legitimate phase completion, preserve its concrete arena/graph and stop-lifecycle assertions, and never revoke READY while workers can own the phase. No timeout extension or runtime abort suppression is justified by these observations.
