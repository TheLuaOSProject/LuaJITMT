## Worker authority and roots

`gc2_worker_main` (`src/lj_gc2.c:2766`) sets its physical TLS TG, enters its sole startup native scope and attaches before scheduling. This TG has no Lua stack. `G2TG(g)` resolves that same TLS TG through `lj_thr_get_tg_fallback` (`src/lj_obj.h:2861`, `src/lj_thr.c:1687`); the new call does not change TLS, find mainL or acquire a Lua actor. `gc2_worker_drain_inner` has returned and relinquished its own worker claim before the new boundary call.

`gc2_sweep_prepare_bridge_result` (`src/lj_gc2.c:5604`) retains both original `sweep_bridge_can_progress` checks around its existing `gc2_worker_claim`. That predicate requires SWEEP, empty recovery and no finalizer work that blocks sweep. The original claim still serializes list mutation with worker sweep and close. No admission predicate is removed or weakened.

The helper runs the same existing allocator preparation handshake if a live internal TG lacks its cycle certificate. The target resets its own cursors at an owner safepoint, or the existing remote-native action obtains the already required action authority. Root preparation still uses `gc2_sweep_root_snapshot` (`src/lj_gc2.c:5569`): provisional0→2, existing JIT close/active checks, the real roots handshake, then same cycle/phase/JIT revalidation before2→1. A root participant can still invalidate the provisional generation. NEEDSCAN requests still take the existing additional owner scan. The worker only directly flushes its own TLS TG's private SSB; other owners use the existing handshake protocol.

The original bounded owned graph drain, exact table rescan credits, active JIT/recorder/weak owner checks, SSB/recovery/NEEDSCAN publications and marks-this-round checks remain before pruning and at READY. It still invokes `lj_gc_sweep_gc2_unmarked` (`src/lj_gc.c:1902`), whose existing root/list claims, SMR/reader/arena/lifetime validations and side-body preservation are unchanged. It does not invoke destructors. Owner-pending publication and complete READY checks remain in their old order. This is scheduling of an existing authority-preserving protocol; it is not permission to read mutator-private roots without that protocol.

## Owned progress and refusal

The helper samples the current cycle, root-scanned state, EOF, READY, normalized pruning cursor and preparation requirement only after claiming and rechecking admission. A NULL pruning cursor is normalized to the root-head slot both before and after. This is necessary because a failed first validation may save that slot without advancing any work.

The actual pruning return counts unlinked objects. It does not use the prune's internal visited/seen count. At a shared exit, and still under the same worker claim, a changed deferred epoch selects DEFERRED before any positive classification. Otherwise same SWEEP phase and cycle are required for every positive result. A positive bridge result requires at least one observed actual unlink, cursor advance, EOF0→1, scanned-not1→1, READY0→1, or previously required allocator preparation now completely cycle-certified. A bridge already ready and with no outstanding preparation is COMPLETE. Failed validation at the same normalized frontier without any such change is BLOCKED. No attempt counter alone can become progress.

Every old retry path still releases the claim and wakes workers. The public void wrapper and its preserve argument remain; all old callers retain their signature and behavior. The preserve argument was already unused. The internal result makes scheduling decisions explicit without changing the root or arena algorithm.

In `gc2_worker_main`, PROGRESS adds one scheduling unit and, after the existing worker-stop check, directly continues to the next outer scheduling iteration. This prevents a worker from parking just because there is no new producer wake for its own remaining bounded prune unit. Every new iteration rechecks phase, claim and gates. BLOCKED/DEFERRED route through existing `gc2_worker_deferred_backoff` (`src/lj_gc2.c:2727`), which reabsorbs futex wake-sequence changes until the one-millisecond deadline or STOP. This avoids two workers amplifying the helper's own retry wakes when a frontier has not moved. COMPLETE leaves the existing idle-close and snapshot-before-wait logic available. The old active-cycle timed retry remains a notification backstop.

Graph-only drain work or a whole pending-chain flush returning to the same head may conservatively back off. A phase change after initial admission also returns a nonpositive result. This is a conservative scheduling classification, not a claim that no logical work occurred. The quiet fixture proves busy-claim refusal, no false progress under that claim, multiple real cursor-only advances and completed worker progress after the main caller stops producing work. It does not force every internal fail-validation branch.

## Native worker exit and stop/join

The new boundary permits workers to lead RESET_ALLOC and SCAN_ROOTS handshakes. Candidate1 exposed an existing assumption at worker exit: startup native depth remained1 across `lj_tg_detach`. Detach (`src/lj_tg.c:758`) publishes DETACHING, performs at most one pre-teardown poll, then flushes private allocations/roots and clears tmpbuf, owner Lua hints, FFI roots and native state. DETACHING remains registry-borrowable until RETIRED. The frozen candidate1 witness lets a real leader consume a request after that last poll and proves teardown crosses RETIRED before the action returns.

Candidate2 calls the existing `lj_native_leave_tg(tg)` immediately before detach (`src/lj_gc2.c:2846`). The worker starts with exactly one native entry. Its scheduling path has no L; `gc2_peer_wait_l(NULL)` and `gc2_peer_wait_owned_l(NULL)` use the no-L retry path rather than entering another native scope (`src/lj_gc2.c:5030`, `:5052`). L-aware creation/join/retry scopes belong to the pool controller and balance before return. The real exit wrapper records depth1 for RESET and SCAN in normal, assertion and ASan controls; no native depth is injected by a test.

At depth1, `lj_native_leave_tg` (`src/lj_safepoint.c:651`) release-stores native0, issues the existing sequential fence, then polls that exact TG. The fence pairs with `safepoint_signal_late`'s post-request/post-poll fence (`src/lj_safepoint.c:679`). Thus either the owner observes the published request and acts locally, or the leader sees the native scope still open and retains the existing consumed-poll action hold. A remote action already consumed must finish its scan/allocator action and leader cleanup before this owner can enter detach. An epoch ACK alone is not scan completion: the RESET control pauses after its epoch claim and the SCAN control pauses before the claim; both retain poll while native0 and prevent detach entry.

A new request after native0 cannot obtain remote-private action authority, including after detach's final own poll. It remains pending until the exact owner polls or the existing DEAD-retirement protocol discharges the slot. The unchanged late-request witness observes native0, actual nonzero request and zero remote-action overlap, then normal join/leader/pending cleanup. No private mutation is inserted between native close and its exact-TG poll, and no field clearing is moved ahead of the existing holds.

The controller path `gc2_worker_stop_locked_l` (`src/lj_gc2.c:2619`) remains unchanged: it publishes worker STOP and wakes the pool, holds the exact joining caller native as appropriate, joins, then returns/accumulates caller actions on native leave. Already admitted worker handshakes are completed, not cancelled. The eight RESET/SCAN × workers1/2 × L-aware/no-L cases keep the joining caller nonnative and deliberately withhold its target ACK until ordinary stop begins. All complete with owner unchanged, native0, pool exited, and leader/pending/request/poll cleared. Earlier startup requests are serviced only before the target handshake is released.

The inherited consumed-poll gates remain necessary in addition to native close. The existing local/pre-claim duplicate fixture deliberately creates legitimate remote refusal and duplicate publication, then proves actual scan and consumed-poll waiting. Its final v2 correction changes only a transient zero-mask oracle and retains those completion checks; it does not replace them with an epoch-only assertion.

## Limits

The new invocation does not introduce new IDLE requests, call finalizers, borrow mainL or modify ordinary string-reclamation restrictions. It does not bypass a held constructor, root owner, reader, recorder, phase guard or finalizer. Those states may still defer useful work. Synchronous handshake waits and full detached pending-chain flushes are inherited and remain potentially long. Stop/join may wait on a noncooperating actor. No wait-free, lock-free, sanitizer-race-freedom or universal completion proof is claimed. The separate fair-constructor source was not combined or tested here.
