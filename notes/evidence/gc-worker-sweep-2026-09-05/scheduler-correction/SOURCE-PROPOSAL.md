# Scheduler fixture READY authority correction — source checkpoint

This isolated patch changes only t-gc2-worker-scheduler.c. Runtime source and both frozen default archives remain unchanged. It follows the separately frozen default scheduler abort diagnosis; no functional validation has occurred at this source checkpoint.

The new manual READY-veto case runs immediately after main's existing real initial collect/STOP and before the first worker starts. It asserts zero workers and exactly one TG. Synthetic setup owns an actual successful worker-token CAS, with cycle_leader=0 and smr_reclaiming=0 checked before and after the CAS. The old completed cycle's READY is reset only while still IDLE under that ownership. The setup retains the existing synthetic root certificate/string initialization and main allocator epoch convention, and asserts that no traversable needsweep/quarantine work exists before stamping the empty frontier.

Before the negative close, the token is released; worker_active=0, cycle_leader=0, smr_reclaiming=0, no workers/peers and no prepared/pending arena work are asserted. close must return 0 with READY=0. The fixture then actually claims the worker token, publishes READY, checks publication, releases the token, and requires the real close to return 1 and increment its completed-close counter exactly once. The positive half verifies that the same uncontended phase had no independent permanent close veto. Holding worker_active to make close trivially fail is explicitly avoided.

The asynchronous physical-arena case acquires the same ownership before any synthetic phase/allocator/READY setup. Its finalizer blocker remains unchanged. The existing main and worker preparation stamps move before the worker token is released; newly added assertions prove their traversable needsweep/quarantine frontiers are empty. Only the original extra arena is prepared for this synthetic physical sweep. This prevents the newly scheduled runtime boundary from legitimately preparing unrelated main/worker owned arenas while the fixture pretends its semantic roots were already scanned.

After finalizer release, workers own all drain/close progress. The fixture never clears READY, restores owner allocator state, restamps epochs or directly republishes READY during that live phase. Every existing concrete physical arena/list/flag/epoch assertion remains. The intermediate phase observation accepts either SWEEP or already-completed IDLE, and the original 1000 x 1 ms observational drain bound remains. The existing async counter proof remains anchored before physical work; a new sweep_to_idle counter proof separately requires actual close progress. Original final IDLE, worker stop/join/slot/count and extra TG detach/reclaim/finalization checks remain.

The helper's 1000 x 1 ms acquisition limit bounds setup contention, not the independent worker drain. The caller never borrows a nonzero token. Because these setup calls begin in IDLE and own the token, they do not need MARK close intent admission. No user callbacks, pool changes or other mutator threads execute inside the owned setup. The post-CAS SMR/phase-sentinel recheck matches the inverse exclusion of ordinary runtime worker claims. Release wakes the existing worker scheduler after publishing token zero.

The initial uncompiled source draft and setup are preserved. Source review noticed that a completed real cycle can retain READY=1, so the final checkpoint explicitly initializes the fresh synthetic cycle while still IDLE and owned. This is not active-phase latch revocation.
