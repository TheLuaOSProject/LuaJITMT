# Protocol and evidence scope

The paired baseline is immutable c106 small-shrink final GCC; candidate is the frozen bin-capacity GCC tree recorded in metadata.json. Both build manifests are preserved. Source inputs and emitted LuaJIT/library hashes were verified against those manifests before any performance harness build. The sole runtime source difference is src/lj_arena.c. Six C harnesses use identical GCC -O2 -g -Wall -Wextra -Werror -mcx16 options, variant-specific frozen headers and the corresponding complete static library. Link lines, dependency files and compiler output are archived. The two public LuaJIT executables were copied and hashed independently.

hot.c and retention.c are byte-for-byte copies from /tmp/lj-plain-shrink-perf-20261126-s5650_mv. growth.lua is a byte-for-byte copy from /tmp/lj-plain-progress-perf-20261126-sucpc_rf. No prior result rows are reused as current measurements. New bulk.c includes a frozen copy of the new bin-capacity fixture to share real-allocation setup, live guard checks and bounded owner-only census; it does not execute the fixture's deliberately corrupt-cycle cases.

The primary matrix was declared before execution in metadata.json:

- Hot: sizes 64, 256 and 4096 B; 5000 untimed warmup cycles and 500000 measured allocate/touch/free cycles; five fresh process pairs per size, 30 invocations.
- Bulk free/refill: 1024, 4096 and 9000 real 1 KiB targets, each followed by a live 16 B guard; PLAIN and TRAVERSABLE; three process pairs each, 36 invocations. Final bump capacity is consumed by real live allocations. Only the free loop and refill allocation/touch loop are timed. Outside timing, complete bin cells, unique reused addresses, all refill payload bytes and every guard byte are checked. Baseline loss of reuse is recorded, not converted into an early benchmark abort.
- Retention: 8192×4 KiB and 2048×16 KiB, each shrinking to 16 B before 1 KiB refills; three pairs each, 12 invocations. Original, shrunk, refilled and all-freed phases emit logical and bitmap-derived physical bytes, block starts, arena count, published free-bin bytes, active bump bytes and operation CPU/wall time. No rebuild/transfer occurs. Process RSS/status is sampled while each stage waits for controller acknowledgement.
- Public Lua: JIT on; one 1 KiB string.buffer payload; 1000 warmup cycles, one warmup full collection, then 40 rounds of 20000 reset/put/get/equality cycles with normal automatic GC. There is no forced collection during the measured rounds. After dropping the buffer and flushing traces, five final full collections are measured separately. Three pairs, six processes. Every stage captures public gcstats, Lua logical bytes and synchronized /proc status before acknowledgement. Work CPU time excludes status sampling and terminal full GC.

All pair orders alternate baseline/candidate on odd samples and candidate/baseline on even samples. Ratios compare corresponding samples; independent medians are also reported. No outliers are discarded. Each timed process uses taskset CPU 8, a 1 GiB address-space ceiling, disabled core dumps and a 60-second controller watchdog. Staged processes additionally require RSS below 512 MiB.

The initial 4 KiB hot spread included both faster and slower candidate samples (paired ratios 0.760–1.306). Before the follow-up ran, the agent declared to root a bounded five-pair follow-up with 2,000,000 cycles and the same frozen hot executables/source. These ten rows remain in long-hot-measurements.json, separate from the 84-row original matrix.

Root then identified possible interference in that first follow-up: CPU 8 and CPU 9 are SMT siblings on physical core 4, and a separate deterministic diagnostic/compilation ran on CPU 9. The original 84-row matrix completed before that work according to message chronology. The first ten long samples remain explicitly classified as potentially overlapping, with no claim that the sibling core was idle. long-hot-overlap-caveat.json records that notification and approximate intervals inferred from stdout filesystem mtimes minus measured controller duration; the first follow-up did not record authoritative UTC start/end timestamps.

After root confirmed CPU 9 idle and redirected all further diagnostic/CI work to CPUs 0–7, the same five-pair long control ran again. Only this follow-up was repeated. long-hot-isolated-measurements.json records ten separate rows including UTC start/end for every process, and cpu-topology.txt preserves lscpu output. Root validation CPUs 0–7 are cores 0–3. Shared-cache, frequency and host interference remain possible even with core 4 reserved, so full paired variation is reported. Neither long set is pooled with the primary matrix, and the potentially overlapping set is not concealed.

Checksums cover preserved workload sources, binaries, runtime input archives and reports. Runtime source archives include source/dynasm inputs and top-level Makefile, with individual manifests; complete build manifests retain every original recorded input. Final verification checks immutable build source/output hashes, harness executables and workload hashes again. Results are focused Linux single-mutator allocator/buffer controls, not stock parity, general application speedup, reclamation of dead TG/FINREG state, or proof that the complete runtime is nonblocking.
