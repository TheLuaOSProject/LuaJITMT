The unchanged ITERN case exposes a runtime progress dependency: ordinary rooted iteration waits for global metadata SMR even when the next result and all traversed storage can be retained independently. A narrow repair can let small scalar arrays progress during that refusal without changing the original fixture schedule or weakening global SMR. This document proposes source changes for review; no candidate runtime implementation exists in this package.

The proposed production delta is local to `lj_tab.c`: add a static `tab_nextscalar_rooted_try` helper and invoke it only in the existing branch where global `lj_gc2_smr_read_try` has already refused. Successful OPEN admission continues through the existing implementation. The helper returns FOUND or END only with complete independent authority; otherwise it returns RETRY and the existing wait/rebase loop runs. It must never expose its RETRY as an invalid-key error or END. This placement targets progress and avoids changing the ordinary OPEN path's work or accounting. Moving the helper onto every iteration for performance would be a separate measured change.

The proposed helper interface mirrors the existing operation:

```
static int tab_nextscalar_rooted_try(lua_State *L,
                                    cTValue *tabroot, cTValue *keyroot,
                                    TValue *outkey, TValue *outval,
                                    uint32_t *nextidx);
```

The eligible domain is deliberately small: a small arena-allocated table whose hash pointer is the permanent global nil node; a null, colocated or separately allocated small array; input nil, an internal `LJ_KEYINDEX` cursor, or an integral numeric key within the current array index range; and a first non-nil result whose tag is number or boolean. An empty table or exhausted array may return END. A GC result encountered before a scalar result must refuse, never be skipped. Hash storage, GC keys, light userdata keys/results, Huge allocations, custom allocator compatibility, invalid numeric keys, unsupported/internal values and transient admissions keep their existing general path.

The attempt must follow this order:

1. Validate L, both input addresses, distinct output slots and the exact physical actor/TG/state owner with `tab_keyed_slot_owner_snapshot`. This occurs before loading candidate source words or consulting any candidate mapping/header. The caller continues to supply stable authoritative source cells; owner validation does not turn an arbitrary C temporary into a root. Save no raw heap pointer across an L-aware call.
2. Copy the table and key source words with acquired TValue loads. Classify only tags and numeric bits. Reject unsupported keys before hashing or GC-header validation. In particular, do not call `tab_tv_snapshot_valid`, `tab_tv_forjit_loadable` or `lj_obj_equal` on an unretained GC candidate. None is needed for this domain.
3. Admit the table's exact small start with `lj_gc2_small_lease_try(g, candidate, sizeof(GCtab), ~LJ_TTAB, ...)`. The helper validates numerical address/alignment, persistent registry membership, mapping-slot and arena admission, allocation/lifetime/type metadata and a minimum byte extent before any table payload read. A malformed or inaccessible candidate cannot be dereferenced merely because its TValue has a table tag.
4. Confirm both actual source cells and the exact state owner after admission, before reading the table's vector pointers. This is the table incarnation check. A lease at an address reused before admission is usable only if the authoritative source currently publishes that incarnation; rechecking only the copied local TValue is insufficient.
5. Load both vector roots from the retained table. Require the node root to equal `&g->nilnode` without dereferencing any other node pointer. For a separate non-null array, admit the exact raw allocation beginning at `array - sizeof(TabArrayHdr)`, with minimum `sizeof(TabArrayHdr)` and expected type zero. Do not read its header or call an ordinary snapshot helper before this independent array admission. Null arrays need no lease; colocated storage is covered by the table lease.
6. Confirm the array and nil-node roots after array admission and before reading variable layout metadata. For a separate array, acquire its immutable capacity and logical size, reject RETIRING, require valid capacity and `asize <= acap`, and require header-plus-capacity bytes within the admitted cell-span bound. For null/colocated storage, read the retained table's logical size and require a null array to have size zero. For colocated storage also require a positive `colo <= LJ_MAX_COLOSIZE`, `asize <= colo`, and `sizeof(GCtab) + colo*sizeof(TValue)` within the retained table span. `newtab_rooted` records its exact inline capacity in `colo`; resize marks it negative when separating. Reject that transition rather than treating the conservative span as the allocation's true requested capacity. The admitted span is an upper bound, not an exact requested byte size; confirmed layout metadata remains the allocation contract.
7. Resolve the scalar cursor as specified below and scan acquired array TValue words within that validated bound. Copy a candidate number/boolean into local scratch. Skip only nil. Any other tag, including a GC word, FORWARD, claim, KEYLOCK or other internal encoding, returns RETRY without following it or publishing it. There is no hash chain traversal.
8. After copying the local result, confirm the paired generation, retiring state, logical size, both original source words and the exact physical state owner while all leases are still held. Use the same `tab_forjit_snapshot_current` semantics, with the node root fixed to the permanent nil node and hmask zero; a colocated attempt must also retain the same positive `colo` capacity. A failed confirmation refuses without modifying any output or cursor.
9. After that last confirmation, publish the two scalar output words and then the scalar successor cursor when FOUND. Preserve `lj_state_stack_pubtv` on stack outputs and the existing non-stack root publication convention; number/boolean output introduces no GC edge. END modifies neither output nor cursor. No source read follows the first terminal output store, because either output can alias an input. Release every successful lease on every exit. No allocation, callback, stack growth, safepoint or explicit wait is permitted inside the attempt.

The source recheck after copying the result means after copying it into local scratch and before terminal stores to caller-visible slots. Rechecking the input after overwriting an aliased output would invalidate `lua_next`'s required in-place key behavior. The terminal publication is therefore the last use of the input cells, matching the existing scalar getter's alias proof.

Cursor semantics must match `tab_keyindex_snapshot_held` exactly within the accepted domain:

| Input | Start index and outcome |
| --- | --- |
| nil | Start at array index 0. A live numeric/boolean value at key zero is visible. |
| `LJ_KEYINDEX` | Use its unsigned low 32 bits directly. An index at or beyond `asize` reaches END after nil-node/generation confirmation. |
| Integer key k with `(uint32_t)k < asize` | Start at k+1 even if that key's current value is nil, as the existing array cursor does. |
| Floating-point key exactly convertible to an in-range integer | Use the existing checked numeric conversion and start at k+1. Both signs of zero have the same key meaning. |
| Negative/out-of-range integer, fractional, NaN or infinite numeric key | RETRY to the original implementation; the new path does not manufacture END or replace its invalid-key behavior. |
| Any unsupported nonnumeric key | RETRY unchanged. |

On a found slot i, output integer key i, the exact acquired scalar value, and `nextidx = i+1` when requested. For an exhausted scan, END is justified only after the table still publishes the same retained array, its same logical size, and the global nil node. The helper must not return END merely because it refused a lease or encountered an unsupported entry. Empty/null-array and all-nil-array cases need the same complete generation/source/owner confirmation as a found result.

The existing small-lease protocol supplies independent lifetime authority, not a general exemption from reclamation. Its persistent mapping-slot reader pins mapping identity until arena `remote_active` admission succeeds. The SC fence and exact lifetime/block/READY checks preserve the reader/destructor ordering. A table lease pins the small table body; a separate array lease pins its plain allocation through the final byte read. The raw array vector remains opaque until admitted and source-confirmed. A plain-arena writer already owning that arena may still deny admission, and terminal mapping deletion or transient lifetime states must still refuse. Registry/reader CAS loops retain their existing lock-free retry behavior; there is no wait-free instruction-bound claim.

Resize and free races remain explicit. If a vector is replaced before admission, the source recheck rejects it before header access unless the current table really publishes that admitted successor. If it is replaced after admission, the old storage remains physically retained, and final paired-generation/retiring checks reject it. Forwarding a candidate slot refuses. Colocated storage uses the retained table's extent, and a changed array pointer or logical size fails the final check. Hash appearance, including integer-key migration into or out of hash storage, fails the nil-node paired-generation check. Physical reuse cannot occur while an acquired lease is held. The helper does not follow a forwarding pointer or rely on a global SMR read acquired elsewhere.

Mutable scalar values retain the existing iteration semantics: each returned scalar is an acquired slot observation, and the operation does not promise a whole-table atomic snapshot during unsynchronized value changes. Skipping nil during the scan is the existing behavior. Structural changes may cause a retry. This narrower path never combines a discovered GC pointer with later address-reused body storage because it never publishes any discovered GC pointer.

Caller provenance is unchanged and concrete. `lua_next` claims the state, materializes and publishes its receiver into a stack root, prepares owned key/output cells and passes those roots; its output key aliases its input key. The x64 builtin `next` passes owned frame arguments and caller result slots to `lj_tab_next_pair_rooted`. The x64 ITERN passes the owned frame's table cell; `lj_tab_itern_rooted` derives an immutable scalar `LJ_KEYINDEX` local from its owned control slot and passes the adjacent output cells. The new attempt has no frame change or L-aware work. The outer existing retry loop retains its saved stack offsets and must restore both input and output addresses before every new attempt after a wait. The scalar `nextidx` pointer is the caller's independent C cursor scratch, as in the existing ITERN wrapper.

Existing rooted-reader retry hooks must remain meaningful. If that one-shot hook is pending in a helper build, the new fast attempt should refuse so the established general path runs the hook only after dropping its own SMR/leases. The new path must not execute allocation-capable existing hooks while holding its independent leases. Any new diagnostic stage hooks must have an explicit nonthrowing/no-stack-growth contract, and their adversarial changes must be observed by the source/generation checks. Production has no hook callout.

The validation gate after review is bounded but requires both real progress and meaningful refusal coverage:

- Run the exact unchanged `t-jit-idle-reclaim-entry.c` through completion on matching optimized GC2-helper, full assertion/helper and target ASan runtimes. Keep the original timeout and this debugger capture as failures/observations. Require all original outputs, displaced counters, closed native/SMR gates, zero native activity, bytecode shadow checks, post-release recovery and generic trace checks. The ITERN call stays before the reclaimer release.
- Exercise ordinary Lua builtin `next`, specialized ITERN and C `lua_next` while the real reclaimer is paused: dense, sparse, zero-key, false/true/numeric, null empty, all-nil and separately allocated small arrays; check exact results, final END, unchanged gate/reader/anchor counts and that release has not occurred. Include integral floating keys, both signs of zero and internal cursors at/beyond the end. The original source must time out in the bounded closed-window control.
- Inspect the bounded helper directly for refusal without output/cursor changes on unsupported keys/results, first GC entry, Huge vector/table admission, inaccessible table/vector pages, malformed size metadata, retirement/forwarding and a real paused plain-arena writer. Do not turn these refusals into public iterator END. Unsupported public operations are checked after writer release on their original path.
- Force source replacement before/after each admission and after local value copying, real array resize including hash appearance, and stack relocation between outer retries. Verify exact lease/arena-reader, SMR, anchor and state-owner cleanup. Validate each required input/output alias and both the found and END confirmation paths.
- Run the existing scalar-hit, rooted-reader, rooted get/length and iterator regression fixtures plus stock off/on on source-identical optimized/assert/ASan builds. Recheck all input, helper-flag and binary identities. Broader testing is justified by new failures or source changes, not by repeated unchanged batches.

The proposal intentionally leaves general hash iteration, GC key/value discovery and publication, Huge/custom allocator topology, and progress under a paused writer of the exact plain arena as separate work. These limits must remain visible even if the unchanged idle-entry fixture passes. No runtime gate is deleted, the fixture is not exempted, and no performance claim is made at this proof stage.
