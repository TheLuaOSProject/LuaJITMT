## Verdict

No source blocker was found in the actual cache-result/lifecycle guard sequence. The existing bounded `lj_tab_gettv_rooted_hit_try` helper is a sound fit for this generated ABI: stable KGC-backed source cells, an aliased enumerated output, status checked before the guarded TValue load, exact cdata identity, and a fresh signed lifecycle check before the exported result or extern access. Numeric values are returned from the actual load. The normal pre-MT path preserves ordinary raw table guards, and its post-lookup checks prevent a raced generic waiting helper from becoming installed native code.

The implementation still needs the requested native root/side, mutation, error/no-replay, first-activation, and final combined-source validation. “One bounded table-admission attempt; no SMR/table wait on this generated path” is justified. “Allocation-free,” “fixed-cost,” “wait-free,” or “every recorder attempt is nonwaiting” is not justified by this patch.

The original method-guard and direct receiver defects remain separate baseline bugs repaired by their earlier commits. This patch adds authority for mutable original-cache values and semantic close. It does not weaken the ordinary shared-MT metamethod refusal.

## Native scratch roots and result lifetime

The call registration has the correct arity and return type: `4, S, INT, CCI_L|CCI_T` describes `(lua_State *, cTValue *, cTValue *, TValue *) -> int`. `lj_ir_call` supplies the implicit L, emits an ordered CALLS, and sets `J->needsnap`. CCI_T conservatively preserves the existing guarded-helper treatment; it does not by itself publish a Lua frame or convert this call into a foreign CALLXS region.

The env KGC and name KGC are retained by the current trace, and the receiver KGC independently retains the namespace and its original cache_env. `TMPREF(envref, IN1|OUT1)` materializes a complete table TValue into this TG's `tmptv`; `TMPREF(nameref, IN2)` materializes the string into `tmptv2`. The numeric-constant TMPREF shortcut does not apply to these GC inputs or to the IN1|OUT1 parent. The helper receives the actual first cell as both source and output, which its contract explicitly permits.

`tab_keyed_slot_owner_snapshot` (lj_tab.c:4411) binds the call to the exact physical actor, TG, and claimed L. It does not reject an otherwise-valid active native owner. The current trace is retained while native code runs. `gc2_scan_owner_tg_roots` (lj_gc2.c:9472) scans `tmptv` and `tmptv2` while `jit_active` is set, and the helper's publication barrier closes the later-root-publication edge. Thus these are enumerated native roots backed by retained containers, not arbitrary C snapshots merely accompanied by an owner check.

`tab_gettv_rooted_try_impl` (lj_tab.c:4862) attempts SMR and table/key/result admissions, confirms exact input words and the owner, then stores the result. It drops every vector pointer before ending SMR, publishes the result root while the exact table/key/result leases remain live, then releases those leases. `hit_try` returns 1 only for that completed hit; all misses/refusals return 0 with the original cells unchanged. A helper refusal therefore leaves an env table in parentout, not a usable result.

The explicit nonzero status guard comes before `lj_record_vload`. A refusal cannot be mistaken for a cached value or pass into a cdata payload dereference. A successful changed-type result is retained even if the next VLOAD exits. Same-type but different cdata is retained through the exact-identity exit. Numeric output carries no GC edge. The old expected cdata remains an anchor root until its KGC is installed and remains a trace root thereafter.

Each TMPREF is a side-effecting IR operation, and `lj_opt_fold` emits it anew rather than applying CSE (lj_opt_fold.c:2530). Each repeated call/loop copy therefore has a distinct parentout TRef. The VLOAD CSE rule cannot equate outputs of different invocations merely because the underlying native scratch address is reused. The immediately following VLOAD does not cross another scratch-producing helper. Existing native scratch lifetime is sufficient; no new persistent scratch root or C runtime helper is needed.

## Publication work is not a fixed-cost guarantee

`lj_gc_pubroot` and `lj_gc2_barrier_tv_g` can publish MARK/WEAK/SWEEP or remembered-set work. SSB overflow may recycle published queue work and grow the grey queue. Growth uses `lj_mem_new_nothrow`; failure returns to the existing allocation-free recovery plane or a sticky reclaim veto rather than throwing through retained leases. The relevant chain is lj_gc2.c:14339/14369, 14444/14536, 10904/10964, and 10545. Existing GC allocation accounting can perform bounded assist or request a later native exit.

This work happens after table-vector SMR closes and while result body leases remain held. The runtime call path has no Lua callback, chain-anchor allocation, table retry wait, or SMR wait. Queue ownership uses existing try admission, publication may retry CAS, and queue growth can still call the allocator. A successful helper call can therefore be more expensive than an uncontended point read; the helper's existing contract already discloses this. Its established publication path is not a new throw/lease-unwind blocker for this patch.

## Guard snapshots and no replay

The implementation forces `lj_snap_add` immediately after CALLS with `mergesnap=0`, then places status, VLOAD type, cdata identity, and lifecycle guards after that snapshot. This matches `rec_idx_mt_shared_load`, including the important fact that both the recorder and interpreter still describe the fast-function frame. `lj_record_ret` has not run. The separate `ffrecord_postcall_snap` repair for a foreign call after returning to the Lua caller must not be substituted here.

The helper has only lookup/root-publication effects. It has not called the selected symbol, returned the builtin result, or written the extern. A guard exit may restart this builtin and repeat its raw lookup/root barrier. It must not repeat earlier Lua stores, counters, or foreign calls. The new post-helper snapshot supplies that boundary. Refusal must remain guarded before VLOAD, even though a VLOAD type failure would often also reject the preserved env table: status is the publication authority, and it deserves its own explicit proof.

An extern store is recorded only after every cache/lifecycle guard. Its existing needsnap handling remains in place. Exact no-replay validation must include writes as well as reads, old installed roots and installed side traces, and type/refusal/lifecycle exits. A root compiling or an exit count increasing is insufficient on its own; observable counters and target values must show that the old path actually executed and then exited before the store.

## Recorder roots, types, and fallible operations

The new `L2TG(J->L)` anchor owner matches `lj_vm_cpcall`'s rollback checkpoint and `rec_idx_mt_shared_sample`. envtv starts with the original table, keytv with the name, and tv with nil; hit_try overwrites only envtv on success. Root-anchor storage consists of linked blocks, so further growth does not relocate earlier anchor slots. Failed second/third pushes or later recorder errors are handled by the enclosing protected trace-state rollback. Normal return pops tv, keytv, then envtv.

The raw `cl`, env, and name identities remain alive before and during constant interning: receiver/name are live call arguments, receiver becomes a KGC, and namespace GC traversal retains the immutable cache_env edge even after debug.setfenv redirects the visible userdata environment. env/name become explicit KGCs before later fallible setup. Neither `CType` pointer in the new sequence points into a reallocatable CType vector: `ct` names the local snapshot. The result anchors remain present across type lookup, raw recorder lookup, snapshots, constant interning, and result construction. No table node, table value slot, or side-cache entry address is exported to native code.

The admission-time `lj_obj_equal(envtv,tv)` remains an eligibility check. It does not establish a runtime result. The actual shared VLOAD has the cache snapshot's type; normal raw RecordIndex emits its own sampled type guard. The cdata branch verifies the returned TRef type and emits forced IR_EQ against the retained expected cdata KGC. This also handles forwarded constant TRefs correctly: known unequal constants go through the ordinary false-guard abort, instead of the stale-TValue shortcut in lj_record_objcmp.

For a constant-value symbol, `tref_isnumber(value)` is the required representation check, and `J->base[0]=value` exports the actual runtime number. There is intentionally no numeric equality guard against the original enum constant. That broader native acceptance is semantically correct: interpreter cache hits return numeric overrides directly. It preserves -0, NaN, infinities, changed finite values, and large unsigned values in the selected numeric representation. Under a dual-number build, an int/number representation change may conservatively side-exit; it cannot be reinterpreted under the wrong tag. This supersedes the earlier design review's finite-cache/NaN equality requirement, which applied to a design still synthesizing the expected constant.

The frozen v1 late writer argument still uses `&rd->argv[2]`, an inherited baseline pattern. The newly selected hit_try path itself invokes no Lua and does not resize L's stack, so no distinct new stale-argument counterexample was found here. ROOT has accepted the one-line v2 refinement `crec_ct_tv(J, ct, ptr, J->base[2], &J->L->base[2]);`. That refresh is sound: `lj_ffrecord_func` initializes rd.argv from L->base and this builtin has not yet returned or changed frames. Reading the current base avoids carrying the earlier stack address across the added fallible setup. It should be described as a robustness refinement, not an independently demonstrated new defect. Final validation must use the v2 source identity.

## First MT activation

Branch selection uses the complete `lj_record_mt_shared_tab` predicate, including sticky active/entering, live count, registered TG count, and non-main recorder ownership. It is sampled after the new fallible KGC/name/anchor/type/name-guard setup. Thus an already-visible activation selects the bounded native helper instead of relying on an early private-world sample.

The pre-MT branch captures the CALLS chain, runs normal raw RecordIndex with zero idxchain, then rejects if a CALLS appeared or the shared predicate became true. This correctly catches an activation that makes generic RecordIndex select its old shared helper, including cases where later optimizer behavior forwards some other part of the lookup. The generated waiting helper cannot survive this abort.

There is still an intentional distinction between recording and generated execution: generic RecordIndex may execute its waiting recorder sampler before this post-check rejects it. This is not an installed native wait, but it prevents a blanket claim that every record attempt is now nonwaiting. Avoiding even that abandoned recorder attempt would require another bounded raw-recording entry or a deeper change to generic sampling; that is unnecessary for this native correctness patch.

An entrant can appear after the post-check or during later constant/snapshot/extern-conversion allocations. Correctness then also relies on the existing first-activation protocol, not merely on one C predicate load. `threading_mt_active_prepare_traces` (lib_threading.c:824) acquires the recorder token and flushes old traces before `threading_gc_enter_counted` publishes mt_active (855/877). A remote entrant cannot run secondary Lua mutation while the current recorder holds that token; token contention requests an abort in `lj_jit_token_acquire_wait` (lj_trace.c:2325). `trace_state` consumes the asynchronous abort before completing publication/releasing the recorder token. This covers the remaining late-allocation window. The same-owner callback/reentry path remains governed by the existing recorder abort/flush protocol; the new helper itself adds no callback.

The post-check is therefore sufficient to reject a generated waiting call in the raced branch, while the mandatory transition protects any pre-MT raw trace from execution beside the first secondary mutator. First-activation validation should still force entry while recording and prove abort/flush plus successful later shared recording. If the separate pure-userdata-metatable optimizer change is included, repeat these checks against the combined final sources.

## Lifecycle and cache semantics

`receiver + sizeof(GCudata) + offsetof(CLibrary,lifecycle)` uses a userdata KGC. The existing ADD-KGC fold returns mutable KPTR for userdata, not KKPTR; the cdata-constant-only contents shortcut cannot apply. `IRTI(IR_XLOAD)` with VOLATILE alone plus signed IR_GE zero is the correct test for sticky closing bit 31. Every valid nonnegative reader count remains admitted, and every closing bit pattern is negative.

`lj_opt_fwd_xload` checks VOLATILE after READONLY, so omitting READONLY matters. The actual source does omit it. The load bypasses forwarding/CSE, and its guard keeps it under DCE and loop substitution. Native IR/machine-code validation should confirm the memory read or fused signed comparison remains in each relevant loop body after the helper and before extern effects.

Because close is irreversible, a successful cache read followed by an open sample can be linearized before any later close. A close that occurred during lookup/publication is caught. Physical handles remain retired until joined teardown; namespace lookup does not require native traversal of side-cache entries. The interpreter already releases its short namespace reader before ffi_clib___index/newindex performs the extern conversion/read/store, so an even later close overlapping that use is not a new semantic split.

Nil and absent entries make hit_try return zero and let the interpreter refill the original table through the existing side-cache protocol. They do not mean semantic close. A changed cdata, false, table, function, or mismatched numeric representation either fails the generated value/type guard or prevents new recording. Replacing the visible userdata env does not redirect cache_env. Giving the original table an __index method does not affect either raw path because RecordIndex's zero idxchain and hit_try both bypass table metamethod dispatch.
