The final CLibrary cache/lifecycle regression fixture passes 324 intended-positive runtime processes on ROOT's frozen v2 Linux/x64 normal, assertion, and ASan builds. This package changes no production source. It adds independent active-MT, original-root/installed-side, original-cache, extern-target, numerical-value, semantic-close, and collection/lifetime coverage. No runtime protocol gate was removed or manually cleared, and no benchmark was run.

Final production inputs are ROOT's `/tmp/lj-clib-cache-root-20260905-i59mqoic/v2/{candidate,strict,asan}` trees. All 224 runtime/generator source inputs match ROOT's manifest across the three variants, verified both before and after validation. The base is `5c455f20e2cc9be74920e9139a9b4002d4ac430b`; only `src/lj_crecord.c` and `src/lj_ircall.h` differ from that base. Their SHA-256 values are `62a718fad1c9c271c8225cb1d2255fddf526dde17eff3ecfe2318c2a2249eaa5` and `822ee730b3589500bf463c9b345cd91fd3c4c5ce056a297734b90f121bd14a69`. The runtime executables, archives, generated vmdef files, source hashes, and copied ROOT build commands are bound by `final-source-identity.json` and `root-v2-*-build.json`. ROOT's trees were only read and executed.

The final Lua fixture is `t-clib-cache-authority.lua` (SHA-256 `f43a25e242d40469a606cd48c553ea7b59ee678c4242b0e72478931ede6cefed`). The linked close wrapper is `t-clib-cache-between-close.c` (`eb2fcc06d171c08ddade7edff84613a19c8006f287b433045f4f487ee5babab4`). The DSO source is `t-clib-cache-authority-lib.c`; `final-library-build.json` records a separate rebuild that exactly reproduces the tested `authority.so` bytes (`17e478b509e4205a5a53374ef62d9d9dc7b5b10ffdd0682ffc24c3387f8226da`).

Per build, the final runtime matrix is:

| Suite | Processes | Coverage |
|---|---:|---|
| Controlled authority | 80 | Forty kind/mode/root-or-side cases with JIT off and on; GC stopped for controlled trace geometry. |
| Close after successful native lookup | 4 | Extern read/write, old root/installed side, JIT on. |

Every JIT-on authority case requires an actual native warm root and an installed side that links to its parent, with trace-exit witnesses. ROOT's current builds must also contain a real `lj_tab_gettv_rooted_hit_try` CALLS in the shared root IR; the helper is identified by vmdef's name/index mapping. A live worker remains parked on a channel from before recording until after reentry, so this is active MT rather than merely the historical attachment latch. The worker uses the public threading interface, and cleanup joins it even after a protected Lua failure.

After warm installation, the fixture freezes the root and side trace generations. Trace starts increment generations even for other functions, and post-warm exits from a fresh/reused trace cannot satisfy the original-target witness. Root-target reentry runs 39 iterations, avoiding the natural root-to-side path that can otherwise complete without a root trace-exit event. Side-target reentry runs 80 iterations and must exit an already installed side. Each lookup/store has a preceding Lua table increment. Success requires exactly 39 or 80 increments; a closed namespace or invalid extern-store cache requires exactly 1 or 40. These counts detect replay or skipped preceding Lua effects after a helper or lifecycle exit.

The ordinary matrix covers function, extern-read, and extern-store original-cache overrides with false, nil, and another cdata; ignored replacement of the debug environment; prior semantic close; numeric enums with +0 and -0 in both directions; false/nil numerical cache values; and an unsigned enum value 4294967295 overridden by 8589934591. Nil must actually refill the original cache, not only return a coincidentally identical cached result. Extern mutations use a third independently loaded namespace to observe and reset root/side/other globals at 17/41/73. A cdata override must redirect reads and stores to the other global; closed/invalid stores must leave the prohibited target untouched.

The GNU linker wrapper always calls the real `lj_tab_gettv_rooted_hit_try`. It matches the selected owner Lua state, global state, original cache table, and key before the real helper, because a successful aliased output replaces the input tabroot. Only a genuine successful lookup with a non-null native jit_base witness triggers `lj_clib_unload`. The close therefore occurs after lookup and before the generated lifecycle load. Atomic release/acquire publication of the arm flag safely publishes its immutable selection to any other thread; only the selected Lua state may consume it. The test never fabricates a successful return or a refusal. Every one of the 24 final wrapper processes reports exactly one native hit, actual success status 1, and a native witness 1, then the closed-library error with exact prefix effects and unchanged prohibited extern-store sentinels. For read cases this proves that the result is not exported after close; the ordering of the physical extern load is additionally a source/IR property, not an independently observable read side effect.

The 72 GC-enabled processes are separate lifetime coverage. They use public full collection before warm, after old root/side installation, and after mutation or prior close, with GC enabled thereafter. Across the final collection, strong fixture aliases to both original env tables and the selected env are dropped. A weak reference to an otherwise unreachable temporary must clear, proving actual collection, while the original cache env's weak witness must survive through namespace/trace roots. The original native targets must still be reached afterward. This specifically exercises ignored setfenv without retaining the old env through those fixture aliases. These cases do not establish simultaneous collector execution inside the hit helper, nor a measured SMR refusal. No concurrent-GC overlap or bounded-refusal timing claim is made.

The C wrappers were compiled outside ROOT's trees against each frozen archive and that tree's headers. Assertion and ASan compilation uses all seven matching defines: `LUA_USE_ASSERT`, `LJ_FUNC_TEST_HELPERS`, `LJ_GC2_TEST_HELPERS`, `LJ_TAB_TEST_HELPERS`, `LJ_ARENA_TEST_HELPERS`, `LJ_TRACE_TEST_HELPERS`, `LJ_XSAVE_TEST_HELPERS`. ASan uses Clang O1 with address sanitizer and frame pointers, and every ASan runtime process uses `ASAN_OPTIONS=detect_leaks=1:abort_on_error=1`. Normal/assertion wrappers use O2. The build records include exact commands, archive hashes, actual header dependencies, and output executable hashes. Functional runs were confined to CPUs 24–27; their elapsed durations are not performance measurements.

Independent semantic negative controls use the previously frozen receiver-fix baseline `597b8705208957ade8465416da30976ab9b52195`, with `lj_crecord.c` SHA `d9117ff3214f258cc84648725effcd498f3d1e93a774a94efd65e81ed11f2bff`. All 40 interpreter cases pass. Of 40 native cases, 38 fail their result/refill/close/extern-target assertions; the two ignored-setfenv controls pass as expected. This is not an exact 5c455f20 baseline: it also precedes the userdata pure-loop optimization. That exception is excluded here by active MT and the loop's Lua stores. `setup.json` records all 226 initial runtime/build inputs and binary hashes. A further two deliberately altered fixture copies independently fail the native witness: `jit.off(run,true)` prevents native compilation, and `hotexit=65535` prevents installed-side formation. Both fail the required-native-root-and-side assertion, with production gates unchanged. These controls are recorded separately from the 324 intended-positive cases.

Fixture-development failures and superseded evidence remain intact. Initial v1 used the Lua `condition and left or right` idiom for expected false values; three pilot failures were oracle errors. V2 fixed false-value expectations but used 80-iteration root reentry; four correct prototype results lacked the over-specific root-exit witness (76/80 prototype passes), and baseline had one additional witness failure (41/80). V3 changed root reentry to 39 iterations, giving 80/80 prototype passes and the expected 42/80 baseline total. V4 added between-close support; its four native wrapper cases passed. The initial C wrapper used nonexistent `tvis(...)` and failed compilation; `t-clib-cache-between-close-v1.c` is preserved, but that early compiler output was not saved as a JSON artifact. Its corrected v2 uses `tvistab`, an atomic arm flag, and owner-state selection. V5 added GC lifetime handling and optional C gc arguments: all 324 v2 intended-positive cases passed, and the baseline/control results are retained under `v5-*`. The final Lua version strengthens original-trace generation ownership; all affected final cases were rerun. The final C executable bytes are unchanged by that Lua witness refinement. Earlier pilot/development results are not substituted for final-byte evidence.

Source review of the fixture and the final recorder found no additional interaction blocker. The existing exact receiver guard retains the namespace; original-cache and key KGCs retain lookup inputs; shared TMPREF parentout/key roots cross the real helper; the post-helper snapshot captures preceding effects; status/value/cdata guards and the signed volatile lifecycle test precede exported constants or extern access. The prior whole-body pure-loop optimization cannot absorb this CALLS/effects-bearing active-MT path. The wrapper's raw C selection fields are only observation handles: Lua locals and trace constants retain their corresponding objects. Broader collector/SMR correctness remains the responsibility of the production review and existing runtime protocol; this fixture does not claim a new lifetime authority.

`run-final.py` records every command, environment change, CPU affinity, input hash, exit code, stdout, and stderr. Its result-file existence check intentionally prevents overwriting frozen evidence. `final-summary.json` summarizes only final-byte results. ROOT owns production integration, canonical registration, broad regression results, and performance measurements. This package's `artifact-manifest.json` classifies text versus hash-only binary/archive artifacts; the preserved baseline/prototype runtime trees are additionally covered by a runtime snapshot archive. Both earlier optimization-study packages were reverified without modifications.
