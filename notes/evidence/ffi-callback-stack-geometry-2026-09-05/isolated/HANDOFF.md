The original failure is a callback stack overwrite, not a missing snapshot field. XSAVE materializes the pre-call stack and stores exact root/base/top offsets, but previously left `L->base/top` at an older interpreter extent. In the frozen original watchpoint, actual base/top were slots 25/29 while the retained native frame required 37/40. Callback continuation setup wrote frame word 66 into the still-live numeric-for step at slot 32. The DONE snapshot legitimately omits that unchanged step and cannot undo the overwrite. The normal runtime returns 4 instead of 6640; its assertion build traps on the bad for-loop argument. Disabling compilation of the callback body alone does not change that failure. The original fixtures, IR, watchpoint transcript, results and identities are frozen in `original-evidence/`.

The callback contract is ordinary same-thread int32 C-to-Lua callback reentry. The function-pointer cdata and callback are strongly rooted Lua locals through all calls, the ABI types agree, and freeing happens only after completion. Warming the foreign call without invoking its callback, then enabling the callback with the same return semantics, is also used by the existing authentic callback fixture. The final new fixture removes the original unrelated struct payload: its Lua work is scalar arithmetic and `int(*)(int(*)(int), int)` only.

The stores execute only after owner/carrier validation, integer stack-extent validation, exact trace pinning, trace-number validation, and successful frame push. Every ordinary rejection therefore retains the prior owner pointers. No allocation, stack relocation, callback, poll or throw occurs between validation and the stores. `lj_native_enter` publishes native state after those owner writes; a remote native observer cannot use them before that publication. This does not introduce a lock, an owner wait, or a new admission path. It adds two owner-pointer stores to successful generated foreign entry; performance was not measured in this task.

Publishing only inside callback setup after its initial owner poll would be too late: callback suspension clears `jit_base`, and the owner root scanner then relies on the actual owner stack extent. Early entry publication gives both that poll and the callback continuation constructor the correct live extent. Nothing is changed in the separate native-ACK transition protocol.

Nested generated calls still require every older frame to be SUSPENDED before pushing a new ACTIVE top. Each new call publishes its own complete XSAVE frame. Interpreted native calls made inside a callback do not use this entry helper and keep their existing Lua geometry. Foreign auto-attached callbacks likewise have no generated XSAVE frame to publish. Stack growth during a callback retains native-frame offsets; the ordinary stack relocator moves owner pointers and generated resume reconstructs the retained JIT base from the current stack. Normal return, nested return, protected callback error, and fresh STOPREQ continue through the existing native-frame/pin cleanup paths.

Validation is Linux x64 on CPUs 0–15. No Windows/macOS work, performance rerun, or shared source edit was performed.
