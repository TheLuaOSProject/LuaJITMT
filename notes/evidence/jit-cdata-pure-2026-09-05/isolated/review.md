# Pure pre-MT cdata method-load reuse: isolated candidate

The narrow candidate passes the new native/IR, mutation, side-link, phase, global-worker, profile, eligibility and protected-error controls. It reduces this study's unchanged `ffi_struct` median from 0.0684s to 0.0206s (seven fresh-process best-of-five pairs, 30m iterations, CPU31). This is an optional Linux x64 optimization for one deliberately restricted interval, not a release claim or a claim that the collector, activation protocol, callbacks, or every JIT path is nonblocking.

## Scope and source proof

The protected root-loop unroller classifies the entire original pre-roll before re-emitting its copied body. A copied-prefix-only test would miss a late effect from the preceding iteration. The initial allowlist accepts SLOAD/FLOAD/HREFK/HLOAD/XLOAD, direct x64 ADD/ADDOV and equality guards, numeric/int32 comparisons, two exact int32/number conversion forms, and a direct numeric/int32 XSTORE whose address is a SLOAD/KGC cdata body plus a positive constant offset in [sizeof(GCcdata), INT32_MAX]. x64 represents those offsets as KINT64 as well as KINT; negative 64-bit representations fail the unsigned range check. The store proof is for valid in-bounds cdata payload accesses, not arbitrary raw pointers, forged objects, or C memory corruption.

All unclassified IR is rejected, including constructors even if later sunk, Lua-object stores/barriers, NEWREF, table.clear, helper/libm/foreign calls, XSAVE, and profiling operations. Accepted x64 lowering and post-unroll PHI/rename/int32-number repair add no callback, allocation or GC step. String ordering and 64-bit division/modulo/power are not admitted. Existing XBAR, generic poll alias limits, table/field store aliasing, HREFK/HLOAD/equality folding and GC barrier behavior are unchanged.

Only two exact FLOAD shapes may ignore the copied mode-0 XPOLL as an alias limit: the typed cdata base-root GG load and TAB_NODE whose producer is that exact root load. The original entry key/type/function guards remain. Generic alias machinery then removes the duplicate method chains; there is no immutable-method constant exemption. The actual exception rechecks the full `lj_record_mt_runtime_shared` predicate, root parent, active private scope, LOOP ordering and mode-0 poll. It does not trust only the earlier cached classification across substitution/snapshot/IR-buffer allocation.

The private byte is set only for a root self-loop during the protected unroll and is cleared immediately after lj_vm_cpcall, before free/error/retry work. Both injected allocation-error checks observe LUA_ERRMEM (4), flag0, and a subsequent successfully compiled trace. Omitting that post-call clear fails the exact flag assertion. The byte occupies existing padding: jit_State3216, FoldState offset232, GG_State42256 and cdata-root IR field276 are identical before/after.

Root entry and side-link safety are separate from a successful poll's lack of effects. Existing side tails target the root's mcode entry, not mcloop. The side fixture proves a side is installed, links to its root, executes natively, and executes again after method replacement; exact replacement calls remain640/640. It also checks that the linked root has the intended hoisted body while retaining entry proof and XPOLL0.

First external attachment cannot be described as universally flushing/exiting a mode-0 loop promptly: the old poll-only handshake can wait for natural exit. Root's independently frozen probe `/tmp/lj-first-attach-mode0-20260905-root/probe-v2.c` directly verifies literal0 and that limitation; it is not this candidate's runtime or a responsiveness fix. Likewise global `lj_gc2_workers_set(g,n)` reaches NULL-L pool creation and can bypass the owner-L trace flush. Worker safety instead uses the existing MARK/WEAK/SWEEP/IDLE close/SC/active-jit_base rules and worker finalizer ring publication without Lua dispatch. This candidate does not establish a new compiler scratch/root-scan lifetime contract or relax any root-scan gate.

The independent source audit is frozen at `/tmp/lj-premt-cdata-proof-independent-20260905-85rwrrol/final-review.md`; its final manifest qualifies the same 508e patch and all three source hashes. It reports no new source blocker, while explicitly keeping the activation and compiler/root-scan qualifications above.

- `phase-gate.c`: owner stages real MARK, peer observes active jit_base and calls existing lj_gc2_jit_mark_request_exit. The actual early exit callback replaces __index. - `global-worker.c`: owner stages MARK; foreign thread observes native activity and publishes a real pool through workers_set(g,1). The worker's normal phase close forces an early exit, whose owner callback changes the method. Pool shutdown occurs only after the atomic early-exit witness, bounding this one-activation control. - `eligibility.lua`: actual native constructor, Lua store, NEWREF, table.clear, foreign-call, indirect-pointer store and libm sin bodies retain repeated cdata-root proof. - `flag-error.c`: GNU --wrap intercepts a real realloc while the private unroll flag is set and injects the normal memory-error throw. Normal/assert pass cleanup and later native compilation. Omitting the post-cpcall clear fails. No allocator identity is forged and no live descriptor is repaired.
- Seven named canonical cases pass: new baseline-method guards, XBAR/XPOLL (including its nested store case), first-thread and owner-L worker activation flush, mutable table FLOAD, HREF node order and HREFK recorder snapshot. ## Separate excluded callback defect

The stronger callback eligibility control found a real pre-existing failure. Warmed generated CALLXS invokes a live callback after activation; exact base and candidate normal loops return4 instead of6640, and assertion mode traps in lj_assert_bad_for_arg_type. All interpreter controls return6640. Disabling callback-body JIT preserves the failure. Native frame and suspended callback observations confirm actual generated callback execution, rather than a trace-count-only oracle.

A hardware watchpoint shows actual L->base/top slots25/29 disagree with retained native-frame geometry37/40. Callback frame setup overwrites the live numeric-for step at stack slot32, double1→frame word66; the post-call snapshot omits that unchanged slot, so corruption survives restoration. This body is excluded by CALLXS/XSAVE and retains all repeated cdata guards on both sources. Root assigned a separate isolated callback-geometry repair. The complete frozen subset is `callback-failure/` (53 text files; its manifest SHA25677cad542284e26684d226d8f6433cc30b6c9735cba6b93c67252a3b93bd1e0f1). It must not be relabeled as a passing callback semantic control for this candidate.

## Cost and preserved failures

`field-cost-results.json`, `field-cost-summary.json` and `cost/` hold all14 process results and commands. The unchanged bench harness reports best-of-five CPU time, printed to4 decimal places; the study takes the median of seven fresh-process values. Baseline0.0684s/2.28ns per operation becomes0.0206s/0.69ns, a69.883% reduction. Separate final IR/mcode dumps show the field loop's root shrinks501→356 bytes while retaining root entry guards and XPOLL0. This is only ffi_struct on CPU31, after semantic/IR checks; the host was not globally isolated. There is no constructor, full-suite throughput, concurrent-MT, callback-repair or new mode-0-poll performance claim.

Earlier failures remain labeled in the artifact tree: KINT-only initial candidate was a no-op; the intermediate TValue.i64 spelling did not compile; the first phase fixture parsed Lua after staging MARK and therefore lost its intended phase; the foreign direct cycle request was correctly denied by owner provenance; a20m worker continuation had a stale arithmetic oracle and timed out, and a valid2m pool-retained continuation exceeded20s with the sampled main thread doing rooted GGET admission while the worker was parked. The final worker fixture bounds its pool lifetime after the actual early exit without dropping its semantic assertions. Those oversized samples are not nonconvergence evidence. The initial direct callback-pointer Lua control did not produce a native root and was replaced by an authentic C CALLXS control, which exposed the separately recorded runtime defect. The initial sin oracle expected FPMATH, whereas this target emits CALLN; the final assertion requires that actual libm-helper IR. GDB setup errors, compile setup errors and negative-control failures remain separate from passing runs.
