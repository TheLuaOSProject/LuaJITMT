This is a read-only review; I did not build or run tests and do not claim the source review proves every concurrent schedule. Root owns the current functional and timing validation. The review covers supported Linux x64/internal-arena operation; Windows/macOS and arbitrary custom allocator callback reentry were not investigated.

The mutation boundary

The implementation adds a hit_only mode to the existing tab_gettv_rooted_try_impl and returns true only for LJ_TAB_ROOTED_GET_FOUND. Existing generic/integer APIs pass zero and retain the previous nil-on-confirmed-miss/retry contract. The new caller passes one, suppressing precisely the SMR-refusal nil store (lj_tab.c:4909) and the ordinary non-FOUND terminal nil store (:4980). Invalid operands/initial-owner refusal already return untouched; a lost final owner goes directly to cleanup with RETRY. No other caller-output store exists in that implementation before FOUND. All resolver writes before confirmation target private snapshots, not the input or output cells. Consequently out==table, out==key, and even all-three aliasing remain sound: every needed source confirmation precedes the final store. The bool wrapper does not reinterpret ABSENT/RETRY as success.

The meta branch at lj_meta.c:711 attempts the existing number/boolean no-SMR reader first, then the broader rooted reader, before allocating chain roots. The broader reader returns false for nil/NaN keys, missing/nil/forward slots, unsupported/internal values, changing/retiring paired generations and admission refusal. Those paths leave the original operands available for ordinary meta_chain_capture_inputs and __index/error processing. In particular false, zero and any non-nil GC value are positive hits, while nil cannot suppress a required __index metamethod. Function-environment mode is explicitly excluded from both attempts, so the new branch cannot convert a current function TValue into an unleased pre-copied env shortcut.

Lifetime and source provenance

- The bounded helper binds exact physical actor, TG, state owner and terminal exception before entering SMR (tab_keyed_slot_owner_snapshot at lj_tab.c:4411) and reconfirms them before publication (:4443/:4964). SMR opens before either mutable source TValue is loaded. The table and collectable key acquire observational exact leases; tag/header checks and key hashing stay within those leases and SMR. The current-generation array/hash resolver (:4199/:4239) reads raw vector headers only within SMR and validates both vector roots together before it accepts a result. Huge vectors use the existing same SMR retirement authority; no pointer into a vector escapes.
- A collectable result receives its own exact lease while the source-vector SMR interval is still open (:4938). The lease protects its incarnation against deletion/reuse after the value load even if the table entry changes. The result is type/loadability checked while retained. Root/owner reconfirmation then precedes copyTVrel into the enumerated output. Cleanup drops vector SMR, publishes the output's stack/root barrier, then releases result, key and table leases (:4985-5004). Thus a receiver/key alias can remove the original root without freeing an object still in use, and a GC result has no unretained gap between table read and destination publication.
- The TValue leases are observational (lj_gc2.c:16589 calls gc2_tv_admit_scoped at :7204), so merely attempting the broader reader on a miss does not make its receiver/key semantically black or manufacture graph reachability. Semantic result publication remains the existing barrier after the copy. This preserves the weak/nonweak distinction expected by the general reader.

The newly reached callers

1. Ordinary x64 TGETV supplies actual frame table/key cells and the pc[-1].A destination; TGETB's scratch key is numeric. TGETS loads the immutable key from KBASE and materializes its tag in TMP1 (vm_x64.dasc:5106 and :1095). TMP1 is native caller storage, but its string identity is backed by the executing function/prototype constant root, not a replaceable env/table child copied before admission. Saved base/PC identify the live frame, and no production callback or stack-moving operation occurs during the attempt. The table root is reloaded from BASE+RB. The returned output pointer still names the same stack because this attempt cannot grow it; cont_ra's copy is idempotent. GGET deliberately calls lj_meta_tgetenv_rooted with BASE-16 and remains on the original chain-capture path (:1064).
2. lua_gettable/lua_getfield (lj_api.c:1957/:1989) hold the exact state claim. Ordinary indices point directly at stack cells, the universe registry cell or upvalues in the claimed current C closure; none is an unrooted TValue copy. Mutable LUA_GLOBALSINDEX/LUA_ENVIRONINDEX receivers are special: api_stackroot_push_index first allocates/enumerates a real stack slot, index2adr_envcapture opens source SMR, leases the env loaded from the current state or retained C frame, release-publishes into that slot, then drops the lease (:61/:327). Only afterward does meta receive that stack receiver. Key/output aliasing is intentional and is preserved on failure. api_getfield materializes its interned key before resolving the receiver, and all stack growth happens before calling meta.
3. FFI table-valued metatype __index (lib_ffi.c:1101) obtains a CType-owned root, copies the resulting table to L->base, release-publishes that enumerated argument slot and only then releases metaroot (:1124). It calls the new branch with table/output==base and key==base+1 (:1134). The original cdata object is no longer required for successful table lookup; the key remains intact for bad-member errors. A miss/refusal now preserves base until general meta capture, and later metamethod calls/stack growth still occur only after all point-reader leases and SMR have closed. No private CType anchor survives entry to meta.

Exception/reentry check and resolved documentation qualification

No Lua callback, metamethod dispatch, L-aware wait, stack grow or catchable-error construction occurs in the bounded attempt on the supported internal allocator. All such meta work remains after a false result and complete cleanup. Output publication calls lj_state_stack_pubtv -> lj_gc_pubroot -> lj_gc2_barrier_tv_g (lj_state.c:301, lj_gc.c:4400, lj_gc2.c:15486), so it must retain the exact result lease until this barrier completes, as it does.

The baseline general rooted-try header said the helper never allocates. During this review the owner corrected that comment; the frozen candidate includes the correction. The former claim was broader than the implementation: a GC-valued success can fill the SSB, convert a published node under worker_active, and grow grey storage through lj_mem_new_nothrow (lj_gc2.c:14346 -> :14824 -> :14643 -> :10914; lj_gc.c:4699). This is pre-existing behavior inherited from the reused FOUND path, not a new failure introduced by hit_only. The allocation happens after the vector SMR closes while exact object leases remain live. It does not throw on OOM; queue failure falls back to durable recovery. Its accounting checkpoint cannot recursively acquire the already-held worker token, so it cannot run a full collecting/stack-moving callback under the leases. On the supported internal allocator path I found no missing cleanup edge. The frozen candidate now accurately describes avoiding chain-anchor allocation and explicitly allows internal GC-queue growth after vector SMR closes. This documentation issue is resolved in the reviewed header; it is not a remaining requested change.
