The unchanged hard-check test fails because its previous GC cleanup did not finish, not because the interpreter omitted its hard-check bridge. The original strict process aborts at line 230. All 224 inputs in the frozen normal/strict/ASan runtime trees match commit 843786094729ca189b39920cd05ec6756d28444f; the strict fixture was compiled with the same eight APICHECK/assert/helper flags.

Read-only diagnostic snapshots in diag-v3/strict-results.json show cycle 2 in MARK before the ordinary-threshold TNEW. That TNEW increments both hard checks and assists by one and leaves mark_close_intent=1. worker_active is zero, the JIT phase gate is open, and SMR reclamation is open. finish_gc2_mark calls cycle_to_idle once, which returns with the same MARK phase, cycle 2 and close intent. The next mark_begin does not start a cycle. The subsequent hard-only TNEW increments the hard-check counter but cannot claim assist work while fair MARK-close intent is pending. The initial unfinished-SWEEP hypothesis is therefore not supported by this reproduction.

The source explains these observations. lj_gc2_cycle_to_idle is a void, best-effort preserving abort and returns when gc2_worker_claim refuses. gc2_worker_claim explicitly rejects a MARK close intent. lj_gc2_assist uses that same worker claim after checking MARK/WEAK and hard debt. Removing that exclusion or fabricating IDLE/clearing close intent would invalidate the close protocol. Repeating cycle_to_idle alone would not make this close owner progress.

The fixture can instead finish through the real public full-collection driver, which owns MARK closure and continues WEAK/SWEEP through their normal completion paths. This is a single-owner interpreter fixture with JIT off, no peer and no callback that intentionally defers collection. The proposed cleanup calls lua_gc(L,LUA_GCCOLLECT,0), asserts success, and separately asserts actual IDLE and cleared MARK-close intent. Both arming helpers should require IDLE before mark_begin and actual MARK afterward. Every existing hard-check increment, assist increment, batch-cadence exclusion and unchanged legacy color-state assertion remains required.

This proposed change is fixture-only. It does not make cycle_to_idle synchronous, delete a runtime gate, suppress a hard-check requirement, or assume the public API's return alone proves phase completion. The original and diagnostic failures remain separate artifacts.
