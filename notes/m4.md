  timed channel waits, `thread:join()`, mutex waits, and `threading.sleep()`.
  Blocking APIs now turn STOPREQ into the planned
  `thread interrupted: VM shutdown` Lua error.

  `tools/ci/m4_threading_shutdown.sh`. The test drops an unjoined worker
  blocked in `channel:recv()` under `pcall` and another unjoined worker in a
  CPU-bound Lua loop; process shutdown must interrupt both, let them write
  markers, join them, and then exit.
- Added `lj_safepoint_ack_check()` and routed x64 VM safepoint polls through
  it so a mutator that acknowledges `LJ_GC2_HS_STOPREQ` throws immediately
  instead of acknowledging shutdown and continuing bytecode execution.
- Changed the x64 VM poll trigger to check the global pending-handshake count

- Later M6 dispatch-localization work moved the x64 VM poll trigger from the

  the running `TGState.poll` through the current TG dispatch base. The shutdown
  guardrail now checks the current `TGPOLL` marker plus the checked ack helper
  instead of the original global pending-count marker.

Mid-handshake attach catch-up:

- Reworked the safepoint leader from a pre-counted `hs_pending = live`
  snapshot to a sentinel-pending protocol:
  - publish action bits;
  - publish `hs_pending = 1` as the leader sentinel;
  - publish the next epoch;
  - traverse the TG list and increment `hs_pending` only for live TGs whose
    `hs_epoch_ack` is older than the new epoch;
  - drop the sentinel after deterministic/native acks have been attempted.
- This prevents a TG that CAS-prepends after the old live-count snapshot from
  being signaled without also being counted.
- Exposed `lj_safepoint_apply_tg(g, tg, actions)` so attach can self-apply
  the active in-flight action set before making the TG visible in
  `gc2.tg_list`.
- `lj_tg_attach` now samples the current epoch and, when `hs_pending` is
  nonzero, applies the current actions locally and release-stores
  `hs_epoch_ack = epoch`. The leader skips TGs that already acknowledged the
  epoch, so a mid-handshake attach is either counted/signaled or self-caught
  before first bytecode.
- Extended `tests/t-thr-substrate.c` with a controlled race:
  - hold the leader handshake open by clearing the main TG's `cur_L`;
  - attach a pthread TG while the epoch is pending;
  - assert the child TG self-applies `ALLOC_BLACK | STOPREQ` and acks the
    current epoch without incrementing the leader's signaled count;
  - restore the main `cur_L`, ack the counted main TG, and join both threads.

Lua-visible spawn/join/current slice:

- Added `UDTYPE_THREAD` userdata for `threading.thread` handles.
- Added a `LJThread` payload in `lj_thr.h` with:
  - substrate `LJThr`;
  - child `lua_State *`;
  - separately allocated `TGState *`;
  - state/join/futex/status/result-count fields;
  - a main-thread marker.
- Added `TGState.thread_ud` as a non-root backpointer used by
  `threading.current()`.
- Important lifecycle choice: spawned TGs are allocated separately from the
  userdata and are not freed on join. `lj_tg_detach` leaves dead TG nodes in
  `g->gc2.tg_list`, so tombstone memory must remain address-valid until a real
  reclamation scheme exists.
- `threading.spawn(f, ...)` now:
  - creates a child Lua thread in the same VM;
  - copies `f` and arguments to the child stack;
  - originally rooted a `threading.thread` handle in the thread-method private
    live table; the current code allocates a native live-root node while the
    handle is stack-rooted, claims `mt_live`, publishes the node, then calls
    `pthread_create`;
  - initializes a child TG and lets the pthread attach it before executing Lua.
- The pthread entry runs the child with `lua_pcall(..., LUA_MULTRET, 0)`,
  records either success results or an error object on the child stack, detaches
  the TG, publishes `DONE`, and wakes joiners.
- `thread:join([timeout_s])` now:
  - rejects joining the current/main thread;
  - waits in native state and polls on leave;
  - supports timeout as `nil, "timeout"`;
  - is idempotent and copies cached child-stack results on every join;
  - keeps the live-root node in place until after caller stack growth and
    result copies, so `luaMT_join()` callers holding only a `lua_State *` do
    not lose the child root during an allocating stack check;
  - returns `true, ...results` or `false, errobj`.
- `thread:id()` and `thread:running()` are registered.
- `threading.current()` lazily creates a main-thread handle and returns the
  current TG's handle for spawned threads.
- Legacy GC and GC2 userdata traversal now mark `UDTYPE_THREAD` child
  `lua_State` stacks.
- Extended `tests/t-threading-api.lua` for spawn result tuples with nil holes,
  idempotent joins, child errors, join timeout, `current():id()` from a child,
  and concurrent joiners.
- `tools/ci/m4_threading_api.sh` now runs the Lua smoke test with `-joff`, as

Lua-visible mutex convenience API:

- Added `UDTYPE_MUTEX` userdata and `threading.mutex()`.
- Registered:
  - `m:lock()` using a futex-backed state word and native-state waits;
  - `m:trylock()` returning a boolean;
  - `m:unlock()` waking waiters and erroring on unlocked mutexes;
  - `__tostring` returning `threading.mutex`.
- Extended `tests/t-threading-api.lua` to cover trylock/lock/unlock behavior,
  an unlock error, and a spawned worker blocked on a parent-held mutex.
- Added the first M4 guard against automatic legacy GC while secondary Lua
  threads are active. Repeated spawn/join exposed an automatic-GC hang around
  the sixth child; forcing GC only between joins passed. The current guard
  raises `g->gc.threshold` to `LJ_MAX_MEM` for the active-child interval and
  restores the prior threshold after the last child detaches. A later slice
  split this from the one-way `mt_active` latch into `global_State.mt_live`.
- Added a matching `lua_gc` guard for explicit collection while secondary Lua
  threads are active:
  - `collect` and `step` are no-ops during the active-child interval;
  - `stop`/`restart` update the saved logical threshold and keep the temporary
    M4 pause in force;
  - `isrunning` reports the saved logical state, not the temporary M4 pause.
  A child blocked on a channel plus parent-side `collectgarbage()` reproduced
  the hang before this guard.
- Added `global_State.mt_gc_exclusive` so explicit legacy `collect` / `step`
  cannot race a new secondary entrant between the `mt_live` check and the GC
  work. Spawn and `luaMT_attach()` wait out this slow-path word before
  incrementing `mt_live`; `collect` / `step` release it if a live entrant wins
  the race.
- Added `tests/t-mt-litmus.lua` and `tools/ci/m4_threading_litmus.sh`.
  The litmus suite runs 100 `-joff` repetitions covering:
  - join happens-before for child return values;
  - channel handoff visibility after `threading.fence()`;
  - explicit parent `collectgarbage("collect")` / `step` while a child is
    active and blocked;
  - FIFO channel order;
  - mutex exclusion across a blocked spawned worker.
- Added `tests/t-threading-stress.lua` and `tools/ci/m4_threading_stress.sh`.
