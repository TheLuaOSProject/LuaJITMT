# M8 Notes

Weak modes and current finalizer semantics:

- Original plan state: `plan/12_implementation_plan.md` defines M8 as the
  complete weak-table and finalizer milestone: full `gc_mayclear()` parity,
  the weak resurrection-race store hook, finalizer thread/ordering,
  `ffi.gc()` interplay, keeping Lua 5.1's "no `__gc` on tables" rule, and
  `lua_close()` finalization drain.
- Current bridge state entering M8 already had GC2 weak snapshots, legacy-color
  weak clearing, P_WEAK write barriers, and finalizer sweep guards staged from
  M3/M7. This slice does not replace those bridges with the final
  scheduler-owned weak/finalizer design.
- Added `tests/t-weak-modes.lua` to cover the planned `t-weak-01..05` semantic
  surface that is deterministic today:
  weak-value, weak-key, and all-weak table modes; string keys/values not being
  weak-cleared; cycles made only of weak tables not keeping themselves alive;
  `ffi.gc()` reverse finalizer order; explicit `ffi.gc(cd, nil)` clearing;
  nested GC inside a cdata finalizer; the Lua 5.1 rule that table `__gc` does
  not run; a finalizer that spawns and joins a thread; and a bounded concurrent
  weak-value writer safety pass.
- Added `tools/ci/m8_weak.sh` as the first explicit M8 gate. It runs the Lua
  semantic test under interpreter and default JIT, runs the existing
  `t-gc2-phase` finalizer phase accounting coverage, runs the existing
  `t-gc2-traverse` weak/barrier C coverage, runs
  `tests/t-m8-ffi-weak-newindex.c` for cdata metatype weak-target writes, and runs
  `tests/t-m8-close-finalizers.c` to assert `lua_close()` drains cdata
  finalizers, chained cdata finalizers, and chained userdata finalizers. A
  reduced `t-ffi-gc-finreg.lua` smoke pins worker-created FINREG finalizer
  firing under interpreter and default-JIT modes. The gate then rebuilds with
  `LUA_USE_ASSERT` and `LJ_GC2_PARANOIA` and reruns the focused weak/close
  gates.
- Extended the finalizer phase guard regression checks so `lj_gc2_finalizer_enter`
  records the current TG owner, peers remain blocked while the owner can finish
  nested sweep work, and `lj_gc2_finalizer_leave` clears owner state while
  advancing the leave counter exactly once. This tightens the current bridge
  accounting; it is not the final async/per-thread finalizer dispatch design.
- Extended `t-gc2-traverse` with a `lj_gc2_weak_complete()` bridge check. The
  test now proves that fully drained GC2 weak snapshots skip legacy weak
  clearing when they cover the legacy weak list, and that a complete snapshot
  can owner-clear legacy weak tables that were absent from the side vector
  before skipping `gc_clearweak()`. Incomplete or overflowed snapshots still use
  the legacy fallback.
- Added a post-clear weak-write regression in `t-gc2-traverse`: after a `kv`
  weak table has already been processed by `lj_gc2_weak_drain()`, a late
  weak-phase store marks the new key and value through the P_WEAK write hooks
  and keeps the entry present. This covers the original resurrection-race store
  hook at the current bridge level.
- Extended the post-clear regression to the VM existing-key path. Weak clearing
  leaves nil-valued hash slots behind, so `lj_meta_tset()` now marks weak keys
  before returning an existing slot during `P_WEAK`, including nil-valued dead
  key slots reused by a later `t[k] = v`.
- Extended the weak-phase key barrier to weak-value tables too: their hash
  keys are strong, so a collectable key inserted during `P_WEAK` must be marked
  even when only values are weak. `t-gc2-traverse` covers the VM `t[k] = v`
  path for a weak-value table and verifies both the new key and value survive.
- Follow-up C API `__newindex` target-owner slice: `lua_settable()` and
  `lua_setfield()` now ask `lj_meta_tset_owner()` for the actual table that owns
  the resolved slot. This keeps the P_WEAK post-store barrier on a weak table
  reached through a strong proxy's table-valued `__newindex`, instead of applying
  it to the proxy. `t-gc2-traverse` covers both C API setters through a weak-value
  target proxy.
- FFI cdata metatype `__newindex = weak_table` now uses the same resolved-owner
  barrier path in `ffi_meta___newindex`. The focused
  `tests/t-m8-ffi-weak-newindex.c` harness keeps this coverage separate from the
  long traversal test because FFI metatype state is global to the Lua state.
- FFI module registration now treats `_LOADED.ffi = module` like the other
  weak-phase table writes. `ffi_register_module()` builds a real key `TValue`
  and calls `lj_gc2_barrier_weak_write()` after the direct slot store, so a
  user-mutated weak-value `package.loaded` table cannot clear the freshly
  opened FFI module during `P_WEAK`. The traversal harness covers this in a
  fresh state that opens only base/package, makes `package.loaded` weak-value,
  enters `P_WEAK`, then calls `luaopen_ffi()` directly.
- Generic library registration now applies the same weak-write bridge to
  direct `lj_lib_register()` slot publications. A caller can pre-create a
  weak-value module table, enter `P_WEAK`, and then open a standard library;
  the traversal harness covers this with a custom `LIBINIT_SET` stream that
  copies an existing unmarked table into a fresh weak-value module table and
  verifies the value survives weak drain.
- JIT profiler callback anchoring now treats the registry as a possible weak
  table too. `jit.profile.start()` stores the profiler thread and callback
  directly with `copyTVrel()`, so it now calls `lj_gc2_barrier_weak_write()`
  after each registry publication. The traversal harness makes a fresh
  registry weak-value, starts `jit.profile` during `P_WEAK`, and verifies the
  pre-existing callback is marked.
- Added a paranoia-only weak zero-diff check. When `lj_gc2_weak_complete()`
  decides that the GC2-cleared snapshot covers the legacy weak list, paranoia
  builds rescan that legacy list in non-mutating mode and abort if any weak
  slot is still clearable. This makes the current skip-legacy decision directly
  check the original weak-set zero-diff requirement.
- GC2 weak snapshot discovery now mirrors the traversal-time weak mode into the
  table GC flags, and `gc2_weak_process_tab()` drains from those captured flags
  instead of re-reading the current metatable `__mode`. `t-gc2-traverse` mutates
  `mt.__mode` after snapshot discovery and before weak drain to preserve the
  original legacy behavior.
- P_WEAK late-write barriers now use the same captured weak mode before
  falling back to current metatable lookup for uncaptured tables. The post-clear
  resurrection regression mutates `mt.__mode` before drain and then writes a
  new key/value pair, verifying the late write still marks both sides.
- The original "finalizer that spawns a thread" probe initially hung because
  `threading.spawn()` waited for `mt_gc_exclusive` while the caller was already
  inside explicit full-GC finalization. `gc_call_finalizer()` now releases that
  explicit-GC exclusion only around the protected user finalizer call, then
  reacquires exclusivity when no finalizer-spawned thread remains before the
  collector resumes. This is a correctness bridge for finalizer-spawn semantics,
  not the final async finalizer-thread architecture.
- Follow-up liveness bridge: if a finalizer-spawned thread outlives the
  callback, `gc_call_finalizer()` now reports deferred GC instead of waiting
  for `mt_live == 0` inside the finalizer path. `lj_gc_fullgc()` returns to the
  mutator with the collector still in finalization state and normal threading
  GC pause still active; the mutator can release/join the worker and a later GC
  resumes the cycle. The saved logical GC threshold is restored through the MT
  threshold mirror while the worker is live, so `collectgarbage("isrunning")`
  still reports the logical state instead of the temporary pause.
  Explicit `collectgarbage("step", ...)` now honors the same deferred result:
  `gc_onestep()` treats it as no completed progress and keeps `GCSfinalize`
  open after the finalizer queue is empty while a finalizer-spawned TG is still
  live.
  `tests/t-m8-finalizer-spawn-live.lua` covers full collect and explicit step
  under a timeout in the M8 gate. The same test now covers userdata `__gc`
  through `newproxy(true)`, so both userdata and cdata finalizers exercise the
  outliving-worker deferral bridge.
- Added a GC2 finalizer dispatch owner claim. `lj_gc2_finalizer_try_enter()`
  lets the owning TG run or reenter finalizer dispatch while peers back off
  instead of racing legacy finalizer queue state; close-time drains use the
  blocking wrapper. The phase test covers peer claim failure, owner reentry,
  owner clearing, and enter/leave counter balance. Close-time cdata finalizer
  table draining now enters the same GC2 finalizer guard around callbacks.
- Removed the older `global_State.finalizer_token` bridge. Finalizer frame
  setup and protected calls are now serialized by the GC2 dispatch owner claim
  instead of a separate shared-VM-thread token.
- Replaced the shared `vmthread(g)` user-finalizer callback stack. Finalizer
  callbacks now claim the collector caller's `lua_State` through `thr_owner`,
  run the protected callback on that state, restore the previous TG `cur_L`,
  and release the claim. `tests/t-m8-finalizer-state.c` covers userdata,
  `ffi.gc()` cdata, and an unowned coroutine state passed to `lua_gc()`.
- Removed the old `fin_token` path from close-time cdata finalizer table
  disable. FINREG generation tables are disabled directly during `lua_close()`
  after `lj_threading_shutdown()` has joined secondary threads.
- Follow-up close-time fixed-point slice: FINREG generation tables now remain
  enabled while `lua_close()` drains finalizers, so a close-time userdata or
  cdata finalizer can register another cdata finalizer with `ffi.gc()`.
  `lua_close()` checks both the GC2 finalizer queue and pending FINREG cdata
  before breaking the close loop, then disables FINREG generations only after
  the fixed point.
  `tests/t-m8-close-finalizers.c` now covers a cdata finalizer that registers a
  chained cdata finalizer during close.
- Follow-up close-loop cap slice: the fixed-point drain no longer stops after
  ten successful close passes before checking for pending userdata or FINREG
  cdata. The close-finalizer harness now includes an alternating cdata/userdata
  chain that needs more than ten passes and asserts both sides drain completely.
- Follow-up close-time cdata order slice: close-time cdata finalizers are
  separated from the GC root list into the GC2 finalizer queue instead of being
  called directly from a FINREG hash scan. This preserves the current
  reverse-order behavior for cdata registered in allocation order while still
  using the FINREG generation table to detect pending close-time work.
- Added close-time FINREG growth coverage. A close-time cdata finalizer now
  registers a batch of additional `ffi.gc()` cdata finalizers large enough to
  force new FINREG generations, and `lua_close()` must keep FINREG enabled and
  continue the fixed-point drain until the whole batch has fired exactly once.
- Removed the unnecessary structural path for explicit no-op clears:
  `ffi.gc(cd, nil)` now returns before structural insertion when the cdata has
  no finalizer table entry, while still clearing the cdata FIN flag/telemetry.
- Added a lock-free empty-anchor insert fast path for enabled missing-key FFI
  finalizer registration. It claims the target hidden-table anchor with the
  existing FINREG sentinel before publishing the key/finalizer.
- Extended the same FINREG insertion protocol to collision chains in the
  current hash generation: a free node is claimed, CAS-prepended as a
  claim/nil-key placeholder, then key/finalizer publication completes. The
  legacy `lj_tab_set()` resize/full-table fallback and rare grow-publisher
  token have been replaced by a FINREG-only multi-generation registry:
  `CTState.fin_head` CAS-publishes new weak-key generations, while legacy GC
  and GC2 root/traverse every generation and wait out the claim sentinel before
  marking finalizer values.
- Factored cdata finalizer slot clear/callback execution into owned helper
  surfaces: normal GC2-queue cdata finalization rechecks the FINREG generation
  list and claims the slot before clearing/calling it. Close-time cdata
  finalizer draining now separates cdata into the same GC2 finalizer queue
  instead of calling finalizers directly from a FINREG table scan. Membership
  and ordering still come from the legacy root/FINREG discovery passes.
- Added a userdata FINREG membership bit over the userdata-only meaning of the
  existing `0x10` GC flag. `lj_gc2_finreg_udata_set()` now records membership
  transitions, and `lj_gc_separateudata()` mirrors both lazy additions and stale
  removals discovered at separation time. This covers in-place metatable mutation
  cases where `mt.__gc = fn` or `mt.__gc = nil` bypasses `lua_setmetatable()`
  old/new metatable comparison. The traversal harness now checks behavior, not
  only telemetry: a lazy in-place `__gc` add runs exactly once, while a stale
  in-place clear suppresses the finalizer.
- Normal userdata `lua_setmetatable()` finalizer registration now also
  publishes to a GC2-owned userdata FINREG side list. `lj_gc_separateudata()`
  scans that side list, queues discovered objects through the GC2 finalizer
  queue, and clears side-list references on disable or queueing.
- Userdata with any assigned metatable is now published to the same GC2 side
  list, even when the metatable does not yet contain `__gc`. This lets the
  side-list scan discover in-place `mt.__gc = fn` additions without relying on
  the legacy userdata-chain pass; the traversal telemetry now expects the
  in-place add case to increment `finreg_udata_discovered`.
- Userdata side-list publication now happens before the metatable pointer is
  made visible. `lj_gc_separateudata()` can queue through GC2 userdata FINREG
  identity even when the object is no longer on the legacy userdata chain; the
  legacy chain unlink is now only opportunistic cleanup before finalizer queue
  publication. `t-gc2-traverse` asserts normal finalizer registration, in-place
  clear/add cases, and a manually chain-unlinked finalizer userdata all queue
  through the side-list path.
- Internal userdata constructors that install finalizer metatables directly now
  reuse `lj_gc2_finreg_udata_register_mt()`, so IO files, buffers, FFI clib
  handles, `ffi.pin()` handles, and threading channels enter the same GC2
  userdata FINREG side list as `lua_setmetatable()`. The traversal harness
  creates and drops representative internal userdata and asserts side-list
  registration/discovery/queueing moves. The helper now also publishes internal
  userdata with non-finalizer metatables, matching the `lua_setmetatable()`
  side-list contract for later in-place `__gc` additions; a `threading.mutex`
  regression mutates its metatable through `debug.getmetatable()` and verifies
  lazy discovery through the side-list path.
- `table.insert()` now routes its direct array writes through the weak-write
  bridge during `P_WEAK`, including both positional shifts and the inserted
  value. `tests/t-gc2-traverse.c` covers inserting an unmarked collectable value
  into a weak-value array table during the weak phase.
- Added direct C API raw-set coverage for the same weak resurrection-race
  surface: `lua_rawset()` now has a focused all-weak hash insertion assertion,
  and `lua_rawseti()` has a weak-value array insertion assertion during
  `P_WEAK`. These pin the existing weak-write bridge on raw setters that bypass
  metamethod dispatch.
- The weak clear predicate now lets a current-cycle GC2 mark from a late weak
  write override stale legacy white while `GCSatomic` remains open. The
  traversal harness covers a pre-drain late write surviving
  `lj_gc2_weak_drain()`, preserving the original M8 weak-table intent without
  widening the plan.
- GC2 weak clear now mirrors legacy string retention: strings found in weak
  slots are marked in the GC2 arena bitmap and have their legacy white bits
  cleared. The traversal harness covers a self-metatable weak table so internal
  `newproxy`-style `__mode` strings cannot be swept while the table keeps the
  slot.
- Finalizer-spawn threshold handoff now preserves the logical GC-running state
  across workers that start during `__gc`: finalizer callbacks prepublish and
  restore the saved threshold through `mt_gc_threshold`, and worker entry keeps
  that saved value when it observes the finalizer's temporary `LJ_MAX_MEM`
  threshold during `GCSfinalize`.
- Added a GC2-owned finalizer queue bridge. `lj_gc2_finalizer_enqueue()` and
  `lj_gc2_finalizer_dequeue()` now own finalizer queue publication and pop
  operations, with release-published tail updates and queue/dequeue telemetry.
  Userdata separation, close-time cdata separation, and cdata sweep finalizer
  queueing all route through this helper. The representation preserves legacy
  dispatch order while isolating the mutation surface for the next
  scheduler-owned queue slice.
- Sidecar test-gap review from Sagan, recorded for follow-up:
  close-time finalizer-spawn, nested `collectgarbage()`, error continuation,
  and `ffi.gc(cd, nil)` suppression are now covered by
  `t-m8-close-finalizers`; worker-created FINREG finalizers now report through
  `t-ffi-gc-finreg.lua` and the parent asserts exact per-worker finalizer
  counts plus no extra callback. M8 runs a reduced `t-ffi-gc-finreg.lua` smoke
  under `-joff` and default JIT. Weak resurrection coverage is strong in
  synthetic same-thread P_WEAK tests; deterministic peer-TG and hot/JIT store
  variants are covered later in this note.
- Added a default-JIT run of `tests/t-m8-finalizer-spawn-live.lua` to the M8
  gate. The existing `-joff` run remains, so finalizer-spawn deferral is now
  checked under both interpreter and JIT-enabled runtime modes.
- Added a cdata-first P_WEAK discovery bridge. `atomic()` now moves white
  finalizer-registered cdata from the root list to the GC2 finalizer queue
  immediately after `MARK -> WEAK`, before weak clearing and sweep. This keeps
  the legacy newest-first root-list order for now, increments
  `finreg_cdata_pweak_queued`, and queues through the owned finalizer dispatch
  helper. The remaining final FINREG target is still to make registration
  ordering independent of the root list and then replace the ring bridge with
  the planned scheduler-owned finalizer queue.
- Tightened the isolated cdata P_WEAK telemetry gate: `t-gc2-traverse` now
  asserts exact one-object deltas for FINREG queueing, P_WEAK discovery,
  finalizer queue/dequeue, FINREG clear, and the cdata callback count, then
  runs another full collection to assert the finalizer is not queued or fired
  twice. The M8 shell guardrail also pins the full close-time cdata order
  assertions.
- Added a GC2 side vector for P_WEAK cdata finalizer preclaims. Mark-begin
  pre-grows/compacts the vector, P_WEAK cdata discovery claims the FINREG slot
  and copies the finalizer `TValue` before clearing the slot, and cdata
  finalizer dispatch consumes the matching preclaimed record before falling
  back to FINREG lookup. P_WEAK now immediately legacy-marks the copied
  finalizer value and propagates any newly gray callback graph before sweep, so
  deferred dispatch no longer depends on the hidden FINREG slot to keep the
  callback alive. If the side vector is full, discovery restores the claimed
  slot and falls back to the existing object-only queue.
- Preclaimed cdata finalizer dispatch now atomically claims the cdata FIN bit
  before calling the copied callback. A later `ffi.gc(cd, nil)` clear can
  therefore suppress a P_WEAK-preclaimed callback even though the FINREG slot
  was already copied and cleared during discovery. The traversal harness
  manually models that handoff by preclaiming, unlinking, queueing, clearing
  through `lj_cdata_setfin(... nil ...)`, then draining and asserting the
  callback did not run.
- FINREG generation tables are now scanned at P_WEAK before the root-list queue
  pass. The scan claims and copies dead cdata finalizer values from FINREG
  slots, then leaves the cdata membership flag set so the existing root-list
  pass can preserve LuaJIT's current newest-first finalizer queue order. The
  preclaim consumer now searches by object because FINREG hash/generation scan
  order can differ from queue order. The remaining semantic gap is an ordered
  FINREG membership structure that can provide both discovery and ordering
  without using the root list as the ordering bridge.
- The traversal telemetry harness now includes a three-cdata P_WEAK case that
  asserts exact three-object FINREG queue/preclaim/dispatch deltas, no second
  dispatch on another collection, and current newest-first cdata finalizer
  order (`3,2,1`). This pins the FINREG preclaim plus root-order bridge while
  the ordered FINREG membership structure is still pending.
- Added an append-only ordered FINREG membership list under `CTState`. Each
  successful enabled `ffi.gc()` registration publishes a `FinRegOrderNode`
  newest-first after the FINREG slot value and cdata FIN bit are visible. During
  `P_WEAK`, cdata finalizer discovery now scans that list in registration
  order, claims the FINREG slot, unlinks the cdata from the root list, copies
  the finalizer into the preclaim vector, and queues through the existing GC2
  finalizer ring in that same order. The legacy root-list queue path remains as
  fallback for entries without ordered coverage or preclaim capacity.
- P_WEAK cdata discovery now enters the legacy root-list queue path only when
  the ordered FINREG scan reports missing ordered coverage or preclaim
  capacity. Ordered FINREG object identity is enough for P_WEAK discovery even
  when the cdata is no longer on the legacy root list. `t-gc2-traverse`
  snapshots `finreg_cdata_pweak_root_fallbacks` and asserts both ordinary
  ordered FINREG cases and a manually root-unlinked ordered cdata keep root
  fallback flat.
- The traversal harness now distinguishes registration order from allocation
  order by allocating `a,b,c`, registering `b,a,c`, and asserting dispatch order
  `c,a,b`. It also re-registers `a` after `b` and asserts the latest `a`
  finalizer runs first and only once. Ordered-path telemetry asserts no fallback
  in these focused cases.
- P_WEAK cdata preclaims now grow the GC2 preclaim vector on demand instead of
  overflowing immediately when the initial capacity is full. A 160-object
  ordered FINREG batch in `t-gc2-traverse` asserts preclaim capacity grows,
  `finreg_cdata_preclaim_overflow` stays flat, and the legacy P_WEAK root-list
  fallback counter does not move. This keeps large ordinary ordered batches on
  the GC2 FINREG discovery path instead of routing them through root fallback.
- Ordered FINREG nodes now publish the cdata object identity next to the
  hidden-table slot. P_WEAK, close-time separation, and close pending scans
  validate that side identity before queueing, so ordered discovery no longer
  reconstructs membership solely from the FINREG table key.
- P_WEAK and close-time cdata root-list fallbacks now require an actual pending
  FINREG generation-table entry when the ordered list is missing or otherwise
  reports no queued objects. A fresh `require("ffi")` plus full collection in
  `t-gc2-traverse` asserts both P_WEAK and close root fallback counters stay
  flat when FINREG has no pending finalizers.
- Close-time finalizer drain coverage now includes both cdata and userdata
  finalizers that raise errors, followed by same-kind finalizers that must still
  run. This pins `lua_close()` error-continuation behavior for the fixed-point
  drain without changing the current pre-close threading shutdown semantics.
- Close-time cdata finalizer suppression is now covered: a newer cdata
  finalizer clears an older queued cdata with `ffi.gc(cd, nil)` during
  `lua_close()`, and the older finalizer must not run when its queued object is
  later dispatched. This pins the FINREG clear path while ordering is still
  bridged through GC2 finalizer queue publication fed by legacy discovery.
- Close-time nested-GC coverage now includes both cdata and userdata finalizers
  that call `collectgarbage("collect")` from inside `lua_close()` finalizer
  dispatch. The harness asserts the outer fixed-point close drain still
  completes each nested-GC finalizer exactly once.
- That nested-GC test exposed a stale-stack-pointer bug in
  `gc_call_finalizer()`: a recursive finalizer could grow/move the callback
  `lua_State` stack, after which an outer finalizer restored its old raw
  `TValue *top`. The finalizer path now checks stack space before building the
  protected-call frame and saves/restores the old top with
  `savestack()`/`restorestack()`.
- Close-time finalizer-spawn coverage now probes the shutdown path explicitly.
  Since `lua_close()` runs `lj_threading_shutdown()` before finalizer dispatch,
  both cdata and userdata finalizers assert `threading.spawn()` fails with
  `VM shutdown in progress` and the fixed-point close drain still completes.
  This exposed a rejected-spawn cleanup bug: the child Lua stack had already
  been rehomed into the unstarted worker TG arena before shutdown rejection, and
  later close-time nested GC could sweep the child state after that TG was
  freed. `threading_spawn_core()` now rejects immediately when shutdown is
  already visible and rehomes the child stack back to the caller TG before
  freeing an unstarted worker TG on later failure paths.
- Finalizer-spawn deferral is now instrumented with
  `finalizer_spawn_deferrals`. The traversal harness drives a cdata finalizer
  that spawns a live worker, asserts full GC returns with `GCSfinalize` still
  open, `mt_gc_exclusive` released, the logical threshold held at
  `LJ_MAX_MEM`, and the deferral counter incremented, then releases the worker
  and verifies the next full GC reaches `GCSpause`.
- The same traversal probe exposed a joined-thread cleanup gap under assert
  close checks: joined `threading.thread` userdata had no `__gc` hook to free
  its heap `TGState` after GC2 reclaimed the dead TG list entry. Thread userdata
  now registers with the GC2 userdata finalizer side list at creation, and its
  finalizer frees a done-and-joined TG only after confirming it is no longer
  registered in the GC2 TG list.
- Added a producer-side GC2 MPSC finalizer queue bridge. Finalizer producers
  now CAS-push objects onto `GC2State.finalizer_mpsc`; the single consumer
  now drains and reverses that stack into `GC2State.finalizer_tail`, a
  GC2-owned consumer ring, before mark or dispatch. This preserves current FIFO
  dispatch order for ordered cdata and userdata cases while stopping normal
  finalizer queue traffic from publishing through the legacy queue field.
  `lj_gc2_finalizer_queue_pending()` now observes only the producer stack and
  GC2 consumer ring, and runtime mark/dequeue/root-scan paths no longer treat
  legacy finalizer queue storage as a fallback. Sweep and
  `lua_close()` still see newly published finalizers while
  `lj_gc2_finalizer_pending()` keeps its broader active-finalizer meaning for
  peer sweep blocking.
- The phase harness now includes a concurrent producer check for that MPSC
  bridge: four pthread producers publish disjoint unlinked objects through
  `lj_gc2_finalizer_enqueue()`, the owner drains once, and the test verifies
  every object is dequeued exactly once with matching queue/drain counters.
- Close-time cdata discovery now uses the ordered FINREG registration list as
  the primary source and publishes directly into the GC2 finalizer queue in
  newest-first order. The legacy root-list walk remains only as a fallback when
  ordered registration data is absent; ordered FINREG object identity is enough
  for close-time discovery even when the cdata is no longer on the legacy root
  list. `t-gc2-traverse` now exercises this path directly with
  `lj_gc_finalize_cdata()`, including a manually root-unlinked cdata, and the
  normal GC2 finalizer drain.
- Close-time cdata root-list fallback is now separately instrumented with
  `finreg_cdata_close_root_fallbacks`. The traversal harness snapshots that
  counter around the ordered close-time cdata case and asserts it stays flat,
  so normal close-time ordered FINREG discovery is pinned away from the legacy
  root scan. This exposed a stale ordered-node case: close-time cdata queueing
  now marks the cdata finalized before enqueue, and close-time candidate checks
  reject already-finalized cdata so duplicate ordered records cannot trigger a
  root-unlink fallback after the object has already been queued.
- Close-time cdata pending detection now also checks the ordered FINREG
  registration list before falling back to the legacy generation-table scan.
  `finreg_cdata_pending_order_hits` records positive ordered hits, and the
  traversal close-time cdata case asserts the `lua_close()` fixed-point
  predicate can observe pending cdata through ordered FINREG data while the
  root-list fallback counter remains flat.
- The fallback FINREG generation pending scan now uses the same close-time
  cdata candidate predicate as ordered pending detection, so cdata already
  marked finalized and queued on the GC2 finalizer queue no longer looks like
  unqueued FINREG work. The traversal close-time cdata case asserts
