# Darwin ARM64 one-eightbyte HFA CALLXS arguments

This follow-up extends the earlier two-float HFA argument path to direct dense structs containing one float, one double, or two floats. The shared classifier records member count, width, alignment, and offsets; the recorder emits one FPR `XLOAD` per member (`IRT_FLOAT` for float, `IRT_NUM` for double). Semantic and post-RA walks independently reconstruct that metadata from the exact guarded CData CType, tie each XLOAD to its source frame slot and CALLXS parameter, require the expected FPR carrier, and reject any HFA raw member in a Lua snapshot. The CData TValue remains the rooted owner during native call entry/leave.

Scope stays bounded to a named fixed argument with at most two direct members and total size at most eight bytes. Members must be homogeneous and tightly packed at their natural offsets. Mixed fields, references, unions, nested/array fields, float triples, two-double (16-byte) structs, variadic HFA formals/tails, stack-passed members, stack crossing, and HFA results remain closed. The one-double HFA uses the Darwin AAPCS64 FPR bank; it does not reuse x86 aggregate rules.

The aggregate contract fixture now includes distinct one-float and one-double candidates. Each compares against a JIT-disabled oracle with a live MT peer, requires its exact candidate root to publish and finish CALLXS natively, observes a selected-root exit, checks exact C effects, forces full GC, then requires the same candidate to re-enter and exit natively with correct effects. Private source clones independently exercise semantic and post-RA rejection for raw-member snapshots, wrong XLOAD type, wrong address/source, changed CType guard, changed field offset, changed CALLXS binding, wrong FPR class, invalid spill slot, and invalid value type. CType signature positives/negatives cover the two new shapes, mixed float/double fields, a double pair, and a float triple.

While adding the native CALLM regression, inspection found a separate asymmetry in post-RA source replay: `producer_scalar` checked `abi.nparams+1 == BC_CALL.C`, omitting the observed scalar vararg tail. It now checks `abi.nparams+(actual_count-abi.nargs)+1`, matching semantic replay. A live-peer fixture has a variadic scalar producer with one tail argument feed its result through CALLM to an integer-aggregate consumer; it asserts the candidate root's native aggregate finish counter, selected-root exit, oracle equality, and exact producer/consumer effects. The candidate loop trace contains multiple CALLXS nodes (the loop trace can unroll both calls), and the root receives private semantic/post-RA malformed-view checks.
