# ARM64 FFI 64-bit arguments from a FORL index

The integer FFI contract now admits the canonical ascending integer loop index as an `int64_t` or `uint64_t` argument when the recorder emits an `IR_CONV` without `IRCONV_SEXT`. AArch64 lowers that conversion as zero extension. The independent semantic and post-RA proofs bind it to the exact root loop's guarded index SLOAD and pre-loop / backedge / PHI recurrence, paired FORI/FORL bytecode, nonnegative KSHORT initializer, and positive KSHORT step. The existing integer ABI proof still binds the converted value to the exact CALLXS argument and excludes it from snapshots or unrelated IR uses. Other no-SEXT INT-to-64-bit conversions remain closed; existing sign-extension proofs are unchanged.

The post-RA proof also handles the published source form: it checks the prototype shadow is the captured FORL and the live JFORL's register and trace ID match the owning trace, then derives loop geometry from the shadow instruction. It does not mistake the patched JFORL for an original FORL.

Admission negatives mutate the initializer to a negative value and the step to zero. Both semantic and post-RA validators reject each mutation. The native fixture covers signed and unsigned calls in register and stack positions, live-peer execution, a below-initializer limit that skips FORI, selected-root exits, and reuse after full GC. The narrower static source grammar intentionally leaves reverse loops, negative starts, dynamic starts/steps, and arbitrary INT sources interpreted.
