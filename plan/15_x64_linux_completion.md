# x86-64 Linux completion plan

The target is one GC64 heap shared by running Linux threads, with the interpreter, tracing JIT, native FFI and collector enabled together. The 2026-11-25 audit starts at `49523abd8`. The mainline already has per-thread dispatch, physical state ownership, a bitmap allocator and GC2, rooted shared-value access, C type snapshots, cooperative trace exits, RX/RW aliases and bytecode import. M0–M10 describe the design history. Implement the remaining work against these production paths.

The current milestone is lock freedom and stability with the built-in arena allocator. Custom allocator callbacks are outside the project scope. Compatibility covers the documented Lua language and public libraries, C API, JIT controls and FFI on that configuration. Exercise API calls while peers mutate the heap, force collection, attach and detach. Check returned values, errors, side effects, pointer lifetimes and whether other mutators can complete operations when an actor is suspended. Table traversal order, the identity of a generated trace, optimization choices, and the number of collector steps are implementation-defined. Internal probes help exercise specific interleavings and establish coverage.

## Starting measurements

On an i9-14900K with GCC 14.2, the release binary passed all 509 vendored stock source cases and 509 cases imported from genuine LuaJIT v2 bytecode. With a second mutator attached, `bench/jit-parity.lua` observed exits from 18 of 20 workload roots. Shared iteration and boxed 64-bit arithmetic produced correct results through the interpreter in that sample.

With stock and fork run sequentially on CPU 8, the 15-case default-JIT geomean was **1.178× stock elapsed CPU time** at full scale, against the design baseline `b925b3e3f`. New hash insertions took 1,080 versus 86 ns/op, closure creation and mutation 345 versus 36 ns/op, and coroutine switches 127 versus 24 ns/op. A separate interpreter comparison across two P-cores gave 7.42×. Retain all rows, including string workloads that favor the fork. Allocation sinking can hide allocator and GC costs. Also measure objects retained in a ring and bytes reclaimed per completed major cycle.

## Implementation order

| Area | Production constraint and implementation | Acceptance on Linux x64 |
| --- | --- | --- |
| Shared lifetime | Start from a live Lua root or a published trace constant. Bind the table and its storage generation before dereferencing a shared edge. Separate removal, the reader grace period and physical reuse. Reuse a counted arena lookup across the handoff to arena-local admission. | Pause lookup, resize, retire and reuse independently. A reader returns a complete value or refuses with its output and GC roots intact. A stalled reader permits unrelated operations to finish. |
| VM and tables | Inventory ordinary operations that wait on structural owners or in-progress key publication. Make pending work discoverable and helpable. Keep barriers, aliased destinations and the first foreign attachment in the contract. Retain the public iteration semantics across resize, native execution and side exits. | Suspend an actor mid-insert and mid-resize. Exercise growing/shrinking arrays, hash collisions, weak keys, replacement, clear, and GC around publication. Check documented outcomes with the interpreter and with JIT enabled. |
| Strings and GC | Intern through the current or migrating directory under a generation pin. Retain canonical identity across unlink, lookup, rescue and a second grace period. Small strings can be reclaimed while managed Lua workers run. Extend coverage to large mappings, collectors on secondary threads and background GC workers. Preserve borrowed `lua_tolstring` bytes through callbacks and native code. | Hold one mutator active throughout string churn. Observe duplicate-free identity and physical reclamation before join. Check heap growth, finalizer counts and phase completion with active, parked and detached peers. |
| JIT and FFI | Bind each runtime specialization to its mutable dependencies. Verify the caller's stack roots across on-trace calls, callbacks, errors, remote flush and GC. Let other interpreters continue while compilation is busy. Use fallback wherever a specialization lacks a lifetime or ABI proof. | Use documented semantics and stock results as public oracles. Exercise real compiled calls and side exits with a live peer. Test integer/SSE register classes, register exhaustion, by-value aggregates, sret, variadics, callbacks, errno and unwind. |
| Progress and performance | Inventory waits by caller. A failed recorder acquisition may skip recording. A table store, barrier, interner or ordinary allocation must make progress if another mutator is descheduled. Keep explicit channel/join/mutex waits and cold module or declaration initialization visible at the API boundary. Test first attachment during already-compiled code. | Pause individual owners at publication boundaries. Check independent successes, CPU usage and recovery after resumption. Run the full matrix below before marking the project stable. |

The lifetime rules follow the removal and reclamation split in RCU. C11 §5.1.2.4 governs the ordering between participants. LuaJIT's FFI rules define lifetimes for application-owned buffers and callbacks, and its JIT controls distinguish compilation, flushing and execution. [Linux RCU overview](https://www.kernel.org/doc/html/latest/RCU/whatisRCU.html), [C11 committee draft](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), [LuaJIT FFI semantics](https://luajit.org/ext_ffi_semantics.html), [LuaJIT JIT controls](https://luajit.org/ext_jit.html).

## Progress after b1.2.1

- Arena preparation runs once per collector epoch across thread attachment. A live local closure now survives worker pool changes and full collections. Collection can finish while a marked, initialized table still awaits ownership-list publication, and while a peer continuously interns a rooted string. Detached threads' empty arenas can be unmapped.
- A thread can complete `table.clear` while a resize is paused before freezing its source. After the owner has copied a hash-only resize, readers and writers can publish the new hash and retire the old one. Cover the earlier copy stages, collision slots and array changes with the same suspended-owner test.
- During ordinary string-table expansion, interners can use buckets whose migration has completed. Collision rehash also admits unrelated source buckets. Quarantine supports identity-preserving rescue, directory removal and a second reader grace period before body reuse. Physical collection of ordinary unreachable strings with active peers still needs complete coverage of interpreter, JIT and native references.
- Numeric interpreter loops now service stop requests without a function call. A parked trace-event callback can release the recorder for a peer flush. The imported-bytecode suite caught a side trace clearing a live Lua local during recording. Linux CI runs all 509 stock source cases with JIT on, the 387 eligible interpreter cases and 509 imported bytecode cases under GCC and a Clang assertion build.
- Native FFI coverage includes mixed-register SysV aggregates, register exhaustion and an outer C call retaining Lua string bytes across a nested callback and collection. Audit ordinary FFI readers during a paused declaration and continue testing concurrent callbacks and allocation lifetimes.

## Progress after b1.2.2

- A peer can finish copying a separated array, reserve collision-chain slots, move integer keys between the array and hash, and complete the first resize during foreign attachment. Pure hash growth publishes a descriptor directly from the free structural word. Paused-owner tests check subsequent writes, deletion and transitions between strong and weak metatables. Array shrink currently uses this path when the destination hash can hold the old hash and the entire array tail. Audit compact destinations, colocated arrays and the finalizer registry separately.
- String interning preserves canonical identity across growth, mixed dense/sparse shrink and same-size collision rehash. A lookup can finish migration for its own destination while the initiating thread is suspended. A collector can adopt a completed directory after its final old reader leaves. Keep previously pinned generations across repeated topology changes in the retention tests.
- The public FFI name, layout and native-call paths can read the committed type graph while another thread is editing an existing declaration. The paused-parser test observes both successful commit and rollback, including an incomplete type, an unaffected named struct, an enum constant and a native call.
- Main-thread explicit major collection physically reclaims small strings while managed Lua workers run interpreted code or hot native traces. A worker certifies its own root scan at an outer VM checkpoint or after restoring a native trace exit. The regression measures at least 600 reclaimed bodies per churn round before join, validates borrowed C string bytes across a parked FFI callback, retains a weak string value and runs a finalizer once. Large strings and additional collector cohorts still need lifetime and progress tests.
- A collection can finish while a peer continuously reads the same table. Idle pacing state is published atomically, a duplicate safepoint request survives poll clearing, and a sweep handed to a worker checks its post-sweep roots. Concurrent public full collections and explicit stepping after a stop are exercised through the embedding API.
- Shared JIT execution now covers boxed arithmetic, closed upvalues, protected metatable changes and nested multi-result FFI calls. The FFI suites exercise native library-cache reads and writes, side exits, callback returns and SysV aggregate calls with a worker attached. Open upvalue and side-trace cases still rely on interpreter fallback where the recorder cannot establish stack ownership.
- Repeated stock runs exposed a collection freeing a nested prototype still reachable through a closure. The collector now records semantic visits per collection for closures and upvalues, and resets mark bits through the stable arena registry, including arenas between owners. A deterministic nested-prototype and captured-value case covers the lost graph. The visit fix passed 30 consecutive full 509-case source runs with GCC and another 30 with Clang ASan. The combined arena reset and traversal fixes passed the source, interpreter and independent stock-bytecode matrix with GCC, Clang assertions and ASan.

## Progress after b1.2.3

- Main-thread major collection unmaps unreachable large strings with an interpreted or native Lua peer and with zero or two GC workers. A paused C/FFI callback retains its borrowed bytes. An exact root scan now distinguishes popped C stack capacity from live frame slots when it encounters a string past its irreversible close. Tests cover both a rescued neighbor and actual unmapping after the second grace period.
- A one-unit public GC step can finish marking despite new barrier work between calls. String classification precedes arena liveness reset, and a bounded retirement cursor lets successive steps free a cohort. A completed native exit publishes its restored Lua root certificate before acknowledging the safepoint. Concurrent or nested full-collection requests preserve the initiating owner's scope.
- Ordinary table readers and writers can finish a paused first resize of inline storage, compact sparse array shrink, and hash-only shrink of mixed or pure-hash tables. Shared `ipairs` acquires its result before releasing the backing array. Closed-upvalue reads can compile on a side trace while a peer remains attached.
- Distinct cdata finalizers can register while a previous registration has published its order and paused. The collision regression forces a new registry generation and checks that both finalizers run once.
- The next acceptance cases are physical string collection driven by secondary Lua threads, automatic collection under ordinary allocation, and bounded mutator progress when a VM peer has stopped polling. Check each with background workers disabled and enabled. Retiring memory can require a peer to supply its roots. Its suspension must still permit other mutators to read, write and allocate. Keep testing unregistered native borrows and collector coordination separately.

## Progress after b1.2.4

- A managed secondary can initiate full collection and unmap large unreachable strings with the main thread running interpreted or compiled Lua and with zero or two GC workers. The initiating thread holds the commit authority. Pool workers may stage the quarantine. A C callback retaining borrowed bytes still prevents physical reuse.
- Ordinary table and closure reads retain the observed value without continuously scheduling a new traversal of an already scanned payload. The same rule applies to table-valued metamethods and buffered upvalue reads. Writers still publish changed edges. A paused native return retains the exact stack proof for the entire acknowledged scan. At idle, a trace exit no longer publishes stack roots from a past collection when there is no string reclamation request.
- Ordinary allocation may return while another managed thread is suspended during MARK activation, MARK or WEAK root snapshots, and the barrier switch at entry to SWEEP. Each retained phase waits for its actual acknowledgements before destructive work. The allocating thread can continue in the interpreter and can publish new edges. Competing collectors can use the completed, barrier-protected stack snapshot across subsequent stack writes. A terminal sweep can retain its closed native-entry gate through the final check and observes any finalizer-spawned worker.
- A queued cdata finalizer has a distinct delivery ticket. Clearing or replacing its callback preserves later registrations, including rearming the same callback. Same-object peers can finish prepared publications and revoke provisional registration, replacement and clear. Identical rearm can finish at a validated read. Inactive order records are freed after readers leave. Exercise the remaining interval between key claim, finalizer flag changes and ordered publication with a suspended same-object publisher.
- Automatic collection under sustained string allocation with a hot native peer still needs a bounded heap and direct evidence of physical reuse. Extend the suspended-actor allocation tests through the SWEEP root bridge, allocator rotation, reader grace and the return to idle. Keep the irreversible decisions behind complete root and reader proofs.

## Progress after b1.2.5

- Ordinary allocations and public one-unit GC steps can return while a managed peer owes its MARK or WEAK root scan. SWEEP can rotate allocators, scan roots, and count two quarantine grace periods across separate turns. Each grace requires a distinct completed epoch. A newly retired huge mapping restarts both periods, even if the second acknowledgement was already pending. Resuming a new coroutine after the initial SWEEP snapshot can request another owner scan. The coroutine preserves its live stack, while another mutator continues allocating.
- In generational mode the parser publishes each completed child while it constructs the containing prototype. Publishing the unfinished parent could veto all later collections. The public regression removes the strong reference from a weak value, forces collection, and then calls the compiled closure. The collector paranoia suite exercises the same repair.
- Cdata registration, replacement and clear publish the callback and its generation in one atomic update. Collection retains the pending callback and cdata until delivery. Another thread can enqueue a claimed callback while its first publisher is stopped. Reentrant replacement, duplicate queue entries, allocation failure, and close-time delivery have independent tests.
- Mixed tables can grow out of their inline array while the initiating writer is parked on either side of publishing the resize descriptor. A concurrent reader and writer can finish the copy and observe the committed values. Continue through pure-array growth and first publication of a hash vector using a distinct identity for each storage generation.
- Sustained string allocation with a native Lua peer and two collector workers still grows the measured heap. Record bytes physically freed, live and quarantined bodies, completed collection cycles, and pending object kinds. Check automatic pacing and the initiating owner's stack certificate at the physical commit. A successful explicit collection after joining the peer cannot establish this bound.

## Correctness and progress checks

- Run both stock corpora, the public embedding and FFI cases, first-attach/flush races, assertion builds, ASan, TSan C drivers and the torture and weak/finalizer soaks. Keep the stock bytecode producer separate from the executable under test. Record which cases are eligible for each build.
- Run stalled-actor tests through ordinary API and bytecode entry points. Exercise sustained allocation, retention and reclamation with live workers, including after repeated worker detach. Explicit channel rendezvous, joins and module initialization have their own documented synchronization semantics.
- Publish tested checkpoints as prereleases with their outstanding issues. A stable lockless milestone requires the public semantic, lifetime and progress checks on one revision.
