# x86-64 Linux completion plan

The target is one GC64 heap shared by running Linux threads, with the interpreter, tracing JIT, native FFI and collector enabled together. The 2026-11-25 audit starts at `49523abd8`. The mainline already has per-thread dispatch, physical state ownership, a bitmap allocator and GC2, rooted shared-value access, C type snapshots, cooperative trace exits, RX/RW aliases and bytecode import. M0–M10 describe the design history. Implement the remaining work against these production paths.

Compatibility covers the documented Lua language and libraries, the public C API including allocator callbacks, JIT controls, and FFI. Exercise API calls while peers mutate the heap, force collection, attach and detach. Check returned values, errors, side effects, pointer lifetimes and whether other mutators can complete operations when an actor is suspended. Table traversal order, the identity of a generated trace, optimization choices, and the number of collector steps are implementation-defined. Internal probes help exercise specific interleavings and establish coverage.

Prioritize stability, storage lifetime and bounded physical memory, then improve performance without weakening those guarantees. Focus current work on Linux x64; defer Windows and macOS validation until a release candidate is ready.

## Release blockers identified on 2026-11-27

| Work | Acceptance |
| --- | --- |
| Allocation and protected calls | A valid positive shrink succeeds across slab and mapping boundaries, including an emergency stack returning to its normal limit. Hold a reader across shrink, exercise growth and release using the new logical size, and check the original mapping is fully released. A protected call must report its original error and the state must execute another call. [Lua allocator contract](https://www.lua.org/manual/5.1/manual.html#lua_Alloc) |
| Worker lifetime | Keep a sentinel thread alive while short workers terminate. Release returned objects in batches and count surviving thread states, empty arenas, and retired finalizer records after completed collections. Retain a second batch of results through the same collections and read their contents. Repeat with zero and two background collectors. |
| Concurrent native execution | The combined native store, read and iterator workload terminated with a signal on the starting revision. Check trace exits, return values and GC together through worker attach, resize and teardown. Include the combined workload in the Linux shared-runtime gate after repairing it. |
| Embedded allocation | The starting revision ignores the callback supplied to `lua_newstate` and silently ignores `lua_setallocf`. Verify a rejecting allocator can decline state creation, a working allocator receives its userdata, wrappers installed on a live state service allocations, and closing the state returns all callback-backed storage. Keep the same GC lifetime guarantees in a state created by a host. [Lua 5.1 embedding API](https://www.lua.org/manual/5.1/manual.html#lua_newstate) |
| Candidate verification | Build the same revision with GCC and Clang assertions, run the stock source and independently produced bytecode suites, shared JIT/GC/FFI workloads, ASan and targeted TSan fixtures. Record command, scope and outcome for each. After the correctness checks pass, compare against the pinned stock release on the same core and compiler using the full-scale benchmark below. |

Follow a buffer through its entire lifetime in these checks. A Lua stack can shrink while an error handler retains its old extent. The compiler's snapshot vector can grow on a different thread from the one that first allocated it. Preserve the logical byte count for copies and Lua accounting, the physical extent for readers and release, and the allocator owner for each old and new block. Exercise allocation refusal inside a real protected call, a live reader during replacement and a recorder running alongside resize and collection. Host allocator tests should also identify which callback supplied the memory that actually contains the Lua values. These cases connect the allocator work to the embedding, JIT and GC release gates. [Lua allocator contract](https://www.lua.org/manual/5.1/manual.html#lua_Alloc), [LuaJIT public API coverage](https://luajit.org/extensions.html).

The bytecode reader already converts supported imported local captures to cells, and the writer can emit a current-format dump. Include load, dump, reload, and execution in parity checks. The older M0–M10 descriptions predate that implementation. [Bytecode normalization and fixtures](../notes/legacy-bytecode-cells.md)

## Implementation order

| Area | Production constraint and implementation | Acceptance on Linux x64 |
| --- | --- | --- |
| Shared lifetime | Start from a live Lua root or a published trace constant. Bind the table and its storage generation before dereferencing a shared edge.
