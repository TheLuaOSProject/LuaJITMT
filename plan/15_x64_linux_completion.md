# x86-64 Linux completion plan

The target is one GC64 heap shared by running Linux threads, with the interpreter, tracing JIT, native FFI and collector enabled together. The 2026-11-25 audit starts at `49523abd8`. The mainline already has per-thread dispatch, physical state ownership, a bitmap allocator and GC2, rooted shared-value access, C type snapshots, cooperative trace exits, RX/RW aliases and bytecode import. M0–M10 describe the design history. Implement the remaining work against these production paths.

The current milestone is lock freedom and stability. Compatibility covers the documented Lua language and public libraries, C API, JIT controls and FFI. Exercise API calls while peers mutate the heap, force collection, attach and detach. Check returned values, errors, side effects, pointer lifetimes and whether other mutators can complete operations when an actor is suspended. Table traversal order, the identity of a generated trace, optimization choices, and the number of collector steps are implementation-defined. Internal probes help exercise specific interleavings and establish coverage.

## Starting measurements

On an i9-14900K with GCC 14.2, the release binary passed all 509 vendored stock source cases and 509 cases imported from genuine LuaJIT v2 bytecode. With a second mutator attached, `bench/jit-parity.lua` observed exits from 18 of 20 workload roots. Shared iteration and boxed 64-bit arithmetic produced correct results through the interpreter in that sample.

With stock and fork run sequentially on CPU 8, the 15-case default-JIT geomean was **1.178× stock elapsed CPU time** at full scale, against the design baseline `b925b3e3f`. New hash insertions took 1,080 versus 86 ns/op, closure creation and mutation 345 versus 36 ns/op, and coroutine switches 127 versus 24 ns/op. A separate interpreter comparison across two P-cores gave 7.42×. Retain all rows, including string workloads that favor the fork. Allocation sinking can hide allocator and GC costs. Also measure objects retained in a ring and bytes reclaimed per completed major cycle.

## Implementation order

| Area | Production constraint and implementation | Acceptance on Linux x64 |
| --- | --- | --- |
| Shared lifetime | Start from a live Lua root or a published trace constant. Bind the table and its storage generation before dereferencing a shared edge. Separate removal, the reader grace period and physical reuse. Reuse a counted arena lookup across the handoff to arena-local admission. | Pause lookup, resize, retire and reuse independently. A reader returns a complete value or refuses with its output and GC roots intact. A stalled reader permits unrelated operations to finish. |
| VM and tables | Inventory ordinary operations that wait on structural owners or in-progress key publication. Make pending work discoverable and helpable. Keep barriers, aliased destinations and the first foreign attachment in the contract. Retain the public iteration semantics across resize, native execution and side exits. | Suspend an actor mid-insert and mid-resize. Exercise growing/shrinking arrays, hash collisions, weak keys, replacement, clear, and GC around publication. Check documented outcomes with the interpreter and with JIT enabled. |
| Strings and GC | Resize currently rewrites chain links under a header claim. Deferring a resize on a pinned reader removes one wait. Reclamation in `lj_str_gc2_sweep_begin` still requires sole-mutator admission. Complete canonical identity across unlink, lookup, resurrection and a second grace period, including borrowed `lua_tolstring` bytes. Track pending work through a paused publisher, active native calls, weak processing, finalizers and minor collection. | Hold one mutator active throughout string churn. Observe duplicate-free identity and reclamation of unreachable strings during the run. Check heap growth, finalizer counts and phase completion with active, parked and detached peers. |
| JIT and FFI | Bind each runtime specialization to its mutable dependencies. Verify the caller's stack roots across on-trace calls, callbacks, errors, remote flush and GC. Let other interpreters continue while compilation is busy. Use fallback wherever a specialization lacks a lifetime or ABI proof. | Use documented semantics and stock results as public oracles. Exercise real compiled calls and side exits with a live peer. Test integer/SSE register classes, register exhaustion, by-value aggregates, sret, variadics, callbacks, errno and unwind. |
| Progress and performance | Inventory waits by caller. A failed recorder acquisition may skip recording. A table store, barrier, interner or ordinary allocation must make progress if another mutator is descheduled. Keep explicit channel/join/mutex waits and cold module or declaration initialization visible at the API boundary. Test first attachment during already-compiled code. | Pause individual owners at publication boundaries. Check independent successes, CPU usage and recovery after resumption. Run the full matrix below before marking the project stable. |

The lifetime rules follow the removal and reclamation split in RCU. C11 §5.1.2.4 governs the ordering between participants. LuaJIT's FFI rules define lifetimes for application-owned buffers and callbacks, and its JIT controls distinguish compilation, flushing and execution. [Linux RCU overview](https://www.kernel.org/doc/html/latest/RCU/whatisRCU.html), [C11 committee draft](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf), [LuaJIT FFI semantics](https://luajit.org/ext_ffi_semantics.html), [LuaJIT JIT controls](https://luajit.org/ext_jit.html).

## Correctness and progress checks

- Run both stock corpora, the public embedding and FFI cases, first-attach/flush races, assertion builds, ASan, TSan C drivers and the torture and weak/finalizer soaks. Keep the stock bytecode producer separate from the executable under test. Record which cases are eligible for each build.
- Run stalled-actor tests through ordinary API and bytecode entry points. Exercise sustained allocation, retention and reclamation with live workers, including after repeated worker detach. Explicit channel rendezvous, joins and module initialization have their own documented synchronization semantics.
- Publish tested checkpoints as prereleases with their outstanding issues. A stable lockless milestone requires the public semantic, lifetime and progress checks on one revision.

## Deferred performance work

Use full-scale `aux/bench/bench.lua` with its five runs. Compare paired stock/fork CSVs with `bench/compare_baseline.sh`. The historical single-mutator JIT threshold is a geomean of at most 1.10. Publish the interpreter numbers, large individual regressions and a comparison with upstream rolling LuaJIT alongside it.
